# S5 기계 측정 — ④ 정본대로인가 · ⑤ 화풍이 통일되는가 (task#315)

①②③(다윗 존재·골리앗 존재·좌우 배치)은 별도 에이전트가 육안으로 본다. 여기서는 기계로 재는
두 문항만 잰다. 스크립트: `judge_metrics.py`. 원 수치: `judge-metrics.json`.

## 1. 지표와 근거

### ④ 정본대로인가 — CLIP 교차 유사도

`masks/david.png` · `masks/goliath.png`의 바운딩 박스(마스크 파일에서 파생, 손으로 옮기지
않음 — 다윗 `(189,219,440,546)`, 골리앗 `(793,110,1191,563)`)로 각 장면(`scene/*.png`)의 인물
영역을 크롭하고, IP-Adapter가 실제로 쓰는 CLIP 이미지 인코더(`h94/IP-Adapter/sdxl_models/
image_encoder`, `CLIPVisionModelWithProjection`, ViT-bigG)로 임베딩해 코사인 유사도를 잰다.
이미 HF 캐시에 있는 것을 그대로 썼다(요구사항이 지정한 지표, 새 의존성 없음). 이 스냅샷엔
`preprocessor_config.json`이 없어 OpenAI CLIP 표준 전처리(224 리사이즈·중앙크롭·표준 평균/분산)를
직접 재현했다(diffusers `CLIPImageProcessor` 기본값과 동일 상수).

**통과 기준**(요구사항 그대로): `sim(다윗영역, frozen/david) > sim(다윗영역, frozen/goliath)`
**그리고** 골리앗도 대칭 성립.

### ⑤ 화풍이 통일되는가 — 잉크 밀도/대비 통계

후보 셋(그램 행렬 거리 · 색 히스토그램 거리 · 잉크 밀도/대비 통계) 중 **잉크 밀도/대비 통계**를
골랐다.

- **그램 행렬**은 사전학습 CNN(VGG 등)의 중간 특징이 필요한데 이 환경엔 torchvision이 없다 —
  새 의존성을 깔지 말라는 지시와 상충한다.
- **색 히스토그램**은 후보였으나, 다윗·골리앗 레퍼런스 자체가 이미 같은 팔레트(warm cream,
  muted)라 색 분포만으로는 SWEEP.md가 실측한 "잉크화" 경향(선의 굵기·대비 문제)을 못 잡는다.
- **잉크 밀도/대비**를 고른 결정적 근거: SWEEP.md가 이미 관측한 실패 양상이 정확히 이것이다 —
  "화풍이 잉크 만화 쪽으로 기움"(연필 동화=낮은 대비·옅은 선 vs 잉크 만화=높은 대비·굵고
  진한 선). 이 프로젝트의 실제 실패모드에 가장 직접 대응하고, PIL/numpy만으로 되며(에지 밀도 =
  인접 픽셀 명도차 15/255 초과 비율), 내용(누가 그려졌는가)과 무관하게 화풍만 잰다 — 요구사항이
  경고한 "CLIP은 내용에 반응한다" 문제를 애초에 피한다.

**계산**: 그레이스케일 (평균 밝기, 표준편차=대비, 에지밀도) 3차원을 12장 전체로 z-score
정규화한 뒤, 같은 시드의 (a)와 유클리드 거리를 잰다(요구사항: "각 조건의 화풍 거리를 같은
시드의 (a)와 비교"). 조건 내 3시드끼리도 같은 정규화 공간에서 쌍거리를 잰다("한 조건 안의
3시드끼리도 재라").

## 3. 완료기준 확인 — (b)는 ④에 실패해야 한다

**그대로 보고한다: (b)는 3시드 전부 실패하지 않았다.** `b_all_3_seeds_fail_q4 = False`.
3시드 중 2개(s11, s42)는 다윗·골리앗 둘 다 ④를 통과했고, **1개(s7)만 골리앗 쪽에서 실패**했다
(`sim_goliath_own=0.520 < sim_goliath_other=0.533`, 다윗은 그 시드에서도 통과).
`b_at_least_1_seed_fails_q4 = True` — 완전한 무력화는 아니다.

지표를 고쳐 (b)를 억지로 떨어뜨리지 않았다(요구사항 금지 사항). 대신 관측을 그대로 적는다:

- **오염이 아예 안 보이는 것은 아니다** — 골리앗 s7에서 정확히 예상한 방향(마스크 없이 두
  레퍼런스가 전체에 걸려 정체성이 섞임)으로 실패가 났다.
- **그러나 CLIP 교차 유사도는 이 오염에 그리 민감하지 않다.** `IP_SCALE=0.3`이 약하고
  ControlNet(강도 0.8)의 기하 조건이 "이 위치엔 소년, 저 위치엔 거인"이라는 구도를 이미
  강하게 못박아 두기 때문으로 보인다 — 게다가 프롬프트 자체가 나이·투구 유무로 두 인물을
  텍스트로도 갈라놓아, CLIP 임베딩이 (b)에서도 그 광역 의미 신호(나이·투구)만으로 대부분
  분리돼 버린다. 미세한 얼굴 정체성 혼입까지는 이 지표가 못 잡을 가능성이 있다.
- **결론**: 이 지표는 「완전히 무의미하지도, 완전히 유효한 게이트도」 아니다 — 오염을 **부분적으로만**
  잡는다(6인물-체크 중 1건 실패). (c)/(d)가 (b)보다 자기유사도가 대체로 더 높다는 방향성은
  있으나(예: 골리앗 자기유사도 c/d 0.639~0.647 vs b 0.520~0.577), 이 표본(3시드)만으로 「마스크가
  있어야 확실히 통과한다」는 강한 주장까지는 못 한다.
