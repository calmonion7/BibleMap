# S3 — 영역 마스크 파생 (task#315)

GoliathScene(`--at 9000`)에서 다윗·골리앗·배경 마스크 3장을 붓질 단계(`delay`) 범위로 파생했다.
새로 저작하지 않았다 — 이미 있는 stroke를 delay로 갈라 썼다.

## 1. 구획별 delay 재확인표

주 세션의 실측표를 그대로 전제하지 않고 `scripts/check_mask_ranges.py`로 다시 파생했다(정규식으로
`d(<숫자>)` / `delay={<숫자>}`를 뽑고 구획 주석으로 가르는, 같은 방법).

| 구획 | delay 범위 | 소스 occurrence 수(사람이 셀 때 보는 단위) | 고유 delay **슬롯** 수(마스크가 쓰는 단위) | stroke 요소 수(잉크 기준) |
|---|---|---|---|---|
| 배경(무대+시내) | 0–960 | 9 | 9 | 27 |
| 골리앗(서 있는 자세) | 1080–4800 | 31(d() 30 + 정본호출 1) | **32**(정본 `STEPS=2`가 2880·3000 두 슬롯 소비) | 84 + 정본 4 = **88** |
| 쓰러진 자세(유령) | 30–1110 | 10 | 10 | 30 (전부 잉크 0) |
| 다윗 | 4920–7560 | 22(d() 21 + 정본호출 1) | **23**(정본 `STEPS=3`이 6480·6600·6720 소비) | 57 + 정본 8 = **65** |
| 제외(충격 표시·흙먼지) | 7680–7920 | 3 | 3 | 9 |
| **합계** | | | | **219** (= `cond-scene-meta.json`의 `total_strokes`) |

재확인 결과 **주 세션 표는 정확하다** — "골리앗 n=31"·"다윗 물매 n=4(7320/7440/7440/7560 occurrence)"는
전부 **소스에 나온 g/컴포넌트 호출 occurrence를 센 것**이고, 인물 정본 컴포넌트(`cast/david.jsx`
`cast/goliath.jsx`)가 호출 하나로 내부에 `STEPS`개 delay 슬롯을 더 쓴다는 점만 다른 층위다. 마스크의
"연속성"은 occurrence가 아니라 **고유 슬롯 값**이 120ms 간격으로 끊김 없이 이어지는지를 봐야 하므로
(`check_mask_ranges.py`가 정본 파일의 `STEPS`·`STEP_GAP`을 읽어 펼친다), 이 표에 두 단위를 나란히 적었다.
잉크 기준 stroke 수(88·65)는 `render_scene.py --delay-range`로 실측한 값과 정확히 일치한다(아래 3절).

## 2. 범위 배정 — 골리앗 [1080, 4800] · 다윗 [4920, 7560]

`scripts/check_mask_ranges.py`의 `derive_ranges()`가 **유일한 정본**이다(마스크 생성 스크립트가
이 함수를 그대로 가져다 쓴다 — 범위를 두 곳에 옮겨 적지 않는다, ADR 260820-003946). 두 범위는
겹치지 않고(`max(골리앗) < min(다윗)`), 각각 120ms 간격으로 끊김 없이 이어진다 — 둘 다
`derive_ranges()`가 단정한다.

## 3. 두 충돌의 처분

### (가) 쓰러진 자세(delay 30–1110)가 배경·골리앗 범위와 수치상 겹친다

**처분: 소스 범위는 그대로 두고, 잉크 기준으로 런타임에 제외한다.** `--at 9000`에서 쓰러진 자세의
조상 `<g opacity={reduce?1:0}>`가 `opacity:0`이라(교체 페이드가 10.25s에 시작 — 9.0s보다 뒤) 이
구획의 stroke는 전부 **유령**(`visibility:visible`인데 잉크 0)이다. `render_scene.py`의
`_DELAY_FILTER_JS`는 `_VISIBLE_JS`와 같은 누적 opacity 판정(조상 사슬 곱 ≥ 0.02)을 델레이 범위
판정에 **함께** 걸므로, 이 30개 stroke는 delay 숫자로는 배경([0,960]) 구간과 값이 섞여도
자동으로 어느 마스크에도 잉크를 남기지 않는다. 실측: 다윗·골리앗 캡처 둘 다 `render_scene.py`가
"유령 선 30개"를 그대로 보고했다(두 캡처가 서로 다른 delay 범위인데도 유령 수가 동일 — opacity
게이트가 delay 범위와 독립적으로 작동한다는 증거).

### (나) 충격 표시(delay 7680)·흙먼지(7800·7920)가 다윗 범위 안에 있지만 다윗의 몸이 아니다

**처분: 어느 인물 범위에도 넣지 않는다 — 배경 여집합으로 둔다.**
- **충격 표시**(103.5–106.5, y13–15)는 골리앗 이마 위다. 다윗 delay 구간에 두면 다윗 마스크
  바운딩 박스가 골리앗 쪽으로 늘어나 겹침이 생긴다(직접 확인함 — 아래).
- **흙먼지**(x59–83.5)는 두 인물 사이 빈 허공이다. 다윗 쪽에 넣으면 바운딩 박스가 x14~83.5까지
  뻗어 골리앗의 방패(x79–89)와 맞닿는다.
- 둘 다 `check_mask_ranges.py`의 `excluded` 구획으로 갈라 다윗·골리앗 어느 delay 범위에도
  포함하지 않았다(`derive_ranges()`가 "제외 구획의 delay가 인물 범위에 섞였는지"까지 단정한다).
  배경은 인물 마스크의 여집합이므로 이 9개 stroke의 픽셀은 자동으로 배경에 간다.
- 이 결정이 실질을 잃지 않는 이유: 충격 표시의 좌표는 어차피 골리앗 정본(투구, cy=19, 상단
  y≈11–13)의 바운딩 박스 **안쪽**이다 — 골리앗 마스크가 이미 그 자리를 덮으므로 결과 픽셀은
  포함 여부와 무관하게 같다.
- **실측으로 확인했다**(`--delay-range 4920,7920`으로 제외 구간까지 포함해 따로 캡처 → 커밋하지
  않는 `/tmp` 산출물, 재현 가능): 제외 두 구간을 다윗 범위에 넣으면 다윗 바운딩 박스가
  `(189,219,439,545)` → **`(189,129,1082,545)`로 폭발한다** — 충격 표시 좌표(로컬 x≈103.5–106.5,
  1216px 캔버스에서 ≈x1079)가 최대 x를 골리앗 바운딩 박스(x793 시작) **한참 안쪽인 x1082까지**
  끌고 간다. 즉 이 두 stroke를 다윗 쪽에 넣으면 겹침은 미세한 경계 문제가 아니라 **x793~1082
  (약 289px, 두 인물 폭을 합친 것보다 큰) 대규모 겹침**이 된다 — (나)를 배경으로 돌리는 처분이
  분명한 정답임을 확인한다.

## 4. 선→면 변환 — 바운딩 박스

**바운딩 박스를 골랐다**(볼록껍질·팽창 대신). 근거:
1. **두 인물이 화면에서 완전히 좌우 분리돼 있다** — 실측 바운딩 박스가 다윗 x[189,439], 골리앗
   x[793,1190](1216폭 캔버스)로 **354px(≈29%) 간격**을 두고 떨어진다. 팽창이나 볼록껍질이 주는
   이점(오목한 부분을 메움)이 겹침 회피에는 필요 없다 — 분리 자체가 이미 크다.
2. **파라미터가 없다** — 팽창 반지름 같은 값을 튜닝할 필요가 없어 eco(표준 라이브러리 min/max만).
3. **계획이 경고한 두 실패(헐거움/빡빡함) 중 "빡빡해서 인물 윤곽이 잘림" 쪽을 확실히 피한다.**
   선화는 윤곽선뿐이라 팔다리 사이·소매 안쪽처럼 실제로는 "그 인물"인 자리에 잉크가 없는 곳이
   많다 — 팽창은 그 구멍을 완전히 메우지 못할 수 있지만 바운딩 박스는 절대 인물의 어떤 부위도
   자르지 않는다. 대가로 "헐거움"(사지 사이 빈 배경까지 인물 영역에 포함)을 의도적으로 받아들인다
   — S4가 실제 생성물에서 화풍 번짐을 관측하면 그때 팽창/볼록껍질로 좁히는 것이 후속 후보다.

## 5. 겹침·커버리지 (완료기준)

`make_masks.py` 실행 결과(1216×640 = 778,240px):

```
delay 범위 — 다윗 (4920, 7560)  골리앗 (1080, 4800)
다윗 bbox(x0,y0,x1,y1)   = (189, 219, 439, 545)  잉크 21271px
골리앗 bbox(x0,y0,x1,y1) = (793, 110, 1190, 562)  잉크 52326px
겹침 픽셀 = 0 (기대 0)
커버리지 = 화면 전체 778240px, 모두 정확히 1회 피복 확인
```

스크립트가 두 단정을 코드로 건다(`assert`, 실패 시 예외로 중단) — 겹침 0, 그리고 세 마스크
(다윗+골리앗+배경) 각 픽셀의 피복 횟수 합이 전부 정확히 1. `Read`로 마스크 3장을 열어 육안으로도
확인했다 — 다윗 흰 영역이 화면 왼쪽, 골리앗 흰 영역이 오른쪽에 있고, 배경 마스크는 그 둘의 정확한
여집합이다.

## 6. 게이트 발화 확인 (ADR 260823-221839 따름 정리 3)

`scripts/check_mask_ranges.py`가 「다윗·골리앗 delay 범위가 연속하고 겹치지 않는다」를 소스에서
단정한다(브라우저 불필요 — deploy.sh가 빌드 **전**에 부르므로 :8080이 옛 빌드인 시점에도 항상 돈다).
`scripts/check.sh`에 두 줄로 배선했다:

```
run "check_mask_ranges" python3 scripts/check_mask_ranges.py
run "check_mask_ranges --selftest" python3 scripts/check_mask_ranges.py --selftest
```

`--selftest`는 합성 소스로 **고의로 범위를 섞어**(겹침 1건·불연속 1건) 검사가 정확히 실패하는지
인메모리로 확인한다 — 실제로 실행하면 두 위반 모두 `AssertionError`로 잡힌다:

```
selftest: 정상 소스 PASS {'goliath': (120, 240), 'david': (360, 480)}
selftest: 겹침 주입이 정확히 실패했다 — 두 인물 delay 범위가 겹친다: 골리앗 ≤240, 다윗 ≥240
selftest: 불연속 주입이 정확히 실패했다 — 다윗: delay 불연속 360→730 (간격 370, 기대 120)
```

`CHECK_STRICT=1 bash scripts/check.sh` **전항목 PASS**(check_mask_ranges 포함) 확인 완료.
