# 정본 참조 편집 판정 — Qwen-Image-Edit-2511 (task 359)

358은 Qwen-Image-2.1 edit 세기 0.7로 「다른 길」(사울 1/8 · 다윗 2/8)이었다. 그러나 사후 조작 확인에서 0.7은 몸 상자 안 변화가 5.0/255로 사실상 무처치였다(`REF-EDIT.md` 끝 절). 이번에는 상업 이용이 가능한 **Qwen-Image-Edit-2511(apache-2.0)**로 같은 참조 편집을 다시 하고, 358과 같은 규칙에 조작 확인 하한을 더해 판정한다.

## 고정 절 (편집·판정 전 작성 — 결과를 보고 바꾸지 않는다)

### 모델과 「안 돔」

- **Qwen-Image-Edit-2511** 하나 — `mflux-generate-qwen-edit --model qwen-image-edit-2511`(mflux 0.22.0, `~/.local/biblemap-imggen/.venv-mflux`). 가중치 `Qwen/Qwen-Image-Edit-2511`(apache-2.0).
- 이 CLI에는 `--mask-image`·`--strength`가 없다 → **그림 전체를 편집**한 뒤 몸 상자만 되붙인다(아래).
- 스텝 20(mflux 기본), guidance 2.5(models/qwen README 기본). 미리보기 없이 고정.
- **양자화 사다리** q8 `--low-ram` → q6 → q4. 「안 돔」은 단계마다 **첫 1장**까지만 본다: 메모리 초과·깨진 출력·실행 오류, 또는 장당 10분 초과(스왑). 세 단계 모두 안 되면 판정 없이 `결론: 실행 불가`와 사유, `metrics.json` `stop`.
- 우회 구현(직접 포팅·커스텀 커널)은 하지 않는다.

### 바탕·대상·참조 (358과 같다)

- 바탕: 353 문구 Z-Image 1216×640. 시드 `[11, 42, 7, 23, 5, 101, 202, 303]` — 11·42·7은 `cast-v2-pilot/scene/`, 나머지는 `ref-edit/base/`(358에서 그린 것 그대로).
- 처치: 길갈 사울 · 엔게디 사울 → 다윗(사울을 되붙인 결과 위에 다윗 편집) · 라마 다윗. 편집 수 32.
- 참조(`--image-paths` 순서): 바탕(엔게디 다윗은 사울 되붙인 결과) · 정본 초상 `frozen/<id>.png` · 정본 전신 `lora-sheet-v2/<id>/07.png`.
- 지시문: 358 틀에서 「the person in the masked area of image 1」만 위치로 바꾼다 — 「Replace the man on the {left|right} in image 1 with the man shown in image 2 and image 3 — same face, hair, beard, body build and clothing. Keep his pose and position, and keep the pencil and watercolor drawing style, lighting and everything else of image 1 unchanged.」 좌우는 그 장면 정본 인물 둘의 머리 상자 x 중심 순서(세 장면 모두 정본 인물이 둘이라 「the man」 단독형은 쓰이지 않는다).
- 출력 1216×640, 시드 = 바탕 시드.

### 되붙임

- 몸 상자 = 358 `gen_ref_edit.make_mask` 그대로(OWLv2 「a person」 상자 + 위로 머리 높이 하나 + 각 변 6%).
- 되붙임 = 편집 원본(전체)에서 **몸 상자 안만** 바탕에 얹는다. 경계는 상자 마스크를 가우시안 반경 8px(`REF_EDIT_2511_FEATHER`)로 흐린 알파로 섞는다. 상자 밖 픽셀은 바탕 그대로 → 「대조와 처치의 차이는 편집 하나뿐」 유지.
- 산출: 전체 편집 원본 `~/.local/biblemap-imggen/ref-edit-2511/raw/<장면>/s<시드>-<인물>.png`, 되붙인 최종 `edit/<장면>/s<시드>.png`(엔게디 사울 중간본은 `s<시드>-saul.png`).

### 조작 확인 (358 회고에서 더한 관문)

- `mask_diff` = 되붙인 결과와 **그 편집의 입력 그림**(엔게디 다윗은 사울 되붙인 결과, 나머지는 바탕)의 **몸 상자 안 평균 픽셀 차**(0~255, RGB 평균).
- 이 식은 358 기록을 그대로 재현한다(2026-10-17 확인): 358 미리보기 세기 1.0 = 17.32·42.58 → 평균 29.95, 0.7 = 5.3, 본 편집 32장 = 4.88(입력 그림 기준)·4.97(바탕 기준). 시드에 따라 변화 폭이 크다(1.0에서 17~43).
- S0 첫 1장 mask_diff **≥ 10**이어야 본 편집으로 간다. 32장 평균 `mask_diff_mean` **≥ 10**이어야 판정 페이지를 게시한다. 미달이면 그 자리에서 멈추고 사용자에게 묻는다(`stop`).

### 판정 규칙 (358 `REF-EDIT.md` 「판정 규칙」과 같다)

- 보기 방식: 카드 폭 356 CSS px(DPR 3), 확대·크롭 없음, 대상 머리 위 ▼, 두 장면 위/아래, 한 화면 한 질문, 폰용 비공개 Artifact.
- 화면 A 2(사울 길갈↔엔게디, 다윗 엔게디↔라마): 처치 8쌍 + 대조 3쌍(353 s11·42·7 바탕끼리), 고정 시드 359로 섞는다. 「두 ▼가 같은 사람으로 읽히는 쌍을 누르기」.
- 화면 B 1: 엔게디 처치 8장 「두 ▼ 인물이 서로 닮아 구별이 안 되는 그림을 누르기」.
- 화면 C 3: 장면마다 기준(345 승인본, 라마는 353 s11) + 처치 8 + 대조 3, 시드 359로 섞음. 「연필 화풍이나 장면 뜻이 기준보다 크게 무너진 그림을 누르기」.
- 분해능: 화면 A 대조 「읽힌다」 합 ≤ 2/6. 넘으면 `판정: 보류`.
- **채택** = 분해능 충족 + 사울·다윗 모두 「읽힌다」 ≥ 5/8. (처치 무너짐 비율 − 대조 무너짐 비율) > 0.5면 조건부로 내린다(세 장면 합산). **조건부** = 한 명만 ≥ 5/8 또는 화풍 감점. **다른 길** = 그 밖.
- 결론 줄 끝: 「영상 패키지 사용: 가능(apache-2.0)」.
- 채택이면 ADR `260904-055320`을 뒤집는 새 ADR(실측표 포함). 조건부·다른 길이면 그 ADR 개정 메모에 결과 한 줄.
- 판정 결과 표에 `mask_diff_mean`과 장면별 평균을 같이 적는다.
- 쌍·그림 번호 ↔ 처치/대조·시드 대응은 **게시 전에** `samples/ref-edit-2511/metrics.json` `screens`에 적는다.

- **q6 — 안 돔.** 길갈 사울 s11: 스텝당 약 175초(첫 스텝 221초), 20분 제한에서 6/20스텝.
- **q4 — 안 돔.** 길갈 사울 s11: 스텝당 약 145초(첫 스텝 210초), 20분 제한에서 7/20스텝(장당 약 48분 속도).
  - q4 실행 중 30초 간격 `vm_stat` 기록: 스왑 출입이 크게 오간 것은 모델 적재 구간(첫 약 3분)뿐이고, 디노이징 스텝 동안은 30초당 수천 페이지(수십 MB)에 그쳤다. → **느린 원인은 메모리(스왑)가 아니라 계산량이다.** 양자화를 q8 → q4로 내려도 스텝당 180 → 145초로 거의 그대로인 것과 맞는다.
  - mflux 0.22.0 `variants/edit/qwen_image_edit.py`: guidance가 있으면 스텝마다 트랜스포머를 **두 번**(긍정·부정 프롬프트) 돌리고, 조건 그림 3장(바탕·초상·전신)이 함께 들어간다. 358의 2.1 edit는 guidance 없이 한 번이었다(25스텝 전체 211초). 추정: 모델 크기(2511 20B급 대 2.1 7B, 약 3배) × 2회 계산(2배) × 조건 토큰 증가가 약 20배 차이를 만든다(조건 그림 토큰 수는 직접 재지 않음).
  - **모델 크기 정정(2026-10-17, 사후):** 계획·고정 절은 2.1을 2511과 「같은 20B급」으로 적었지만, Qwen-Image-2.1 공식 카드는 그림 생성부 7B(Single-Stream DiT 32층) + 인코더 Qwen3-VL 8B다. 2511은 Qwen-Image 계열 20B MMDiT다.
- 세 단계 모두 안 돔 → 고정 절대로 **판정하지 않고** `metrics.json` `stop`에 사유를 적었다. 본 편집(S1)·판정 페이지(S2)는 하지 않는다.

## 후속 시험 — Lightning 4스텝 LoRA (2026-10-17, 판정 아님 · 다음 과제 근거)

359 「실행 불가」 뒤 사용자 요청(「권고 진행」)으로, Apache 그대로인 `lightx2v/Qwen-Image-Edit-2511-Lightning` 4스텝 LoRA(bf16 850MB)를 붙여 같은 첫 1장(길갈 사울 s11, q8 `--low-ram`, 참조 3장)을 4스텝 · guidance 1로 돌렸다(`try_ref_edit_lightning.py`).

- **mflux는 guidance 값과 상관없이 스텝마다 부정 프롬프트 계산을 한 번 더 한다** → guidance 1이면 혼합식에서 상쇄되므로, 부정 차례에 긍정 결과를 돌려주는 실행용 래퍼 `mflux_qwen_edit_cfg1.py`를 만들었다(설치 패키지 무수정).

|---|---|---|---|---|---|---|
| plain | 고정 절 그대로 | 870.6초 | 약 200초 | 58.5GB | — (mask_diff 12.23) | — |

- plain과 cfg1의 원본 그림 차이: 평균 0.053/255, 최대 12 → 래퍼는 결과를 바꾸지 않는다(반올림 수준).
- **조작 확인 지표 결함:** 「몸 상자 안 mask_diff ≥ 10」은 전체 편집 → 되붙임 방식에서 재렌더 잡음(상자 밖 약 15)만으로 통과한다(첫 행: 12.23인데 실제로는 무처치). 이 방식의 조작 확인은 **상자 안 변화 − 상자 밖 변화**(또는 비)로 재야 한다. 358 2.1 세기 1.0(마스크 편집)은 안 42.6 / 밖 0.01이었다.
- 피크 58.5GB는 실제 메모리 32GB를 넘는다 — LoRA 합치기 적재 단계의 스왑으로 추정(스텝 시간에는 큰 영향 없음).
- **정본 정의와 정본 전신 그림의 어긋남:** 사울 카드 층(`cast_describe`)은 「broad shoulders, thick barrel torso … dark wool tunic」인데, 참조로 넣는 전신 `lora-sheet-v2/saul/07.png`은 마른 체격·갈색 겉옷이다. 손으로 쓴 시험 지시문의 「lean, brown tunic」은 그림 쪽을 따랐다.
