# 인물 소개(Person Context) 저작 규칙

`people.json`의 소개 항목이 따라야 하는 정본 규칙. 큐레이션 인물 및 책 상세 「주요 인물」에 노출되는 여정 없는 인물에 대해 구절 근간의 짧은 소개 데이터를 저작하기 위해 제정.

## 1. 목적

**구절 근간 소개 데이터**(큐레이션 인물 + 책 상세 「주요 인물」에 노출되는 여정 없는 인물). 각 인물이 누구인지, 무엇으로 알려졌는지를 담백한 산문 한 단락과 근거 구절 목록으로 제공한다.

## 2. 데이터 위치·키

- 위치: `data/person_context/people.json`
- 키: theographic_id (Airtable record id, 예: `recyYgUiSETdWFgEP`)

## 3. 스키마

```json
{
  "recyYgUiSETdWFgEP": {
    "role": "최초의 사람",
    "intro": "아담은 하나님이 흙으로 지으신 최초의 사람이다. 하나님이 그 코에 생기를 불어넣으시니 생령이 되었다. 그러나 아내와 함께 선악과를 먹어 죄와 사망이 세상에 들어오게 하였다.",
    "verses": [
      { "ref": "창 2:7", "textKo": "…", "textEn": "…" },
      { "ref": "창 3:6", "textKo": "…", "textEn": "…" }
    ]
  }
}
```

## 4. 규칙

### 규칙 1 (최우선) — 근거 구절 원칙

**모든 소개·역할은 성경 구절을 근간으로 한다. 근거 구절 없는 진술은 금지.** `intro`의 모든 사실 주장은 `verses` 중 하나로 뒷받침되어야 한다. 뒷받침할 구절이 없는 진술은 쓰지 않는다.

### 규칙 2 — 톤

담백·설명적으로 쓴다. `book_context`의 톤(사실 서술 중심, 신학 용어는 절제)과 일치시킨다. 교리 중립을 지킨다 — 교파 고유 교리(예: 특정 구원론·종말론 해석)는 피하고 전통적·통설적 견해만 다룬다.

### 규칙 3 — 분량

- `role`: 짧은 명사구, 8자 내외 (예: "최초의 사람", "믿음의 조상").
- `intro`: 2~3문장, 300자 이하.

### 규칙 4 — verses

- 최소 1개 이상.
- `verses[0]`은 그 인물을 대표하는 구절.
- `ref`는 개역 약어 + 장:절 (단일 절 우선, 범위는 꼭 필요할 때만).
- `textKo`/`textEn`은 손으로 쓰지 않는다 — `generate_verse_text.py`가 프리베이크한다. 저작 시점에는 `ref`만 채운다.

## 5. 2단 품질 계층 (ADR-0027 — 가계도 폐포 전원 커버)

가계도 폐포 인물 전원 커버(task#195)부터 항목은 두 계층으로 나뉜다:

- **서사 인물**(성경에 이야기가 있는 인물): 위 규칙 그대로 — `role` + `intro` 2~3문장 + `verses`.
- **족보 단역**(계보 목록에만 등장): `intro` 없이 `role` 사실형 한줄(예: "유다와 다말의 아들, 베레스의 형제" — 부모·형제·자녀·등장 계보 등 성경 기록 사실만) + `verses` 1~2개. 전원 산문 저작은 지어내기(규칙 1 위반)를 강제하므로 사실형 한줄이 상한이다.

계층 구분은 스키마상 `intro` 유무로 표현된다(별도 필드 없음). 근거 구절 원칙(규칙 1)은 두 계층 모두 동일하게 적용된다.
