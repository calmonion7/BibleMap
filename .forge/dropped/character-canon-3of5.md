# 2층 얼굴 후보 생성 — 정본을 조건으로 인물당 후보를 뽑는다 (무인)

## Goal / Non-goals

- **Goal**: 2/5의 SVG 정본을 **조건 입력으로** 인물별 얼굴 후보를 생성하고, 사람이 한 자리에서 고를 수
  있는 **대조표**까지 만든다. 여기서 멈춘다 — **선택은 4/5**다.
- **왜 여기서 자르는가**: 선택은 사람 판정이고, 워크플로우는 실행 중 사람 입력을 받을 수 없다. 한 계획에
  넣으면 중간 사인오프가 생긴다(PLAN-FORMAT 분할 규칙 (a)).
- **Non-goals**: 후보 **선택**·동결(4/5) · 쌍거리 임계 확정(4/5) · 생성 배선(5/5) · 장면 재생성.

## Source of truth

- ADR `260824-075708` ①(2층은 1층을 조건으로 뽑은 후보에서 **사람이 고른다**) · ④(선택 분담) ·
  ⑤ + ADR-0025 2026-08-24 개정(**예수 포함**, 다만 *「신성한 인물의 얼굴은 절제한다 — 이목구비 최소,
  광휘·자세로 무게」*).
- **생성 스택 정본**: `~/.local/biblemap-imggen/`(레포 밖) + task#308의 동결 설정 —
  SDXL base 1.0 + `xinsir/controlnet-scribble-sdxl-1.0` · 30스텝 · guidance 6.5 · MPS.
  구동 선례: `.forge/reports/storyboard-density/run_grid.py`.
- **task#308이 남긴 실측 규칙 넷**:
  ① **조건 입력은 「연출 종료 후」가 아니라 「잉크가 최대인 순간」에 찍는다** — 교체 페이드가 있는 장면은
    종료 시점이 **의도적으로 단순화된 상태**다(골리앗 88선 → 30선). `render_scene.py`가 이제 유령 선 수를
    경고로 낸다.
  ② **조건 입력에 들어간 것은 무엇이든 구워진다** — 글자뿐 아니라 **아이콘도**(확대 버튼이 구워진 실측).
    `--no-labels`가 svg 밖 패널 내용을 전부 숨긴다.
  ③ CLIP **77토큰** 상한(초과분 조용히 잘림). SDXL은 인코더가 둘이라 `prompt_2`로 **서로 다른 내용**을
    줄 수 있고, `prompt_embeds` 직접 주입이면 상한 자체가 사라진다.
  ④ **프롬프트가 조건 입력과 같은 것을 말해야 한다** — 어긋나면 실패 원인이 갈라지지 않는다.
- **원가 실측**: 1216×640·30스텝 ≈ 90~105초/장(MPS 단독). **GPU와 브라우저 렌더를 동시에 돌리지 않는다**
  (58초 → 98초로 떨어진 실측, task#305 회고). 렌더를 먼저 다 끝내고 GPU를 시작한다.

## Slices

### S1. 정본 → 조건 입력 (브라우저 렌더 구간, GPU 정지)
`#/cast`에서 인물별 머리 정본만 이름표·오버레이 없이 촬영하고, 얼굴 시트용 조건 입력으로 변환한다
(2값화 레시피는 `.forge/reports/storyboard-density/prep_ctrl.py` 승계).
- **완료기준**: 인물 수만큼 조건 입력 PNG가 생기고, 각각 **텍스트 노드 0 · 유령 선 0**을 렌더 시각에
  스크립트가 단정한다(사후 주장 아님).

### S2. 프롬프트 설계와 토큰 게이트
인물별 프롬프트를 조합표의 5축에서 **파생**한다(손으로 쓰지 않는다 — 조합표가 정본이므로). 화풍 블록은
장면 생성과 같은 것을 쓴다(정본 얼굴과 장면 화풍이 어긋나면 레퍼런스가 안 먹는다).
- **완료기준**: 전 인물 프롬프트가 CLIP 상한 안이고(초과 시 **하드 실패**), 각 프롬프트의 5축 서술이
  `roster.json`과 일치함을 스크립트가 대조한다.

### S3. 후보 생성 (무인)
인물당 후보 4장(시드 4개). 예수는 ADR-0025의 절제 조항을 프롬프트·네거티브에 반영한다.
- **완료기준**: `.forge/reports/character-canon/candidates/<slug>-s<seed>.png` 가 인물수×4장 존재하고,
  전수 sha256이 서로 다르며 각 파일 ≥ 50KB. **중간에 죽어도 재개 가능**해야 한다(존재 파일 건너뛰기).

### S4. 선택용 대조표 조립
인물별 후보 4장을 한 장에 묶고, **인물 이름·slug·5축을 칸 안에 각인**한다. 4/5의 사람이 한 자리에서
고를 수 있어야 한다.
- **완료기준**: 인물 수만큼 대조표 PNG가 존재하고, 크기가 상수에서 재계산한 규격과 일치한다.

## Definition of Done

1. `CHECK_STRICT=1 bash scripts/check.sh` 전항목 PASS.
2. 조건 입력 PNG가 인물 수만큼 있고, 메타 JSON이 전수 `text_nodes: 0` · `ghost_strokes: 0` 기록.
3. `candidates/` 가 인물수×4장이고, 튜플 집합이 `roster.json` × 시드 4개를 **정확히** 덮으며,
   sha256 전수 상이 · 최소 50KB.
4. 대조표 PNG가 인물 수만큼 존재하고 규격 일치.
5. 프롬프트 전수가 CLIP 상한 안이고 5축이 `roster.json`과 일치.

## 리스크

- **원가.** 인물 74명 × 4장 × ~95초 ≈ **8시간** 무인 GPU. 재개 가능성이 필수다.
- **얼굴만 뽑을 것인가 전신을 뽑을 것인가.** raster-pilot 실측은 *「시트 전체를 물리면 얼굴뿐 아니라
  레이아웃까지 전이돼 장면이 「인물 나열」이 된다 → 얼굴 크롭 1컷」* 이다. 다만 **영역 마스크가 생긴
  지금은 그 실측이 다시 볼 값**일 수 있다(마스크가 레이아웃 전이를 가둔다). 이 파트는 **얼굴 크롭을
  기본으로** 가되, 전신 시트가 필요하다는 신호가 나오면 5/5의 배선 검증에서 판정하고 여기서 해결하지 않는다.
- **1층의 정보량이 얇다** — 원 + 실루엣뿐이라 후보 4장이 서로 크게 다를 수 있다. 그것이 정상이고,
  좁히는 것은 4/5의 선택과 게이트다.
