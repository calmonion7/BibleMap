# BibleMap — 도메인 용어집

## 구절 근거 원칙 (verse-grounded principle)

이 사이트가 사용자에게 보여주는 모든 분석·서술 정보는 **성경 구절을 근거로 삼는 것이 제1규칙**이다. 근거 구절 없는 진술을 화면에 두지 않으며, 데이터를 만들거나(저작·큐레이션) 지우는(중복 제거 등) 작업은 결과물이 구절 근거를 잃지 않는지를 기준으로 검증한다 — 인물 소개·성품이 진술마다 근거 절을 다는 것, 사건이 근거 구절(📖)을 갖는 것이 모두 이 원칙의 사례.
_Avoid_: "참고 구절"(장식적 인용이라는 뉘앙스 — 구절은 장식이 아니라 근거다)

## Theographic ID

Theographic Bible Metadata 레포에서 사용하는 Airtable 레코드 ID. `rec` 접두사로 시작하는 14자 문자열 (예: `recv0dAY2ULzJ687g`). 모든 엔티티(Person, Place, Event, PeopleGroup)의 안정 키. 영문명은 동명이인이 존재하므로 조인·참조 기준으로 사용하지 않는다. Neo4j 노드의 `theographic_id` 속성으로 저장된다.

## publish 레코드

Theographic 데이터에서 `fields.status == "publish"`인 레코드. 데이터가 검수 완료된 상태. `status == "wip"` 레코드는 미완성이므로 BibleMap 적재에서 제외한다.

**예외 — 가족 폐포 wip 인물 (ADR-0021)**: Person에 한해, publish 인물에서 가족 필드(father/mother/children/partners/siblings)로 도달 가능한 wip 레코드는 노드로 적재한다. [[가계도-family-tree]]의 혈통 완전성을 위해서다(다윗의 자녀 21명 중 publish는 솔로몬뿐). 단 3중 격리를 지킨다 — `status: "wip"` 속성 마킹, **가족 간선만** 적재(사건 참여·그룹 등 나머지 간선은 publish 전용), `/search` 결과에서 제외. 폐포 밖 wip(고아 섬)과 Person 외 엔티티는 여전히 전면 제외다.

**엔티티별 status 필드 유무**: Person·Place는 `status` 필드가 있다. Event·PeopleGroup은 `status` 필드가 없으므로 "전체 포함"으로 처리한다(`fields.get("status", "publish") == "publish"` 패턴). Verse·Book·Chapter 등 추가 엔티티를 적재할 때는 `status` 필드 유무를 먼저 확인해야 한다.

## Period

별도의 엔티티 타입 없음. 성경의 시대(족장 시대, 왕국 시대 등)는 `Event` 노드의 `PART_OF` 관계로 표현한다. 상위 Event가 하위 Event들을 포함하는 계층 구조.

## Book

성경 각권을 나타내는 Neo4j 노드 (label: `Book`). Theographic `books.json`에서 적재. 주요 속성: `theographic_id, name, nameKo, testament(구약/신약), genre, authorKo, startYear, endYear, chapterCount`. 추가 속성(LLM 생성 후 주입): `background`(시대적 배경 텍스트), `themes`(성경 주제 배열), `keyVerse`(대표 구절 참조). Book → Event 관계는 `CONTAINS_BOOK`.

**CONTAINS_BOOK 관계 생성 방법**: `Book.verses ∩ Event.verses` 교집합. Theographic events에 scripture 직접 참조 필드가 없으므로, Book이 포함하는 구절 배열과 Event의 구절 배열의 교집합이 비어있지 않으면 `CONTAINS_BOOK` 관계를 생성한다 (`load_books.py`). 파이프라인 재실행·관계 수정 시 이 방식을 유지해야 한다.

**의미**: `(Book)-[:CONTAINS_BOOK]->(Event)`는 "그 책이 그 사건을 기록한다" = **사건의 성경적 근거**를 뜻한다. 한 사건을 여러 권이 기록할 수 있다(예: 공관복음 평행 기사 → 마/막/눅).

**발생(primary) vs 회고 인용 (ADR-0012)**: 한 사건의 참조가 여러 책에 걸칠 때, **첫 참조(authored=`books[0]`, theographic=`verses[0]`의 책)가 발생 위치**이고 나머지는 **다른 책의 회고 인용**이다(예: 아브라함 부름은 창세기에서 *발생*하고 사도행전 스데반 설교가 *인용*). 관계에 `primary` 불리언으로 구분하며, Book의 "주요 사건(topEvents)·주요 인물(topPersons)·지도 장소"는 `primary` 관계만 집계한다(회고 인용이 그 책 파생 뷰를 오염시키지 않도록). 반대로 사건 행의 📖 근거 칩(사건→기록 책)은 인용도 정당한 근거라 primary로 거르지 않는다. 한계: 서신서가 신학적으로 회고하는 사건(히 11장 믿음의 선진 등)은 verses[0]가 그 서신이라 서신을 발생으로 오판정할 수 있다(서신서는 CONTAINS_BOOK으로 연대·발생 판정 불가 — 실 저작일은 [[저작-사건-authored-event]]). 사건의 날짜가 없는 책(서신서·시편·잠언 등 31권)은 이 관계가 없어 사건 근거 칩으로는 등장하지 않고, 대신 추정연도 단독 마커로 배치된다(아래 "사건의 근거" 참조). 이 31권은 별도의 **book_events 오버레이**(아래 항목)로 "집필 배경·저자·직접 다루는" 사건과 약하게 연결되어 마커 행에 사건 칩이 표시되지만, 이는 `CONTAINS_BOOK`(권위 그래프·구절 교집합)과 별개의 추정 연결이다.

## Character Trait (인물 성품)

Person 노드에 주입되는 속성 `traits` (JSON 문자열 배열). 각 항목: `{trait: "겸손", verse_ref: "민 12:3", description: "..."}`. LLM(Claude API)으로 생성 후 수동 검수, `data/character_traits/people.json` → `inject_person_traits.py`로 Neo4j 주입.

**성품의 정의 (task#157)**: 시간·상황을 관통해 반복 확인되는 **지속적 인격 특질** — 미덕과 결함을 모두 포함한다(성경은 인물을 미화하지 않으므로 다윗의 통회·야곱의 기만처럼 결함도 정직하게 싣는다). 행위·사건(예배·찬양), 칭호·신분(하나님의 마음·메시아 계보), 은사·능력(괴력·예언), 시기·이력(말년의 타락)은 성품이 아니다 — 행위는 성품의 *증거*로 verse_ref·description에만 담는다. 라벨은 **통제 어휘**(미덕 24+결함 8) 안에서만 쓰며, 정본 규칙·어휘 표는 `data/character_traits/AUTHORING.md`, 기계검증은 `validate_traits.py`.

## Book Context (권별 컨텍스트)

각 Book의 시대적 배경·주제·대표구절을 담는 정적 JSON (`data/book_context/books.json`). LLM(Claude API)으로 생성 후 수동 검수. `inject_book_context.py`로 Book 노드 속성에 주입. Verse 텍스트(대표구절·인물 성품 인용절)는 **빌드타임에 getbible에서 한국어(`korean`)+영어(`kjv`)로 미리 받아 데이터에 함께 저장**한다(`generate_verse_text.py`, ADR-0003) — 런타임 외부 fetch 없음. 단 **사건 근거 절 본문은 인라인이 아니라 정본 절 사전**(`data/bible/verses.json`, 전권 31,103절 프리베이크)에서 `/event/{id}/verses` 응답 시 합성한다(ADR-0015 — event_verses는 verseID 참조만 보유). Book의 대표구절 본문은 `keyVerseTextKo`/`keyVerseTextEn` 속성으로 주입된다.

## Place Context (장소 컨텍스트)

좌표가 있어 지도에 뜨는 장소(43개)의 **성경적 배경 산문(`background`)·대표구절(`keyVerse`)**을 담는 정적 JSON (`data/place_context/places.json`, dict 키=장소 id). **Book Context의 장소판** — 구조·파이프라인이 동일하다: LLM 직접 생성(ADR-0006, `place_coords`의 `note`를 시드로) → 대표구절 본문 빌드타임 프리베이크(`generate_verse_text.py`의 `bake_place_context`, `keyVerseTextKo`/`keyVerseTextEn`) → `inject_place_context.py`로 Place 노드에 4개 필드(`background`/`keyVerse`/`keyVerseTextKo`/`keyVerseTextEn`)만 SET. **실제 노드의 서술 보강이라 오버레이가 아니라 주입**한다(추정 독립 데이터만 오버레이하는 ADR-0004 원칙 — book_context와 동일 선례). SidePanel은 `node.label === 'Place'` 블록에서 "장소 배경"·"대표 구절"(한/영 탭) 섹션으로 렌더한다. 기존 `note` 필드는 시드로만 쓰고 보존(미렌더).

## 추정연도 (placementYear)

사건-구절 교집합(`CONTAINS_BOOK`)이 없어 `startYear`를 못 얻는 31권에 부여하는 타임라인 배치 연도 (`data/book_years_approx/books.json`의 `placementYear`, `yearApprox=true`로 표시). **기준은 "작성(저작) 시점"이 아니라 "그 책이 속하는 사건/내용 시대"** — 정확연도 책의 `startYear`(그 책이 기록한 사건들의 `startDate` 최소~최대를 `load_books.py`가 집계)와 **같은 의미축**이다. 즉 추정/정확은 *의미*가 다른 게 아니라 *도출 방법*만 다르다 (정확 = 사건 집계 자동, 추정 = 사건이 없어 수동 추정). 구약 내러티브·시가서는 배경 시대로 배치하고(작성 시점은 `basis`에 곁들이되 배치엔 안 씀), 신약 서신서·계시록은 "쓰여 보내진 순간이 곧 그 책의 시대"라 결과적으로 작성 시점과 일치한다. 사건 연결(아래 Book Events ⚡)과는 **독립축** — 연결이 있어도 연도는 여전히 추정이다.

## 사건 연대 (startDate)

Event 노드의 발생 시점 속성. **혼재 형식의 문자열**이다 — 연도만("-4003", "30"), 연-월("-1451-01"), 연-월-일 3파트가 공존하고 BC는 음수 접두. 따라서 **문자열 사전순 정렬은 BC 연도를 역전**시킨다("-1451" < "-4003"). 정렬·비교·필터에 쓸 때는 반드시 연도를 파싱해 수치로 다룬다(부호 분리 후 첫 파트를 정수화 — 프론트 `dates.js`의 `parseYear`, 백엔드 nodes.py `_year`가 같은 규칙). 책의 `startYear`는 이 값을 집계해 파생된다(추정연도 항목 참조).

**정본 연대계는 현대 보수 연대계**다(출애굽 BC 1446 · 다윗 통치 1010–970 · 성전 착공 966, 분열왕국은 Thiele 왕 연대 — ADR-0014; 신약 앵커는 십자가 AD 33 — ADR-260722-070154). theographic 원본 연대는 구약이 Ussher계(출애굽 1491 등)·신약이 십자가 AD 30 기준으로 기록돼 있어 보수계로 저작된 [[저작-사건-authored-event]]·인물 여정과 한 타임라인에서 충돌했고, 교정 오버레이(`data/date_corrections/`, 구약 113 + 신약 138 = 251건)가 원본 이벤트의 `startDate`/`sortKey`를 정본계로 재정렬한다(task#158 구약, #237·238 신약 — 판정표 `.forge/reports/nt-corrections-*.md`). 신약 이관 규약: 원본·저작이 같은 장면이면 저작 앵커 **인접** 배치, 복음서 배열 충돌(마태 주제별 vs 마가·누가 연대순)은 이중 증언 우선, 연도 라벨은 인접 저작 앵커 라벨 준수. Person의 `birthYear`/`deathYear`는 UI 미사용이라 Ussher계로 잔존한다(노출 전 ADR-0014 재검토). **교정은 오버레이라 로더(load_theographic 등) 재실행이 되돌린다 — 재적재 후 `inject_date_corrections.py` 재실행 필수.**

**`sortKey`와 `startDate`는 별개의 두 정렬 축이며 서로 역전되면 안 된다.** `sortKey`는 서사 순서(투어 정차지·여정 정렬)를, `startDate`는 화면에 뜨는 연도를 결정하므로, 통합 시간축(여러 인물 파일을 `sortKey`로 정렬)에서 인접쌍의 `startDate`가 역전되면 정렬과 연도 라벨이 서로 다른 이야기를 한다. **새 사건을 저작할 때 `startDate`를 `sortKey`의 정수부에서 공식으로 뽑지 말고, 인접 앵커의 실측 `startDate` 사이에 들어가게 하라** — 기존 데이터는 절삭·내림 어느 쪽으로도 일관되지 않는다(`kadesh-spies` -1444.5 / sd -1445는 내림, `plains-moab` -1406.95 / sd -1406은 절삭). task#265에서 정수부 공식을 적용한 결과 기브롯 핫다아와·미리암 비방이 `sortKey`로는 가데스 정탐보다 앞이면서 `startDate`로는 뒤가 되는 역전이 생겼다([[저작-사건-authored-event]]의 앵커 프레임 정합과 짝을 이루는 규칙).

## Book Events (책-사건 연결 오버레이)

추정연도 책(31권 — `startYear` 없어 `CONTAINS_BOOK`이 없는 서신서·시편·잠언 등)을 타임라인 사건에 약하게 연결하는 정적 JSON (`data/book_events/books.json`, 형식 `{ "<bookId>": ["<eventId>", ...] }`). 연결 기준은 **집필 배경**(서신서→사도행전 사건)·**저자**(시편→다윗 통치)·**직접 다루는 사건**(역대하→솔로몬·유다 왕). LLM(Claude API)으로 생성하는 추정 데이터(`generate_book_events.py`)라 **Neo4j에 주입하지 않고** `/books` 엔드포인트가 런타임에 오버레이해 각 책에 `events` 배열로 실어 보낸다(`book_years_approx`와 동일한 분리 원칙 — 추정·권위 낮은 데이터는 권위 그래프 밖 오버레이로 유지, inject·재빌드 불필요). TimelineView의 책 마커 행은 이 `events`를 ⚡ Event색 칩으로 표시하고(클릭 시 그 사건 선택), 데이터가 없는 사건(예: AD57 이후 후기 서신·계시록, 포로귀환)은 빈 배열이라 칩이 없다. **CONTAINS_BOOK의 "사건의 근거"(구절 교집합) 의미와 무관** — 이 ⚡ 연결이 사건 행의 📖 근거 칩·구절 레이어에 합류하는 것은 **그 (권, 사건) 쌍이 event_verses에 근거 구절을 가질 때만**이다(예: 옥중서신의 "나의 매임" 자기 언급). 구절 근거가 없는 ⚡ 연결은 책 마커 행의 ⚡ 칩으로만 남고 사건의 근거로 승격되지 않는다 — **단 미보유 쌍은 0건이며, 이는 특정 시점의 관측치가 아니라 `scripts/check.sh`의 `validate_approx_book_verses`가 매 배포 강제하는 불변식이다**(task#274 — `VERSE_MAP` ↔ `book_events`를 죽은 키·미커버 쌍 양방향으로 대조하며, 어느 쪽으로 갈라져도 게이트가 비0으로 막는다 → ADR `260820-003946`). 그 구절은 `generate_approx_book_verses.py`의 `VERSE_MAP`이 권마다 **집필 배경을 드러내는 서문 절**(대개 1:1~1:2)로 부여하며, 그것이 사건 자체를 서술하지 않아도(야고보서 1:1이 예루살렘 공의회를 언급하지 않듯) 이 부류 전체에 일관되게 적용되는 설계다.

## 저작 사건 (Authored Event)

`startDate`를 가진 theographic 사건이 AD57(바울 1차 로마 투옥)에서 끊겨, 그 이후 쓰인 후기 서신·계시록(추정연도 31권 중 10권: 디모데전후·디도·벧전후·유다·요한1~3·계시록)이 매달릴 타임라인 사건이 그래프에 없다. 이를 메우려고 **그 책들이 쓰인 정황을 거꾸로 도출해 만든 추정 사건**이 저작 사건이다 — 성경 본문 밖 자유 역사 사건(예 예루살렘 함락 AD70)이 아니라 **고아 책 기반**(예: 계시록→요한의 밧모섬 유배(계 1:9), 디모데후서→바울 로마 2차 투옥·순교, 베드로전후→베드로 로마 사역·순교, 요한1~3→요한 에베소 만년 사역). theographic 검증 사건과 달리 LLM/수동 저작이라 권위가 낮다.

**오버레이가 아니라 Neo4j `Event` 노드로 적재하되 `authored:true`로 마킹한다 (ADR-0005)** — 사건은 `/events`·`/node/{id}`·`/node/{id}/places`·사건 링이 소비하는 **일급 엔티티**라, 오버레이로만 두면 ⚡ 칩 클릭 시 `/node/{id}`가 404가 되어 SidePanel·지도·링이 깨지기 때문(이 점이 *연도·링크* 오버레이를 다룬 ADR-0004와 갈리는 지점). `/events`가 `authored` 플래그를 노출하고 TimelineView가 `추정` 배지 + 범위 라벨로 표시한다. theographic ID(`rec` 접두)가 없어 `authored-<slug>` 식별자를 `theographic_id`에 부여한다. **`CONTAINS_BOOK`(📖 근거)을 갖지 않으므로** 사건 근거 칩을 오염시키지 않고, 후기 10권과는 **book_events 오버레이(⚡)** 로 연결된다(`CONTAINS_BOOK`이 아니라). 기존 Place(로마·밧모·에베소)·Person(바울·베드로·요한)에 `OCCURS_AT`/`HAS_PARTICIPANT`로 연결해 지도·링을 살린다. 연도는 정렬용 단일 `sortKey` + 표시용 범위 라벨(`yearLabel`)로 둔다.

## 저작 인물 (Authored Person)

성경인물탐험에 큐레이션하려는 주인공이지만 Theographic 그래프에 Person 노드가 없는 인물. 기존 큐레이션 16인은 실제 Theographic `rec` id를 재사용하지만, 재사용할 노드가 없으면 **마킹된 authored Person 노드를 새로 만든다 (ADR-0008)**. **단, theographic에 검증 가능한 대응 실레코드가 있으면(가족 링크의 성경 사실 일치로 판정) 저작 노드가 아니라 그 실레코드가 정식 신원이다 — 저작 노드는 원본에 아예 없을 때만 만들고 유지한다(ADR-0022, 사울·룻·기드온 등 11명 이관; 다니엘·엘리야만 저작 잔존).** `data/authored_persons/people.json` → `load_authored_persons.py`가 `MERGE (p:Person {theographic_id})` + `authored:true` + `name`/`nameKo`로 멱등 적재. 식별자는 `authored-person-<slug>`(저작 사건 `authored-<slug>`·저작 장소 `authored-place-<name>`와 같은 계열). **적재 순서 제약**: authored Person이 `load_person_events.py`보다 먼저 적재돼야 인물 여정 사건의 `HAS_PARTICIPANT` MATCH가 성립한다. authored **사건의 주변 참여자**(네로·에스더 등 — 카드·여정 없음)는 이 대상이 아니라 여전히 노드 없이 둔다(ADR-0005의 경계). 카드·여정·SidePanel·지도가 일급 Person으로 소비하지만 traits 부여는 별도 enrich 경로다.

**MERGE 로더의 추가·제거 비대칭**: `load_person_events.py`(및 authored 로더 계열)는 노드·간선을 `MERGE`만 한다 — 여정 사건·참여자 **추가**는 `data/*` 파일 편집 → 재적재로 반영되나(멱등), 관계형 필드 **제거**(`participants`에서 한 명 빼기 등)는 재적재로 사라지지 않아 **기존 간선을 Neo4j에서 직접 DELETE**해야 반영된다(이후 재적재 시 JSON에 없어 재생성 안 됨 = 멱등). 새 여정 사건의 완전 반영은 **①파일 편집 ②`load_person_events.py` 적재 ③api 재시작** 3단 세트이며, 적재 스크립트는 api 컨테이너에 없어(app·data만 복사) **호스트 python**(neo4j 127.0.0.1:7687 + `.env` 비밀번호)으로 실행한다. → [[여정-journey]]

## 화면 단계 (Stage)

앱 최상위 화면 전환 단위. 주요 단계 — **인물 허브(hub)**: 큐레이션 인물 카드 목록, 시작 화면(단, [[인트로-site-intro]]가 켜져 있으면 무해시 진입에서 인트로가 먼저 보인다). **탐험(explore)**: 선택한 인물의 여정 또는 [[테마 투어]]의 지도·타임라인 — 인물·투어 중 **하나가** 정차지를 공급하며 둘은 상호배타다(투어 구동 시 선택 인물 없음). **테마 투어 목록(tours)**: 테마 투어 카드 목록, 허브에서 진입. **성경 책 둘러보기(overview)**: 66권을 구약/신약·장르(율법서·역사서 등 10범주)로 훑는 화면. 사용자에게 노출되는 라벨은 **"성경 책 둘러보기"로 통일**한다 — "성경 개요"는 같은 단계를 가리키던 옛 표기로, 진입 버튼("성경 책 둘러보기")과 어긋나 혼동을 주므로 쓰지 않는다.

**stage 조건부 렌더 = 언마운트/리마운트**: App.jsx가 각 단계를 `{activeStage === 'x' && …}`로 조건부 렌더하므로 단계 이탈 시 그 화면 컴포넌트가 언마운트된다 — 스크롤 위치처럼 **세션 내내 유지해야 하는 상태는 컴포넌트 state로 못 지키고 모듈 스코프 메모리**(예: `scrollMemory.js`·`hubEntrancePlayed`)에 둬야 리마운트를 견딘다. 또한 인앱 "← 뒤로" 버튼은 popstate가 아니라 **전진 push**라(ADR-0010) `history.state`로도 인앱 뒤로 복원이 안 된다 — 뒤로 상태 복원 작업은 "그 뒤로가 popstate냐 전진 push냐"를 먼저 판별해 저장소를 고른다(모듈 스코프 메모리가 인앱·OS 뒤로 둘 다 커버).

**스테이지를 파일로 분리할 땐 언마운트 경계를 넘나드는 상태를 분리 컴포넌트가 소유하지 않는다**: 단계 하나를 별 컴포넌트 파일로 빼면 그 단계만 쓰는 상태도 함께 옮기는 게 자연스러워 보이지만, 조건부 렌더는 언마운트라 **그 단계를 벗어나도 유지돼야 하는 상태는 소실된다**(예: 탐험의 "족보" 탭은 탭 전환이 아니라 전용 단계 진입이어서 그 순간 탐험 화면이 언마운트된다 — 여정과 사용자가 고른 정차지가 날아가 복귀 시 재조회·선택 초기화가 된다). 코드만 훅으로 빼고 **수명은 언마운트를 견디는 생존 조상에 남긴다** → ADR-260801-183736.

**전역 헤더 밑 드레이프는 하위 내비 유무 두 스테이지를 함께 검증**: 책갈피 리본처럼 전역 헤더 밑에 드리우거나 덧대는 요소(ADR-0026 드레이프 관용구)는 허브(하위 내비 없음) 기준으로 설계돼, 하위 내비 바가 헤더 바로 밑에 붙는 나머지 단계(탐험·개요·책·족보·리더)에서 리본 꼬리가 탭을 덮은 선례가 있다 — 헤더 밑 드레이프/덧댐을 추가·수정할 땐 **"하위 내비 있는 단계 / 없는 단계" 두 경우를 함께 확인**한다. 드레이프 깊이는 `RIBBON_OVERHANG`를 단일 출처로 SpineHeader(리본 높이)·App(여백·패널 오프셋) 양쪽을 맞춘다(매직넘버가 흩어지면 어긋나는 결합).

## 인트로 (Site Intro)

사이트의 기능(인물 탐험·여정 지도·테마 투어·성경 책 둘러보기·가계도 등)을 소개하는 관문 화면. 특정 화면을 가리키는 주소 없이 들어온 진입에서만 대문(인물 허브)보다 먼저 보이며, 공유 링크(딥링크)로 들어온 사용자는 보지 않는다. 사용자가 끌 수 있고(끄면 허브 직행), 끈 뒤에도 소개를 다시 열람하는 경로는 남는다. **"대문"은 인물 허브를 가리키는 기존 용어로 유지한다** — 인트로는 대문 앞의 선택적 관문이지 대문의 대체가 아니다. → [[화면-단계-stage]]
_Avoid_: "온보딩 투어"(화면 위 코치마크 안내라는 뉘앙스 — 인트로는 독립된 소개 화면이다)

## 상세 시트 (Detail Sheet)

사용자가 선택한 대상(인물·장소·사건·성경책)의 상세 정보를 보여주는 화면 요소. **대상 종류와 무관하게 하나뿐**이다 — "인물창"·"책 상세창"·"레이어"처럼 따로 있는 게 아니라, 같은 시트가 선택 대상에 따라 담는 내용만 바꾼다. 데스크톱에선 화면 우측에서, 모바일에선 화면 아래에서 올라온다. 탐험 화면에서 지금 탐험 중인 인물 자신은 이 시트로 겹쳐 띄우지 않고(여정 흐름을 가리지 않도록) 그 외 대상을 고르면 뜬다. 허브 화면에는 선택 대상이 없어 시트가 없다. → [[화면-단계-stage]], [[selectednode]]

## selectedNode

프론트엔드 전역 상태. 현재 사용자가 선택한 엔티티의 `theographic_id`와 레이블(Person/Place/Event/Book)을 담는다. MapView / TimelineView 두 뷰가 이 값을 구독해 동시에 갱신된다. (GraphView는 제거됨.)

## 사건의 근거 (Scriptural Evidence)

특정 Event를 기록한 성경 본문. TimelineView의 데이터 흐름은 **연도 → 사건 → 성경권 → 성경구절**이며, 마지막 두 단계가 그 사건의 근거다. 권 단계는 `CONTAINS_BOOK`(사건 ↔ 권, 한 사건에 여러 권 가능), 구절 단계는 원천 theographic `verses`에서 사건·권별로 해석한 절들(인용 범위 + 본문)이다. 원천 theographic 사건 외에 **구절 사건(verse-event)** — 책의 *고아 구절*(어떤 Event에도 안 붙은 절)에서 도출해, 그 구절 없이는 타임라인에 안 뜰 서사에 시대 위치를 준 사건 — 도 근거 구절을 갖는데, 이들의 근거는 theographic event→verses 링크가 아니라 **그 책 고아 구절 범위에 앵커해 저작**한다(책 칩만 있고 구절이 비어 "표시할 구절이 없습니다"가 뜨던 갭을 메움). 타임라인은 사건을 척추로 두고 그 사건의 근거 권을 칩으로 붙여 보여준다. **한 사건의 근거로 어떤 권의 구절을 인정하는 기준은 두 패턴뿐이다 — (a) 평행 기사(같은 사건을 기록한 본문: 공관복음 평행 단락·역대기 평행·족보 언급), (b) 집필 정황 자기 언급(그 사건 중에 쓰인 책이 본문 안에서 그 정황을 스스로 증언: 옥중서신의 "나의 매임" 등). 어느 쪽에도 해당하지 않으면 구절을 만들지 않는다**([[구절 근거 원칙 (verse-grounded principle)]] — 외부 문헌비평 논거(저자 추정 등)는 본문 근거가 아니다). 중복 제거(dedupe)로 병합된 사건의 평행 기사 판정 범위는 남은 사건의 제목이 아니라 **병합 클러스터가 흡수한 장면 전체**다 — 예: "물 위로 걸어간 베드로"가 theographic "예수가 물 위를 걸으심"을 흡수했으므로 베드로 삽화가 없는 막 6장·요 6장의 같은 장면 기록도 이 사건의 평행 기사다. 단, 사건이 없는 책(`startYear` 없음 = `CONTAINS_BOOK` 미연결, 서신서·시편·잠언 등 31권)은 근거 칩이 아니라 추정연도(`book_years_approx`) 단독 마커로 표시되며, 사건이 없으므로 구절 근거 단계는 갖지 않고 클릭 시 권 개요만 보여준다. 다만 이 마커 행에는 **book_events 오버레이**(위 항목)로 그 책과 약하게 연결된 사건이 ⚡ 칩으로 곁들여 표시된다 — 이는 "사건의 근거"(권→사건 기록)가 아니라 책의 집필 배경·저자 맥락이라 방향·의미가 반대다.

**저작 사건의 구절 참조 표기 규칙**: `person_events`의 `context` 말미에 붙이는 참조(`(Exod 14:21–31)` 형식 — 구절 베이킹이 이 문자열을 파싱한다)는 **단일 연속 범위 하나**로 쓴다. 세미콜론·콤마로 두 구간을 적으면 `generate_person_event_verses`가 **같은 책의 두 번째 세그먼트를 무조건 드롭**한다. 진술이 두 구간에 걸치면 둘을 포함하는 단일 연속 범위로 넓히되(교차-장 허용 — `(Exod 32:1–34:28)`), 그 사이에 사건과 무관한 내용이 많이 끼어 억지 인용이 될 때는 **범위를 넓히는 대신 진술에서 그 요소를 빼라**(예: 만나 사건의 "광야 40년"은 근거가 16:35뿐이고 16:16–34에 오멜 규례·안식일 규정이 끼어 수치를 삭제하는 편이 옳았다). 그리고 **`context`에 쓴 모든 진술이 그 범위 안 본문으로 뒷받침되는지 저작 시점에 대조하라** — task#264~266에서 이 축의 위반 5건이 발견됐고 기계검증(개수·정렬·비어있지 않음)은 전부 통과한 상태였다. 같은 제약이 [[테마 투어]]의 정차지 해설(note)에도 적용된다(그 사건의 범위 밖 구절·다른 사건을 끌어오지 않는다).

## 탐색 관점 (Navigation Perspective)

BibleMap 데이터를 바라보는 세 가지 중심 관점. 관점에 따라 같은 데이터가 다르게 시각화된다.

**인물 중심 (Person-centric)**: 특정 Person이 참여한 Event와 그 Event가 발생한 Place들로 해당 인물의 활동 반경을 구성한다. Person에 좌표가 없는 이유도 여기서 비롯된다 — Person은 `HAS_PARTICIPANT → Event → OCCURS_AT → Place` 경로를 통해 간접적으로 공간을 갖는다. **지도에 표시되는 장소 수는 Theographic 이벤트와 authored 이벤트를 합산해 집계된다** — 따라서 인물 대상 authored 이벤트를 추가 계획할 때는 먼저 기존 Theographic 이벤트가 연결하는 장소 수를 파악해야 실제 필요한 authored 이벤트 수를 산정할 수 있다.

**장소 중심 (Place-centric)**: 특정 Place에서 발생한 Event와 그 Event에 참여한 Person들을 조회한다. 지도 마커 클릭이 이 관점의 진입점이다.

**시대 중심 (Era/Timeline-centric)**: 특정 시기의 Event 흐름과 그에 연결된 Person·Place를 탐색한다. `Period`(= Event의 `PART_OF` 계층)가 이 관점의 정렬 축이 된다. TimelineView는 사건을 시대순으로 늘어놓고, 각 사건의 "사건의 근거"(성경권 → 구절)를 함께 보여준다.

## 여정 (Journey)

한 인물의 **시간순 사건(Event) 묶음**. 여정은 사건 하나가 아니라 사건들의 시퀀스이며, 계층은 **여정 ⊃ 사건(여러 개) ⊃ 그 사건의 근거 구절**이다 — 근거 구절은 여정에 직접 붙는 것이 아니라 여정을 구성하는 **각 사건에** 붙는다. 각 사건은 발생 장소(Place)를 통해 지도상의 한 정차지로 나타난다(좌표 없는 사건은 정차지 없이 목록에만 표시). "인물 중심 관점"의 핵심 산물로, 큐레이션 인물에 대해 정의된다. UI(JourneyList)는 이 계층을 "{인물}의 여정 · 사건 N개 → 각 사건 펼치면 구절" 아코디언으로 보여준다.

**참여자 불변식**: 여정을 구성하는 모든 사건은 **그 인물이 실제 참여자인 사건**이다 — 같은 시대·같은 무리에게 일어났더라도 그 인물이 본문에 등장하지 않는 사건(예 모세 여정에서의 발람과 발락, 민 22–24)은 그의 여정에 속하지 않는다. 이 불변식이 깨지면 여정 목록과 인물 연표가 갈린다(전자는 여정 전량, 후자는 엄격 참여자 필터). 결과로 **[[테마 투어]]가 참조할 수 있는 사건은 어떤 큐레이션 인물의 여정에 속한 사건뿐**이며, 주인공 없는 시대 사건은 투어 정차지가 될 수 없다.

## 테마 투어 (Themed Tour)

여러 인물의 [[여정-journey]]을 하나의 주제(시대·서사)로 엮은 큐레이션된 시간순 사건 시퀀스. 여정이 *한 인물*의 사건 묶음인 것과 달리, 테마 투어는 한 인물로는 드러나지 않는 관계(예: 사울-다윗 대립, 족장 4세대 언약)를 여러 인물의 사건을 교차해 보여준다. 계층은 여정과 동일하다 — **투어 ⊃ 사건(여러 개) ⊃ 각 사건의 근거 구절**. 각 정차지에는 **정차지 해설(stop note)** — 그 사건이 *이 테마 안에서* 갖는 의미를 서술하는 투어 관점 텍스트 — 이 붙을 수 있으며, 해설은 사건 본문(person_events)이 아니라 투어의 틀에 속한다(ADR-0028). 정차지에는 해설과 함께 [[장면 스케치]]가 붙을 수 있다. 단일 주인공이 없어, 투어를 구성하는 사건들의 참여자가 곧 그 투어의 등장인물이다. 성경 서사 척추(시대)를 따라 큐레이션되며, 각 투어는 기존 여정 사건을 재사용해 엮는다(신규 사건 저작이 아니라 순서·틀 부여). **커버리지 원칙**: 큐레이션이되 선별적 발췌가 아니다 — 투어 시대에 맞는 저작 사건은 원칙적으로 모두 포함하고, 제외는 동일 장면의 인물별 중복 시점(한 시점만 대표로 남김)과 서사에 기여 없는 순수 연대기 기록에 한한다. → [[여정-journey]], [[탐색-관점-navigation-perspective]]

## 장면 스케치 (Scene Sketch)

[[테마 투어]] 재생 중 정차지 해설 카드 상단에 함께 표시되는 **저작 삽화 시퀀스 애니메이션** — 그 사건의 장면이 양피지 위에 단계적으로 그려지고 움직이는 짧은 연출(예: 물매 돌이 날아가 골리앗이 쓰러짐). 인물 이름표·상황설명 한 줄·출처 캡션이 삽화와 한 장으로 읽히며, 어두운 장면은 강조색이 금색에서 목탄색으로 가라앉는다(무드). 정차지 해설(테마 관점 텍스트)과 역할이 다르다 — 해설이 *의미*를 말하면 장면 스케치는 *사건 자체*를 보여준다. 저작 형식·보관은 ADR-0029(투어별 JSX 코드 모듈), 선화 규약은 ADR-0025를 따른다. 스케치 없는 정차지도 성립하지만, **의도적으로 미저작한 정차지에 한한다** — 미저작은 검증기의 허용목록에 명시된 경우에만 성립하고, 목록에 없는 미저작은 결함으로 다룬다(저작을 잊은 정차지는 화면에 아무것도 뜨지 않으면서 오류도 남기지 않기 때문). **"커버됨"은 레지스트리에 키가 있다는 뜻이 아니라 화면에 그려진다는 뜻이다** — 스케치 모듈이 통합 레지스트리에 import·병합되지 않으면 키가 있어도 렌더되지 않고, 증상은 미저작과 완전히 같다(무음·무오류). 따라서 커버리지 판정은 키 집합 대조와 **모듈 병합 여부**를 한 세트로 본다(task#259). → [[테마 투어]]

## 인물 연결 (Person Connections)

큐레이션 인물([[여정-journey]]을 가진 35인) 상세 시트에서 그 인물과 이어지는 **다른 큐레이션 인물**을 보여주는 두 축. 둘 다 **큐레이션 인물로 한정**되어 모든 항목이 여정으로 점프 가능하다 — 장소판 선례("이 곳을 지난 인물" = `/place/{id}/curated-persons`)의 인물판이다. 기존 SidePanel "이웃"의 가족 관계(부모·자녀·형제·배우자 등 직접 그래프 관계)와는 **다른 축**이며, 그것을 대체하지 않고 별도 섹션으로 얹는다.

- **함께 등장한 인물 (Co-participant)**: 같은 `Event`에 `HAS_PARTICIPANT`로 **함께 참여**한 인물. `Person`끼리는 직접 관계가 없고 `Event`를 경유한 2-hop 공동 등장이라(사건 → 참여자) 가족 관계와 의미가 다르다. **성경상 다른 큐레이션 인물과 같은 사건에 등장하는지에 따라 인물마다 편차가 크다** — 함께 등장하는 인물(왕국 다윗·사울·사무엘·솔로몬, 선지자 엘리야·엘리사, 예수·베드로·야곱 등)엔 잡히고, 어떤 큐레이션 인물과도 공동등장이 없는 고립 인물(사사들·요나·에스더·다니엘 등)은 비어 ②동시대만 남는다. 빈 섹션은 숨기며 — 억지로 만들지 않고 **공백이 곧 그 인물의 고립을 뜻해 정확**하다. 공유 사건 수 내림차순.
- **동시대 인물 (Contemporary)**: 같은 큐레이션 **시대(era)** 에 속한 인물(원시사·족장·출애굽·정복·사사·왕국·선지자·포로·신약 8구간, `backend/app/curated.py`의 `CURATED`/`ERA_ORDER`). era는 모든 큐레이션 인물에 부여돼 있고 각 구간에 2인 이상이라 **항상 1명 이상** 나온다 — 함께 등장한 인물이 비는 인물의 유일한 연결 축이 된다. 함께 등장한 인물에 이미 나온 인물은 중복 제거한다.

→ [[여정-journey]], [[탐색-관점-navigation-perspective]]

## 인물 관계 (Person Relations)

한 인물이 다른 인물과 맺는 관계의 **성격(valence)** 과 그 **시간적 변화**를 손큐레이션으로 담아 **전용 화면**으로 보여주는 축. [[인물-연결-person-connections]]이 그래프에서 파생한 *연결의 존재*(누가 누구와 같은 사건에)만 보여주는 것과 달리, 인물 관계는 그 관계가 **긍정·부정·중립 중 무엇이며 시간에 따라 어떻게 변하는지**를 사람이 붙인 라벨로 표현한다 — valence는 사건 참여로 파생 불가라 반드시 큐레이션이다. **네트워크 그래프가 아니다**(GraphView 삭제 결정 유지) — 시간축 기반 레이아웃으로 표현한다.

- **valence (관계 성격)**: `긍정`·`부정`·`중립` 세 값. 그 시점 관계의 지배적 성향.
- **관계 유형 (type)**: valence와 **직교하는 구조적 분류** — 가족·연인·친구·신하·선지자·스승제자·대적·군주·하나님 등(`스승제자` = 랍비-제자·후계 계승, 엘리↔사무엘·엘리야↔엘리사·예수↔제자; `하나님` = 인물↔하나님의 언약·부르심·순종·반역·심판 축으로, 상대 endpoint는 큐레이션 인물이 아닌 `하나님` 이름 라벨이며 valence로 순종·반역·회개의 변화를 국면에 담는다). valence가 시간에 따라 변하는 감정 성향이라면, 유형은 그 인물이 상대와 맺는 **고정된 관계 종류**다(pair 단위 1개). 뷰에서 유형별 아이콘으로 표시하고 유형끼리 모아 정렬한다.
- **국면 (phase)**: 한 관계 = 시간순 국면 배열. 관계는 성경 서사에서 변한다(다윗↔사울: 총애→시기·추격→살려줌). 각 국면은 valence·라벨·**근거 구절**·대략 연도를 가진다. 변하지 않는 관계는 국면이 하나.
- **레인 (lane) / 초점 쌍 (focus pair)**: 표현의 두 층. **레인** = 관계마다 가로 한 줄, 시간축 위 valence 색 띠(교차선 없이 개요). **초점 쌍** = 한 관계를 골랐을 때 두 인물을 마주 세우고 국면을 시간순으로 잇는 상세.
- **근거 구절 레이어 (evidence verse layer)**: 국면을 누르면 그 관계 근거인 성경 구절 **본문**(한/영)을 레이어로 조회. 근거는 두 층 — **앵커 절**(그 국면의 기준이 되는 한 절)과 **문맥 범위**(앵커를 이해하게 하는 같은 장 안의 주변 절들, 앵커 포함). 문맥 범위가 있으면 범위 절들을 앵커 강조와 함께 보여주고, 없으면 앵커 절 하나로 폴백한다. 구절 본문은 빌드타임 getbible 프리베이크(ADR-0003 선례)로 미리 받아 저장.
- **person-centric (한 인물 기준, 비대칭)**: 주체 인물 하나 기준으로 상대들을 담으며 상대는 **큐레이션 인물이 아니어도 된다**(요나단·밧세바·압살롬 등). 상대가 큐레이션이면 그 여정으로 점프 가능, 아니면 이름 라벨로만 남는다.
- **역할 라벨 (role, 원근 비대칭)**: 가족류 관계에서 각 endpoint는 자기 역할 라벨(`role`)을 가지며 — 아담↔아벨은 아담=`아버지`, 아벨=`둘째 아들` — **뷰는 늘 상대 endpoint의 role을 표시**한다. 그래서 아벨 상세엔 아담이 `아버지`로, 아담 상세엔 아벨이 `둘째 아들`로 원근이 맞게 읽힌다(관계는 pair 하나지만 라벨은 양쪽에서 다르다). 상대가 비큐레이션이면 상대를 가리키는 단일 라벨(`note`)로 대신한다. **role이 화면에 뜨려면 관계의 양쪽 endpoint에 `slug`가 있어야 한다** — 백엔드가 `slug`→`theographic_id`로 키를 만들어 조회하기 때문이다(이름 문자열로 키를 만들면 동명이인에게 다른 서사의 role이 유출된다, task#263). slug 없는 가족 관계에 role을 달면 **조용히 표시되지 않는다**.

## 가계도 (Family Tree)

한 인물을 중심으로 **혈통(kinship)** 을 세대별로 세워 보여주는 전용 화면. 데이터는 **그래프 혈통 간선** — 부모↔자식(`PARENT_OF`/`CHILD_OF`), 형제(`SIBLING_OF`), 배우자(`PARTNER_OF`) — 에서 파생하며, theographic 원본의 `father`/`mother`(배열)를 적재하는 것이 원천이다. **혈통 단절의 1차 보충은 가족 폐포 wip 인물의 실레코드 적재**([[publish-레코드]]의 예외, ADR-0021)이고, **원본에 아예 없는 인물만 [[저작-인물-authored-person]] 패턴으로 저작 보충**한다(재저작이 아니라 구멍 메우기). 대표 계보 1건(예수의 족보 — 마태복음 1장)은 이 보충으로 뿌리까지 무단절을 보증한다.

세 이웃 개념과 명확히 구분된다:

- **SidePanel "이웃"의 가족(직계 1-hop)** 과 달리, 가계도는 같은 그래프 간선을 **다세대로 확장**한다 — 위로 조상선을 뿌리까지(단, [[앵커-인물]] 사이 비앵커 구간은 "…N대" **접힌 세그먼트**로 압축, 탭하면 인라인 펼침), 아래로 자손 2세대까지(자식 세대는 [[어머니-그룹]]으로 묶고, 손주는 요약 칩으로 축약), 형제·배우자는 focus 행에 인라인. 노드 탭은 [[인물-미니-카드]]를 열며, **재중심화(ego-centric)** 는 카드 안의 동작이다.
- **[[인물-관계-person-relations]]**(서사 valence·국면)와 달리, 가계도의 **간선**에는 valence·국면·근거구절이 없다 — 구조적 혈통만 담는 결정적 그래프 파생 뷰다. (미니 카드가 보여주는 소개·구절은 관계가 아니라 **인물** 데이터다. person_relations의 "가족" 유형이 방향 role 라벨을 손큐레이션으로 담는 것과 별개 축이다.)
- **삭제된 GraphView(포스-디렉티드 네트워크)** 와 달리, 가계도는 세대가 축을 이루는 **계층 트리**다 — 자유 배치 네트워크가 아니다. 라이브러리 없이 손수 SVG/CSS로 렌더한다.

**앵커 인물 (anchor person)**: 접힌 조상선에서도 항상 노출되는 인물 — 인장 선화(ADR-0025) 보유 인물 + focus의 직계 3세대(부모·조부모). 인장이 곧 "이야기가 있는 인물"이라는 신호로, 앵커 여부와 도상 위계가 일치한다.

**메시아의 실 (messianic thread)**: 아담→예수 계보 경로(마태1+눅3 사슬)에 놓인 간선만 금색으로 강조하는 시각 장치. 접힌 세그먼트가 계보 위면 금 점선. "모든 계보가 예수로 흐른다"는 페이지의 주제의식을 한 줄로 담는다.

**어머니 그룹 (mother group)**: focus 자식 세대의 표시 단위 — 어머니 간선이 있는 자식은 어머니별 컨테이너로 묶고 어머니 이름을 그룹 라벨로 표시, 미상은 무라벨 그룹. 커넥터는 자식 개개인이 아니라 그룹당 1개. 어머니 간선은 성경에 기록된 경우만 저작 보강한다(ADR-0027).

**인물 미니 카드 (person mini card)**: 가계도 노드 탭 시 열리는 바텀시트 요약 — 인장·이름(한/영)·신분 한줄(role)·생몰·시대·소개 일부·언급 구절·부모, 그리고 재중심화/인물 페이지 이동 동작. 인물의 데이터 보유 계층(큐레이션 35 → 소개 보유 → 단역)에 따라 자연 폴백하며, 전원이 최소 신분 한줄은 갖도록 2단 저작으로 커버한다(ADR-0027).

## 구절 레이어 (Verse Layer)

근거 구절 본문(한/영)을 현재 화면 위에 겹쳐 보여주는 오버레이. [[구절 근거 원칙 (verse-grounded principle)]]의 UI 종착점 — 앱 어디서든 📖 근거 칩·사건·국면을 누르면 같은 패턴의 레이어가 뜬다. 개념상 **앱 전체에 하나의 패턴**이며(소개·여정·연표·관계·의존도·단어 분포·상세 시트 등 진입점만 다르다), [[상세-시트-detail-sheet]]와 구분된다 — 상세 시트는 선택 대상의 상세 *화면*이고, 구절 레이어는 그 위에 잠깐 떠서 본문을 읽히고 닫히는 1회성 조회 층이다. 모바일에서는 화면 아래에서 올라오는 시트로, 데스크톱에서는 중앙 카드로 나타난다. [[인물-관계-person-relations]]의 "근거 구절 레이어"는 이 패턴의 관계판 인스턴스다. 양피지(paper) 질감이 이 레이어의 시각 정체성이다 — 구절 본문은 항상 양피지 위에 놓인다.
_Avoid_: "구절 팝업"·"구절 모달"(구현 형태에 묶인 이름 — 모바일에선 모달이 아니라 시트다)

## 인물 소개 (Person Context)

큐레이션 인물의 [[화면-단계-stage]] 소개(intro) 탭에 담기는 **정체성 콘텐츠** — 그 인물이 *누구이고 왜 중요한가*를 한눈에 전한다. 세 요소: **역할(role)** 한 줄 별칭("최초의 사람"), **소개문(intro)** 2–3문장, 그 산문을 뒷받침하는 **근거 구절(verses, 대표+근거 겸함)**. 프로젝트 저작 원칙에 따라 **모든 소개·역할은 성경 구절을 근간으로 하며 근거 구절 없는 진술을 두지 않는다** — [[인물-성품-character-trait]]이 성품마다 근거 구절을 다는 것과 같은 결이다. ## 하나님 상호작용 mode (God-interaction mode)

한 인물의 생애에서 **하나님과의 상호작용 순간** 하나하나를 분류하는 **5종 통제어휘**. `물음-응답`(묻고/기도하고 → 하나님이 응답·이루심), `물음-침묵`(구했으나 → 침묵·거절), `독단-개입`(안 묻고 행했으나 → 하나님이 그래도 붙드심), `독단-어긋남`(안 묻고 행해 → 어그러짐), `부르심`(하나님이 먼저 부르심/명하심/언약하심 — 인물 주도 아님. **명령형**은 인물이 행할 것을 명하거나 따르라 부르심이라 `obeyed` 불리언으로 순종/불순종을 가르고, **언약형**은 창조·언약·택하심/기름부음·예고·신적 선언처럼 인물이 **수령**하는 것이라 `covenant`로 표시해 결과를 '받음'으로 나타냄 — 둘 다 "하나님과 정렬"이라 [[하나님-의존도-god-reliance]] 분자에 든다). [[인물-관계-person-relations]]의 `valence`(관계의 톤: 긍정/중립/부정)와 **다른 축** 이다 — mode는 "누가 주도했고 어떻게 응했나"를 담는다. **`독단`↔`물음` 경계(중요)**: `독단`은 하나님을 배제하거나 거스르는 주제넘은 자기 판단(사울의 자의적 제사·다윗의 인구조사)이고, **믿음의 예배·제사·헌신·의탁은 독단이 아니라 `물음-응답`**(하나님께로 나아감)이다 — 이 경계를 틀리면 아벨(히 11:4)처럼 믿음의 사람이 의존도 0%로 나오는 오류가 난다([[하나님-의존도-god-reliance]] 정의상 물음은 의존, 독단은 반대편). **표시명(중요)**: `물음-응답`은 petition(묻다·기도)만이 아니라 위 경계대로 믿음의 예배·헌신·동행까지 담으므로, UI는 계기 라벨·헤더를 그 상위 개념 **"나아감"**(헤더 `나아감·응답`/`나아감·침묵`, 계기 라벨 `나아감`, kind 뱃지도 petition 어투를 뺀 `그대로 이루심`/`넘치게 이루심`/`그대로는 아니`)으로 표시한다 — **key·데이터·% 는 `물음-응답` 그대로이고 표시만 나아감**이다(에녹처럼 구한 것 없는 인물이 "요청"으로 오표기되지 않게. task 188). 각 항목은 구절 근거를 필수로 가진다([[구절 근거 원칙 (verse-grounded principle)]]). 각 순간은 **계기(trigger)→결과(outcome) 2단**으로 저작되며(각 단 구절 근거 필수, 같은 절이면 UI가 카드 1개로 합침; 명령 위반처럼 인물의 **행동**이 계기·결과와 구분되는 사건은 선택적 중간 단 `response`를 넣어 **3단 계기→행동→결과**로 저작 — 예: 선악과의 부르심→불순종→심판), **물음 계열(`물음-응답`·`물음-침묵`) outcome엔 응답 성격 `kind`** — `이룸`(요청대로)·`더하심`(그 이상)·`다르게`(다른 방식)·`거절`(안 주심)·`침묵`(무응답) — 를 표시축으로 붙인다(**표시 전용, 지표 % 무관**; 부르심/독단은 mode·obeyed에서 UI가 파생). 통제어휘·저작 규칙 정본은 `data/god_reliance/AUTHORING.md`(선례: word_sentiment·character_traits). → [[하나님-의존도-god-reliance]], [[인물-관계-person-relations]]

## 하나님 의존도 (God-reliance)

각 인물이 "얼마나 하나님을 의지했나"를 나타내는 **퍼센트 지표**. 그 인물의 [[하나님 상호작용 mode (God-interaction mode)]] 순간들을 집계해 **(물음-응답 + 물음-침묵 + 순종한 부르심) ÷ (전체 순간) × 100** 으로 계산한다("하나님과 정렬" 정의, ADR-0023). 인물↔인물 상호 관계가 아니라 **인물↔하나님** 한 축의 궤적이며, **구절 근거가 있는 주요 순간들에 대한 큐레이션 해석** 이지 전수 통계가 아니다. **귀속 원칙**: 각 순간은 **그 인물이 직접 당사자인**(하나님이 그를 대면·그가 하나님을 향해 행한) 하나님-상호작용이어야 한다 — 하나님이 **제3자에게** 하신 선언이나 인물 **미출생** 시의 예고는 그의 순간이 아니라 제외한다(예: 창3:15는 뱀에게 하신 원시복음이라 아담에서 제외). **사건 단위 원칙**: 하나의 상호작용 사건은 **하나의 순간**으로만 센다 — 명령·행동·심판·후행 여파는 별도 순간이 아니라 한 순간의 단(step)으로 잇는다(예: 선악과 범죄를 명하심/따먹음/심판대/추방/930세 죽음 5개 순간으로 쪼개면 한 죄가 분모에 5번 계수되는 왜곡). 기록이 희소한 인물(아벨·에녹 등)은 "표본 적음" 뱃지로 신뢰도 한계를 밝힌다. 헤드라인 %(도넛 게이지)·mode 분해 막대·생애 궤적(연도축 mode색 점)·은혜 하이라이트(`독단-개입`)·인물 간 랭킹·성경 평균 대비 백분위로 [[화면-단계-stage]] 탐험 뷰의 전용 내비 탭에 렌더한다. → [[하나님 상호작용 mode (God-interaction mode)]], [[인물-관계-person-relations]]

## 장 묶음 (Chapter Section)

한 권 안의 장들을 이름 붙은 **연속 구간**으로 나눈 대단락. 각 묶음은 짧은 한글 제목과 장 범위(startChapter–endChapter)를 가지며, 한 권의 묶음들은 **연속·전수·비중첩**이다 — 모든 장이 정확히 하나의 묶음에 속하고 1장부터 마지막 장까지 빈틈·겹침이 없다. 장마다 한 줄 요약을 다는 **장 개요**(task#206, 장 단위)와 달리 장 묶음은 **장 위 계층**으로, [[상세 시트 (Detail Sheet)]]의 본문 리더 목차를 평면 목록에서 구조화된 개요로 격상한다(창세기 = 원시 역사 1–11 / 아브라함 12–25 / 이삭·야곱 25–36 / 요셉 37–50 식). 단장권 5권(옵·몬·요이·요삼·유)은 나눌 것이 없어 묶음을 두지 않는다(목차는 평면 폴백). 프레이밍은 보수 스터디 성경의 **문학·서사 개요 구분**을 따르고 문서비평식 자료 구분(자료가설·제2이사야 등)은 쓰지 않는다([[Book]] 보수 연대·ADR-0014와 일관). 추정·저작 독립 데이터라 Neo4j 주입이 아니라 오버레이(`data/chapter_sections/books.json`, bookId 키 — chapter_summaries 선례·ADR-0004)로 서빙한다. → [[Book]], [[구절 근거 원칙 (verse-grounded principle)]]

## 메시아 예언→성취 (Messianic prophecy → fulfillment)

구약의 메시아 예언절과 신약의 성취절을 짝지은 큐레이션 쌍으로, 탄생·사역·수난·부활 등 주제로 묶인다. **직접 인용과 구분**: 앱의 구약↔신약 인용(`data/quotations/quotations.json`)이 신약이 구약을 *문자적으로 인용*한 쌍인 데 반해, 메시아 예언→성취는 인용이 아닌 **주제적 성취**(예: 시22편 손발 찔림 → 십자가)도 포함한다 — 즉 메시아 성격 인용(부분집합)에 비인용 성취를 더한 상위 묶음이다(기존 quotations 항목에 이미 "처녀 잉태 임마누엘 예언" 등이 섞여 있어 태깅으로 도출). 각 쌍은 [[구절 레이어 (Verse Layer)]]로 양쪽 절 본문을 보여준다. → [[구절 레이어 (Verse Layer)]]

## 언약 (Covenant)

하나님이 특정 인물·백성과 맺으신 주요 언약(노아·아브라함·모세·다윗·새 언약 등). 당사자·약속·표징·핵심절·시대를 갖고 [[사건 연대 (startDate)]] 규약으로 연표에 배치돼 구속사 전체를 가로지르는 주제 실이 된다. [[하나님 상호작용 mode (God-interaction mode)]]의 `부르심` 언약형(인물이 수령하는 신적 선언)과 결이 같으나, 언약은 *인물별 순간*이 아니라 **서사 전체를 잇는 독립 축**으로 저작한다. → [[사건 연대 (startDate)]]

## 비유 (Parable)

예수가 가르치신 비유. 위치·구절이 붙은 [[저작 사건 (Authored Event)]]으로 저작해 지도·연표에 색인 레이어로 얹으며, 종류 태그로 [[기적 (Miracle)]]과 구분한다. → [[기적 (Miracle)]], [[저작 사건 (Authored Event)]]

## 기적 (Miracle)

예수 사역 중의 기적. [[비유 (Parable)]]와 동일하게 위치·구절이 붙은 [[저작 사건 (Authored Event)]]으로 저작해 색인 레이어로 얹으며 종류 태그로 비유와 구분한다. → [[비유 (Parable)]]

## 주제 성구 (Topical Verse Collection)

믿음·사랑·용서·기도 등 **주제(topic)**별로 큐레이션한 성구 묶음. 주제 선택 시 [[구절 레이어 (Verse Layer)]] 패턴으로 성구 본문을 렌더한다. **[[테마 (Theme)]]와 다른 개념** — 테마는 명암 팔레트(Night/Day Atlas) 선택 단위이고, 여기의 "주제"는 성경 내용의 화제 분류다(용어 충돌 주의). → [[구절 레이어 (Verse Layer)]]


## 통합 검색 (Unified Search)

이름과 구절 본문을 한 입력창에서 함께 찾는 검색. 결과는 두 부류다 — 그래프 노드(인물·장소·사건)의 **이름 일치**, 그리고 성경 본문의 **문자열 일치**. 구절 결과는 그 절이 있는 장 본문으로 이어지므로, 찾은 절을 문맥 안에서 읽는 흐름이 된다.
_Avoid_: "단어 검색"([[단어 분포]] 화면의 명사 색인과 혼동된다 — 통합 검색은 활용형을 포함한 본문 문자열 일치다)

## 단어 분포 (Word Distribution)

한 권(또는 전체) 안에서 명사가 얼마나 자주 나오는지의 분포. 빌드타임에 형태소 분석으로 뽑은 **명사 색인**이 출처이므로, 조사·활용형을 포함하는 [[통합 검색 (Unified Search)]]과 매칭 방식이 다르다. 같은 낱말을 물어도 두 화면의 결과 수가 다를 수 있고, 그것은 결함이 아니다.

## 북마크 (Bookmark)

사용자가 명시적으로 저장한 화면. 저장 단위는 인물·구절·장·투어 등 [[화면 단계 (Stage)]] 하나이며, 해시 문자열로 표현되어 복원은 딥링크와 같은 경로를 탄다. 이 기기에만 남는다.
_Avoid_: "즐겨찾기"(브라우저 기능과 혼동)

## 이어보기 (Recent)

사용자가 저장하지 않아도 자동으로 기록되는 최근 방문 화면. [[북마크 (Bookmark)]]와 저장 방식·복원 경로는 같지만 **의도의 유무**가 다르다 — 북마크는 "남기겠다"는 선택이고 이어보기는 자취다. 따라서 이어보기는 상한을 두고 오래된 것부터 밀려난다.

## 이어읽기 (Resume Reading)

마지막으로 읽은 책에서 **아직 읽지 않은 가장 앞 장**. [[읽기 진도 (Reading Progress)]]의 읽은 장 집합과 마지막 위치에서 파생되는 한 점이며, 저장되는 값이 아니라 매번 계산되는 값이다.

**그 책을 완독했으면 이어읽기는 없다.** 완독을 판정하려면 그 책의 총 장 수가 필요하므로, 이어읽기를 그리는 화면은 장 수를 **그 화면이 실제로 부르는 응답으로** 함께 받아야 한다. 장 수를 모르는 동안에는 이어읽기를 내보내지 않는다 — 없는 장을 가리키는 버튼을 잠깐 보여주고 고치는 것보다 늦게 나타나는 편이 낫다. 같은 상한 검사가 이미 오염된 저장값(총 장 수를 넘는 장이 들어간 기록)도 함께 걸러낸다.

[[이어보기 (Recent)]]와 한 글자 차이지만 다른 것이다 — 이어보기는 **방문한 화면**의 자취이고, 이어읽기는 **읽지 않은 장**을 가리키는 진도 파생값이다. 두 이름을 섞어 쓰면 화면 문구와 코드가 서로 다른 것을 뜻하게 된다.
_Avoid_: "이어보기"와 혼용 / "다음 장"(완독 시 존재하지 않는다는 성질이 사라진다)

## 읽기 진도 (Reading Progress)

장 단위로 "읽었다"고 표시한 기록과 그로부터 계산되는 책별·전체 진도율.
_Avoid_: "통독 플랜"(날짜별 목표·일정을 뜻한다 — 진도는 사용자가 지나온 자취일 뿐 정해진 일정이 아니다)

## 장소 페이지 (Place Page)

한 장소를 주어로 삼아 그곳의 배경·핵심 구절·거쳐 간 인물·일어난 사건을 모으는 화면. 인물을 따라가다 장소를 만나는 [[여정 (Journey)]]과 **관점이 반대**다. 어떤 사건이 "그곳에서 일어났는지"의 판정 기준은 여정의 정차 판정과 동일해야 한다 — 두 화면이 같은 장소에 대해 다른 개수를 말하면 안 된다.

## 통사 연표 (Canon Timeline)

특정 인물이나 투어에 종속되지 않고 창세기~계시록 전체를 하나의 축에 놓는 연표. [[Period]]의 시대가 축의 눈금이고 그 위에 사건과 인물의 활동 구간이 겹친다.

**축의 좌표는 연도가 아니라 시대다.** 시대끼리는 실제 시간 길이와 무관하게 대등한 지분을 갖고, **연도 비례는 한 시대 안에서만** 성립한다 — 신약 100년이 전체 4098년의 2.4%인데 사건의 33%를 담고 있어, 전역 연도 비례로는 읽을 수 있는 화면이 나오지 않는다. 시대 간 시간 길이는 각 시대의 연도 범위 표기로만 전달한다.
_Avoid_: 그냥 "연표"(기존의 인물 연표·투어 연표와 구별되지 않는다) / "연도 축"(전역 연도 비례를 뜻하는 것으로 오해된다 — 시대 축이다)

# Coding principles

You are a lazy senior developer. Lazy means efficient, not careless. The best code is the code never written.

Before writing any code, stop at the first rung that holds:

1. Does this need to be built at all? (YAGNI)
2. Does the standard library already do this? Use it.
3. Does a native platform feature cover it? Use it.
4. Does an already-installed dependency solve it? Use it.
5. Can this be one line? Make it one line.
6. Only then: write the minimum code that works.

Rules:

- No abstractions that weren't explicitly requested.
- No new dependency if it can be avoided.
- No boilerplate nobody asked for.
- Deletion over addition. Boring over clever. Fewest files possible.
- Question complex requests: "Do you actually need X, or does Y cover it?"
- Pick the edge-case-correct option when two stdlib approaches are the same size.
- Mark intentional simplifications with a `ponytail:` comment naming the ceiling and upgrade path.

Not lazy about: input validation at trust boundaries, error handling that prevents data loss, security, accessibility, anything explicitly requested.
