# 2026-08-01 — nginx gzip 활성화: 초기 진입 자산 1.94 MB → 491 KB (task#260)

## 계획 대비 실제

- **계획대로**: 3슬라이스 전부. `http` 블록에 gzip 6설정 · 재기동 후 4경로 실측 · CONCERNS 성능 §1 해소 · 커밋 `c8c884f`.
  실측 −68.3%(vendor.js) / −85.5%(maplibre.css) / −71.5%(`/api/stats`) / −81.4%(`/api/events`), 집계 −74.6%.
- **갈린 점**
  1. **`docker compose exec nginx nginx -t`가 옛 설정으로 실패했다.** `docker-compose.yml:31`이 `nginx.conf`를 **단일 파일**로
     bind mount하는데, 편집이 inode를 교체하자 컨테이너는 45줄 파일을 **25줄로 잘린 채** 계속 봤다(`unexpected end of file`).
     `restart`로는 안 고쳐지고 `up -d --force-recreate nginx`가 필요했다.
  2. **계획의 "JS/CSS −70% 이상" 기대치가 `vendor.js`에서 물리적으로 달성 불가**였다 — 레벨 5=62,716 B, 레벨 9=61,990 B로
     어떤 레벨로도 31.4% 아래로 안 내려간다. 계획이 실제로 약속한 건 "초기 진입 1.55 MB → 약 406 KB"라는 **집계** 수치였고 그건 충족.
  3. `gzip_types`에 `application/geo+json`을 추가했다(계획 목록에 없음) — 지도 오버레이가 이 MIME으로 나가는데
     `application/json`만으로는 안 걸린다.
  4. `rolldown-runtime-*.js`(567 B) 비압축은 `gzip_min_length 1024` 미만이라 정상 — 계획이 미리 명시한 오판 방지 항목 그대로.

## 학습

- **다음에 다르게 할 것**
  - **`nginx.conf`를 고쳤는데 반영이 안 되면 컨테이너가 보는 내용을 먼저 확인하라** — `docker compose exec nginx wc -l /etc/nginx/nginx.conf`.
    단일 파일 bind mount는 호스트 파일이 inode 교체로 저장되면 컨테이너가 옛 내용에 고착된다. **`restart`가 아니라 `--force-recreate`.**
    (디렉터리 마운트에는 없는 함정 — 파일 단위 마운트에만 생긴다.)
  - **prod를 건드리기 전 설정 검증은 일회용 컨테이너로**:
    `docker run --rm --network biblemap_default -v "$PWD/nginx/nginx.conf:/etc/nginx/nginx.conf:ro" nginx:alpine nginx -t`.
    같은 네트워크에 붙여야 `proxy_pass http://api:8000/`의 이름 해석이 통과한다.
  - **압축률 목표는 자산별이 아니라 집계로 잡아라.** 라이브러리 번들은 이미 minify돼 있어 자산별 −70%가 불가능한 경우가 있다.
    계획 단계에서 목표 수치를 쓸 때 `gzip -5`/`-9` 한 줄로 상한을 먼저 재고 쓰는 편이 낫다(그러면 달성 불가능한 완료 기준을 안 만든다).
  - **압축 레벨은 5로 충분하다** — 사전압축이 없어 요청마다 재압축하는 구성에서 9는 0.4%를 더 줄이자고 CPU를 더 쓴다.
