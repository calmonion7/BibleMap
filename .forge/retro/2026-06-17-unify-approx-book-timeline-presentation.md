## Learnings
- Do differently next time:
  - **프론트 로컬 검증 게이트**: :8080 nginx는 빌드된 `frontend/dist`를 마운트해 서빙(HMR 아님). 소스 변경을 :8080에서 확인하려면 `cd frontend && npm run build` 필요. 빌드는 `.env.production`의 `VITE_API_URL=/api`를 자동 적용해 nginx `/api` 프록시로 실 API에 붙는다(API는 호스트 :8000 미노출). → 백엔드의 `docker compose up -d --build api` 규칙과 대칭인 프론트 규칙. 다음 프론트 작업도 이 순서로 검증할 것.
  - **단일 파일 프론트 표현 작업은 fg-run에서 워크플로우 생략하고 직접 실행**이 더 싸고 빠름 — 같은 파일을 여러 에이전트가 편집하면 충돌. 워크플로우는 다중 파일·병렬 가능 슬라이스일 때만.
  - **툴팁만으로는 "정직성" 부족** — hover/터치 환경에서 안 보임. 권위/배경 구분 같은 정직성 목표는 한눈에 보이는 가시 라벨(여기선 `배경`)로 보강해야 함. 이 앱의 다른 툴팁 기반 표기에도 적용 가능한 교훈.
  - ⚡=배경 vs 📖=근거 구분은 **색(주황/보라)+아이콘(⚡/📖)+라벨(배경)** 3중으로 충분히 분리됨. 칩 모양(pill)까지 바꿀 필요는 없었다 — 과한 스타일 변경 자제가 옳았음.
