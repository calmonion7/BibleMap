## Plan vs actual
- 계획대로 된 것: S1(재배열 + 전 섹션 펼침 시드)·S2(핵심 인물 조건부 숨김) 전부 — 모바일 우선 6 assert + 데스크톱 회귀 3 assert 통과, 스크린샷 3종 사용자 전달(계획 DoD의 "모바일 확인 가능" 요건 충족).
- Divergences (경미, 제품 수정 없음):
  - **검증 스크립트 1차 실패 — CSSOM 정규화.** 시트 탐지에서 인라인 `transform: 'translateY(0)'`을 문자열 그대로 비교했으나 CSSOM은 `translateY(0px)`로 단위를 붙여 반환. 두 형태 허용으로 수정.

## Learnings
- Do differently next time:
  - **인라인 스타일 문자열을 테스트 assert 키로 쓰지 마라.** CSSOM은 저작값을 정규화(단위 부여 등)해 반환한다 — 상태 판별은 스타일 문자열 비교 대신 rect 위치(예: 시트 top < viewport height) 같은 기하 측정이 안전하다.
  - **"정보가 많다"는 불만은 분량·보유율 실측으로 구조화하라.** 필드 길이 조사(중심 메시지 40자 vs 배경 198자)가 재배열 순서를, 보유율 조사(topPersons 32/66권)가 "무조건 제거" 대신 "조건부 숨김"을 결정했다 — 109 회고의 "실측 워크스루 + 데이터 교차확인" 패턴의 재확인이자 확장(화면 걷기 + 데이터 분포 조사).
  - **접힘 기본값은 '전부 펼침'이 단순하다.** 부분 펼침 시드는 노드 왕복 리셋(109 회고)과 상호작용해 상태 혼란을 만든다 — 상세 패널처럼 전용 스크롤 영역에선 전부 펼치고 접기를 예외로 두는 쪽이 탭 수·일관성 모두 낫다.
- Divergences 요약: 계획 적중, 이탈은 검증 스크립트 셀렉터 1건.
