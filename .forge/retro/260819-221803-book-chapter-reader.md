# 2026-07-17 — 본문 리더: 성경책 장 단위 통독 화면 (task#205, 일괄 승급 2026-08-19)

## 계획 대비 실제
- 계획대로 된 것: `GET /book/{id}/chapter/{n}` 3층 캐시, reader 스테이지(`#/read/<id>[/<n>]`) 신설, `ChapterReader.jsx`. 24체크 통과.
- 이탈: 그리드 헤더에 책 이름이 안 나옴 → 현장 수정 1건.

## 배움
- 다음에 다르게 할 것:
  - **API 응답의 필드 위치를 가정하지 말고 먼저 실물을 확인한다.** `/node/{id}`에서 `nameKo`는 **최상위**, `chapterCount`는 `properties` 안이다. `node.properties?.nameKo`로 짚어 이름이 통째로 비었다. 같은 계열 실수가 반복 기록돼 있다 — `traits`(top-level인 줄 알았으나 `properties.traits`, task#118), `stops`, relations 스키마 오가정으로 기계검증이 1차 대량 FAIL(task#150). **검증 스크립트를 쓰기 전에 응답 한 건을 실제로 덤프**하는 30초가 매번 이겼다.
  - **자동 체크는 "있는지"만 보고 "맞는지"는 못 본다.** 이 결함은 자동 체크를 통과했다 — 스크립트가 "전 50장" 텍스트만 확인했기 때문이다. 잡아낸 것은 **스크린샷 육안 대조**였다. 텍스트 존재 단언만으로 구성된 UI 체크는 빈 값·잘못된 값을 통과시킨다. 화면 작업의 검증에는 육안 대조 한 컷이 반드시 들어가야 한다.
- 확인된 것(유지): 장 이동 히스토리를 push로 두는 규칙(가계도 재중심화·단어 분포 책 교체와 동일한 isForward 규칙)에 합류시키면 뒤로가기가 읽던 장을 역순으로 되짚는다.
