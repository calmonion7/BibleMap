# 2026-06-27 — 인물 우선 2단계 셸·인물 허브 (Part 1/3)

## 계획 vs 실제
- 계획대로 된 것: 6슬라이스 전부. 인물 허브(시대별 13인 카드)·2단계 라우팅(hub/explore/overview)·범용 검색 제거(useSearch.js 삭제)·개요 허브 보조·타임라인 탐험 토글·백엔드 `/persons/curated`. 빌드/lint clean, Playwright 18/18.
- 발산: 워크플로가 못 잡은 **실결함 2건을 메인 세션이 사후 수정**. 목표·구조 이탈은 없으나(계획대로 다 만듦) 검증의 사각이 드러남 → 재그릴링 불요, 회고로 충분.

## 배운 것 (다음에 다르게 할 것)
- **워크플로 검증이 컨테이너를 안 띄우면 런타임 버그를 통과시킨다.** `/persons/curated`가 데이터 경로 오산정으로 컨테이너에서 HTTP 500이었는데, 워크플로 검증 에이전트는 AST 파싱·`npm run build`만 해서 "PASS"로 보고했다. **백엔드를 신규/변경하는 슬라이스의 검증에는 `docker compose up -d --build api` + 실엔드포인트 curl을 반드시 포함**시키거나, 최소한 메인 세션 UAT에서 모든 신규 엔드포인트를 실제 호출할 것. (search-ux 회고의 "백엔드는 hot-reload 아님, api 재빌드 필요"가 이번엔 워크플로 에이전트 단계에서 누락 — 워크플로 프롬프트의 검증 슬라이스에 이 단계를 명시 주입해야 재발 방지.)
- **신규 백엔드 라우트의 데이터 파일 경로는 `overlays._resolve`를 재사용하라.** 레포 레이아웃 기준 상대경로(`os.path.dirname(__file__)` + `../../../data`)는 컨테이너(backend=`/app`, 데이터=`/app/data`)에서 깨진다. overlays.py에 이미 `DATA_DIR(기본 /app/data) → 레포 폴백` 해석기가 있으니 새 라우트도 그걸 쓸 것(컨테이너·로컬·테스트 모두 견고).
- **DoD 항목을 "후속 파트로" 미루는 위임 에이전트를 메인 세션이 잡아야 한다.** 통합 에이전트가 개요 단계 SidePanel 부재를 "Part 3에서"로 이월했으나 그건 Part 1 DoD("개요 동작 유지")였다. 슬라이스 완료기준에 안 맞는 이월은 in-run에서 교정(SidePanel을 explore 전용→app-level 공통으로 승격해 해결).
- 데이터 규약 메모: `person_events/<slug>.json`은 모든 사건의 첫 `participants`가 그 인물(주인공)이라 `events[0].participants[0]`로 인물 id를 안전히 도출할 수 있다(13인 전부 names_ko 역검증 통과). 향후 인물 단위 집계에 재사용 가능.
