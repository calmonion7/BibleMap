## 계획 대비 실제
- 계획대로 된 것: 일회용 스택(prod 무접촉·흔적 0), 드라이버 바꿔치기로 앱·스크립트 코드 무수정 대조, 호출 지점 94곳 파일:줄 귀속(정적 목록과 1:1), 판정 규칙과 DoD 1~7 전부 실측 통과. 판정은 막힘 4 · 기계적 치환 7 · 순서만 다름 21 · 통과 62 · 미실행 0.
- 계획과 달랐던 것:
  - **사전 정적 스캔이 「`CALL {}` 0곳」으로 틀렸다.** `CALL {` 문자열 grep이 Neo4j 5.23+의 범위 지정 형태 `CALL (r, k) {`를 놓쳤고, 그 구문이 막힘 4건 중 하나였다(apply_event_dedupe.py:45). 반대로 위험 후보였던 `EXISTS { … }`와 가변길이 경로 자체는 AGE 1.6에서 그대로 통과했다. 정적 스캔은 실행보다 앞서 위험 지도를 그리는 용도였을 뿐 판정 근거가 될 수 없다는 계획의 전제(판정은 실행으로)가 맞았다.
  - **막힌 구문에서 스크립트가 멈추면 판정 전체가 오염된다.** dedupe가 막혀 사건 81개가 안 지워지자 뒤 스크립트의 결과 불일치가 연쇄로 생겼다(713 vs 794). 그래서 재작성안을 「문구」에서 「대신 실행 + neo4j 대조」로 올렸다. 이 덕에 막힘 4건의 재작성안이 모두 실행 증거를 갖게 됐다.
  - **AGE 서버 프로세스 크래시가 판정을 28건으로 부풀렸다.** 계보 재작성 첫 형태(`WITH p, j, a … sum(…)` — 묶음 키에 시작 노드까지)가 메모리 ~6GB 후 signal 9로 죽었다. 같은 psycopg 연결을 쓰던 뒤 호출이 전부 「connection is closed」로 떨어져 가짜 막힘이 됐다. 묶음 키를 `p, a`로 줄이면 400MB·20초로 정답(107명)이 나왔다.
  - 데이터상 영원히 안 불리는 지점(load_authored_genealogy.py:38, `authored: true` 항목이 있을 때만)이 있어, 실제 경로만으로는 판정이 구조적으로 「미판정」에 갇혔다. 그래서 정적 추출 탐침(AST로 쿼리 리터럴 추출 → 양쪽 실행 → 롤백)을 붙였다.
  - 적재 순서는 계획에 없던 결정이었다. `load_books`는 그래프가 아니라 GitHub 원본으로 구절 교집합을 내므로 원본 바로 뒤에 둔다. 그래야 저작 로더의 CONTAINS_BOOK MERGE가 실제로 실행된다(0개 → 338·13개).

## 배운 것
- 다음엔 이렇게:
  - **Cypher 방언 위험을 정적으로 미리 셀 때는 키워드 뒤 형태를 열어 둔다** — `CALL\s*[({]`, `EXISTS\s*[({]`처럼 괄호 종류를 둘 다 잡는다. 그리고 결과를 「0곳」처럼 단정하지 말고 「후보」로만 적는다.
  - **엔진 대조 하네스는 처음부터 「크래시 격리」를 넣는다.** 쿼리 하나가 DB 백엔드를 죽이면 같은 연결의 뒤 호출이 전부 오염된다. 연결이 닫혔으면 재연결하고, 그 호출만 오류로 기록한다. 막힘 수가 갑자기 크게 뛰면 그 수보다 먼저 「같은 오류 문구가 연쇄됐는가」를 본다.
  - **AGE에서 가변길이 경로를 UNWIND→집계할 때 묶음 키는 최소로.** 시작 노드까지 묶으면 OOM이 난다(실측 6GB, 7.7GB 도커 VM). 맞는 형태도 예수 기준 20초다. 이전을 하면 계보는 앱 쪽 계산이나 사전 계산 테이블이 현실적이다.
  - **AGE의 agtype 문자열 정렬은 neo4j와 다르다**(관찰상 길이 우선). 문자열 `ORDER BY`가 있는 쿼리는 이전 시 `cypher()` 밖 SQL에서 `::text COLLATE "C"`로 정렬해야 neo4j와 같은 순서가 나온다.
  - **「순서만 다름」은 그대로 믿지 말고 ORDER BY가 있는 행만 따로 본다.** 이번엔 두 곳 모두 같은 sortKey 동률이었다. 하지만 깊이 정렬 비교는 `ORDER BY … collect()` 리스트 순서 차이까지 가리므로 그런 쿼리는 별도로 확인한다(events.py:60은 양쪽 0/713 위반).
  - **앱의 비결정 절단은 엔진 차이로 오인되기 쉽다.** ORDER BY 없는 결과를 상한에서 자르는 엔드포인트(노드 이웃 50·유형별 30)는 어느 엔진이든 고르는 원소가 달라진다. 총수·길이·나머지 필드가 같은지로 구분한다.
  - 하네스 실행은 `docker` + homebrew python이고, macOS엔 `timeout`이 없다. 디버깅은 `AGECHECK_KEEP=1`로 스택을 남기고 한다.
  - 슬라이스가 전부 직렬이고 Docker 디버깅 반복이 핵심인 작업은 워크플로우보다 메인 세션 직접 실행이 맞았다(병렬 이득 0, 반복 진단에 맥락 유지가 필요).
