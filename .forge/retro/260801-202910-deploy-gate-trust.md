# 2026-08-01 — 배포 검증 게이트를 fail-closed로: 엄격 모드 · 주입 선행 · 장면 커버리지 검증기 (task#259)

## 계획 대비 실제

- **계획대로**: 5슬라이스 전부. `validate_scene_coverage.py` 신설(275↔275) · `check.sh` 13종 등록 + `CHECK_STRICT` ·
  `deploy.sh` 재배치(`.env`<대기<주입<`npm install`<게이트<빌드<이미지<기동) · 문서 정합 · 단일 커밋 `a2ae543`.
- **갈린 점**
  1. 계획 S2의 완료 기준은 "`frontend/node_modules`를 임시 rename → 확인 후 원복"이었으나, **심볼릭 링크 샌드박스**로 대체했다.
     중단되면 트리가 깨진 채 남는 방식을 피하려는 것. 결과는 동일했고(미설정 `⊘`+exit 0 / 엄격 `✗`+exit 1) 레포는 무변경.
  2. 주입 호출에 `| tee -a "$LOG"`를 붙였다가 **철회**했다 — 파이프라인 종료코드가 `tee`의 것이 되어 `set -e`가 주입 실패를
     통과시킨다. 이번 작업의 목적(fail-closed)을 정확히 뒤집는 회귀였다.
  3. 계획에 없던 `stale` 단언 추가(허용목록에 이제 저작된 항목이 남는 경우) — 형제 검증기의 `removed` 검사와 동형.
  4. 연대 검증(Neo4j) 분기에는 음성 대조군을 못 걸었다 — 소켓 확인이 `127.0.0.1:7687` 하드코딩이라 환경변수로 도달 불가를 못 만든다.
  5. 워크플로 없이 직접 실행 — S1~S5가 전부 `depends:` 직렬이라 병렬 이득 0이고 승인 턴만 늘어난다.

## 학습

- **다음에 다르게 할 것**
  - **"게이트를 엄격하게 만들었다"는 통과 실행으로 증명되지 않는다.** 개발 머신은 Neo4j·`node_modules`가 다 갖춰져 있어
    무변경 상태에서도 `CHECK_STRICT=1`이 통과한다. **엄격 모드류 변경엔 음성 대조군을 완료 기준에 함께 박아라** —
    "스킵 조건을 인위적으로 만들면 실패하는가"까지가 한 세트다.
  - **음성 대조군은 레포를 건드리지 말고 심볼릭 링크 샌드박스로.** 최상위 항목을 링크하되 빼고 싶은 것(`node_modules`)만
    누락시키고, 주입이 필요한 디렉터리(`data/tours`·`src/sketches`)만 실디렉터리로 만들어 그 안에 가짜 파일을 넣는다.
    검증기가 `__file__` 기준 상대경로를 쓰면(`os.path.abspath`는 심볼릭 링크를 풀지 않는다) 샌드박스 루트가 그대로 잡힌다.
    중단돼도 원복할 것이 없다.
  - **`cmd | tee` 는 `set -e` 를 무력화한다.** 로그를 남기려고 파이프를 걸면 실패가 조용히 통과한다.
    로깅이 꼭 필요하면 `PIPESTATUS[0]`를 검사하고(게이트 호출부가 그렇게 한다), 아니면 파이프를 걸지 마라.
  - **커버리지 검증기는 "키가 있는가"가 아니라 "렌더되는가"를 물어야 한다.** 스케치 모듈을 만들고 `tourSketches.jsx`
    병합에 추가하는 걸 잊으면 파일엔 키가 있어 통과하지만 앱은 아무것도 그리지 않는다. 집합 대조에 **병합 여부 검사**를 함께 넣었다.
  - 순서 버그는 순서만 고치지 말고 **게이트 안에 보증을 내려라** — 누군가 다시 재배치해도 같은 무음 통과가 재발하지 않게.
