# 2026-10-15 — 인물 얼굴 유지 A/B 파일럿(task 346): 얼굴은 B(klein 참조)가 다섯 문항 모두 이겼지만 연필 화풍을 둘 다 잃어 「둘 다 아님」

## 계획 대비 실제
- 계획대로 된 것:
  - 2×2 비교가 판정 가능한 형태로 끝까지 갔다. 정본 재작성 → 자·판정자 → A(LoRA)·B(klein) → 16장 → 사람 판정.
  - **A는 32GB에서 됐다.** mflux 0.22 Z-Image-Turbo + 어댑터 q8 · rank 16 · 300스텝으로 인물당 약 2시간, 피크 30.7GB, swap 0. 다만 여유가 1GB 남짓이라 다른 프로세스와 같이 돌리면 터진다. diffusers GGUF Q8에 `load_lora_weights`로 mflux 형식 LoRA가 그대로 올라간다.
  - **B는 첫 시도에 됐다.** klein 4B `mflux-generate-flux2-edit --image-paths A B`(q8, 4스텝): 768² 기준 36.6초, 피크 21.3GB.
  - 얼굴 문항에서는 기계 수치와 사람 판정이 같은 쪽(B)을 가리켰다. 마진 0.220 대 0.091, VLM 같은 사람 11/12 대 3/12, 사람 판정 5문항 모두 B.
  - fg-loop 계약(C1~C8) 통과 후 사람 판정에서 멈추는 종착이 의도대로 작동했다. 수리 0회.
- 갈린 것:
  - **결정적 실패 축(③ 연필 화풍)을 어떤 기계 자도 재지 않았다.** 루프 검사와 S2 자는 모두 얼굴만 봤다. 사람의 최종 「둘 다 아님」은 화풍에서 갈렸다. B-e는 색이 바래고 길갈 s23에 이음선이 생겼다. A는 인페인트한 얼굴만 질감이 다르다. 레포에 `judge_style.py`가 있는데 쓰지 않았다.
  - **S2 자는 임계를 지켰지만 측정 방식은 사후에 바꿨다.** 원시 코사인 → 다른 인물 대비 마진으로 바꿨고, 32px 크기를 빼고, 열화 상한 128px을 더하고, 한 장 기준을 풀 평균으로 바꿨다. 다윗 r −0.499는 임계 0.5의 경계 통과다. 검증 에이전트가 이 점을 의심 항목으로 올렸다.
  - **판정자 교정의 「다른 인물」이 쉬운 대조군이었다.** 기각 대상이 화풍이 다른 옛 SDXL 정본 6명이라 12/12는 화풍 차이 덕일 수 있다. 같은 화풍 쌍(사울↔다윗)은 2/2였다.
  - **VLM으로 머리 좌표를 읽는 방식은 단독 인물 그림에서만 됐다.** 장면 그림에서는 100~200px 어긋나 OWLv2(Apache-2.0, CPU)로 바꿨다.
  - **출발 방식(e/f) 결정은 근거가 약했다.** 0.168 대 0.144였다. 엔게디 시드 42·23이 345에서 뜻 탈락한 후보였고, A-f는 새로 생성하지 않고 345 cand/를 재사용해 B-f와 출발 장면이 달랐다. A 인페인트 설정도 한 가지만 써서, A가 진 이유가 설정 탓인지 방식 탓인지 가를 수 없다.
  - LoRA 시트 12장에 전신 구도가 0장이다. 작은 얼굴은 CLIP 상위 20에 못 들었다.
  - **첫 판정 페이지는 쓸 수 없었다.** 그림 20장과 체크박스 12개를 한꺼번에 늘어놓자 사용자가 「뭘 판정해야할지 모르겠음」이라고 했다. 폰 2열 썸네일에서는 얼굴이 너무 작았다. **질문 하나씩**(무엇을 볼지 + 기준 그림 + A/B 테두리 구분 + 고정 답 단추) + **얼굴 크롭** 페이지로 바꾸자 한 번에 끝까지 판정했다.
  - 환경: PATH의 `claude`가 깨진 fnm 스텁이라 `claude -p`가 실패했다(versions/2.1.143 심볼릭 링크로 우회). 셸 `grep`은 셸 함수로 가려져 출력이 없다. hf-xet 다운로드가 멈춰 `HF_HUB_DISABLE_XET=1`로 다시 받았다(모델 다운로드만 약 2시간).
  - 주 세션이 `running.md`를 실행을 띄운 **뒤에** 썼다(규칙은 띄우기 전).
  - 프롬프트 'bare head'·'graying temples'를 넣으면 16장 모두 정수리가 벗겨졌다.

## 배움
- 다음엔 다르게:
  - **비교 실험의 기계 자에는 사람이 판정할 모든 축을 넣는다.** 특히 화풍(③)을 넣는다. 얼굴만 재면 「얼굴 이김 → 채택」처럼 보이다가 사람 판정에서 화풍으로 뒤집힌다. 다음 과제(B + 화풍 회복)는 `judge_style.py`(또는 345 승인본 대비 질감 거리)를 비교 수치와 루프 검사에 처음부터 넣는다.
  - **임계만이 아니라 측정 방식도 실행 전에 고정한다.** 크기 목록·열화 방식·집계 단위를 params.py에 먼저 박는다. 바꿔야 하면 바꾼 이유와 전후 값을 남기고, 루프 검사에서는 「사후 변경 있음」을 실패에 준해 다룬다.
  - **판정자 교정의 음성 표본은 같은 엔진·같은 화풍으로 만든다.** 화풍이 다른 음성은 판정자의 얼굴 구별 능력을 증명하지 못한다.
  - **장면 속 머리 위치는 처음부터 OWLv2로 찾는다.** VLM 좌표 읽기는 단독 초상에만 쓴다.
  - **사람 판정 페이지는 처음부터 질문 하나씩 + 얼굴 크롭으로 만든다.** 한 화면에 한 질문을 두고, 무엇을 볼지 한 줄, 기준 그림, A/B 색 테두리, 고정 답 단추(A가 낫다 / B가 낫다 / 비슷하다 / 둘 다 안 된다), 마지막에 판정 문장 복사를 넣는다. 폰에서 보이게 claude.ai 비공개 Artifact로 올린다. 장면 속 얼굴은 metrics의 머리 상자로 잘라 보여 준다.
  - **A/B 비교는 출발 장면을 같게 맞춘다.** f 갈래도 두 방식이 같은 시드의 같은 새 장면에서 출발하게 하고, 뜻 탈락 시드는 쓰지 않는다. 한 방식에 설정을 한 가지만 쓰면 「방식이 졌다」고 말할 수 없으니 설정 2~3개로 짧게 훑는다.
  - HF 큰 모델 다운로드는 처음부터 `HF_HUB_DISABLE_XET=1`로 받는다.
  - 다음 과제 전에 환경을 고친다: `claude` fnm 스텁 재설치(또는 PATH 정리), 셸 `grep` 함수 제거.
