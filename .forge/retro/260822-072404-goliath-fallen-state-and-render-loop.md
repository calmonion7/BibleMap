# 2026-08-21 — 골리앗 쓰러진 상태 결함 (task#299) — 검증 창이 제품 수명보다 짧았다

## Plan vs actual

- **What went as planned**: 회전 축·각도 수정((103,54)/-80° → (103,44)/-50°), `reduce` 정적값 동기,
  검증 구멍 봉합, 시각 피드백 도구 신설.
- **Divergences**:
  1. **"그림이 이상함"을 미학 불만으로 읽을 뻔했다.** 애니메이션을 끝까지 돌려 렌더하니 쓰러진 뒤
     몸·창·방패가 지면선을 뚫고 프레임을 벗어나 판독 불가한 뭉치가 되어 있었다. 회전 중심보다
     왼쪽 부위는 반시계 회전 시 아래로 내려간다(방패 y 37 → 63.4, 지면 54 · 프레임 바닥 64).
  2. **놓친 이유**: 필름스트립이 드로인 구간(0~5,480ms)만 5등분해 찍었고 쓰러짐은 7.25초다.
     **그 상태를 한 번도 렌더한 적이 없었다.** 사용자는 실물에서 매번 봤다.
  3. **`reduce` 모드는 깨진 자세를 영구히 보여주고 있었다** — 모션 감소 사용자에게는 그것이 정적
     최종 상태다. 회전값을 바꿀 때 이 사본도 함께 맞춰야 한다.
  4. **계획 밖에서 `scripts/render_scene.py`를 신설했다** — 저작 에이전트가 자기 그림을 못 보는 것이
     반복 실패의 구조적 원인이라고 판단해서다. 도구를 준 첫 라운드에서 에이전트가 렌더를 2회 보고
     최적 각도를 좌표 계산으로 도출했고(-50.5°에서 최대 돌출 53.83 < 지면 54), 처음으로 미학 지적 없이 끝났다.

## Learnings

- **Do differently next time**:
  - **검증 창이 제품 수명보다 짧으면 그 뒤는 무검증 지대다.** 연출이 있는 산출물은 "연출 뒤" 상태도
    반드시 촬영 대상에 넣는다. UAT에 상설했다(`*-after.png`).
  - **모션 감소 모드의 정적 사본은 애니메이션과 함께 바꾼다.** 그쪽이 오히려 결함을 영구히 노출한다.
  - **"이상하다"는 취향 신호가 아닐 수 있다.** 먼저 제품을 전 구간 렌더해 파손 여부를 확인하고,
    파손이 없을 때만 미학 문제로 다룬다.
  - **도구의 기본값이 무엇을 뜻하는지 지시에 명시한다** — `--at` 기본값이 "모든 연출 종료 후"인데
    "서 있는 상태를 보라"고 시켜, 한 작업자가 서 있는 골리앗을 한 번도 못 봤다.
