# 2026-09-04 — 다윗 투어 36장면 (1/7): 생성기·판정기를 장면 명세로 일반화, 삼상17 v42 = v41 픽셀 동일 (task 330)

## 계획 대비 실제
- 계획대로: 명세 JSON(S1) · 파생기 + 토큰 가드(S2) · `--scene` 생성기(S3) · §0/PROMPTING 갱신(S5). 회귀는 최종본만이 아니라
  중간본 7장·판 원본 3장까지 전부 `getbbox() → None` — 어느 단계에서 갈렸는지 귀속할 준비까지 됐는데 쓸 일이 없었다.
- 어긋남 ① 판정자 구역 사본이 생성기와 이미 어긋나 있었다(`shieldman` y0 .52 vs .41, task 329가 한쪽만 고침). 「좌표를 복제하고
  --check로 대조한다」던 주석의 가드는 존재하지 않았다. → 축 이름만 파생하려던 계획을 넘어 판정자도 명세를 읽게 함. 판정 인물은
  `judge.figures`로 명시(ADR `260904-070504`). v41 판정 수치 무변화(S4 상자는 최악 이음매가 아니었다).
- 어긋남 ② 블록 교체 편집(줄 범위 슬라이스)이 `FEATHER` 2줄과 `region_mask` 본문을 함께 지웠다. 문법은 통과했고 GPU 실행에서
  `NameError`로 즉시 실패 — 15분 재실행.
- 어긋남 ③ DoD 4 기준선이 계획 45건 vs 착수 12건. `grep -c`는 줄 수이고 계획은 발생 수를 셌던 듯 — 목표 0은 같아 무해했으나
  계획의 「사전 상태」 명령과 값은 같은 명령으로 재야 대조가 된다.

## 배운 것
- 다음엔 다르게: **줄 번호 슬라이스로 블록을 옮기지 말고 앵커 문자열로 자른다**; 큰 편집 뒤에는 GPU를 돌리기 전에 정적
  미정의-이름 검사(ast 훑기 — pyflakes가 venv에 없다)를 먼저 건다. 15분 실행이 1초 검사로 막힌다.
- 두 파일에 같은 상수가 있으면 「같은 값이어야 한다」는 주석은 가드가 아니다 — 실제로 어긋나 있었고 아무도 몰랐다. 공유 지점(데이터 파일)을
  만들거나 한쪽이 다른 쪽을 import해야 한다. GPU 의존 때문에 import가 안 되면 데이터 파일이 답이다.
- 회귀 가드가 있으면 계획 밖 정리를 안전하게 할 수 있었다(판정자 구역·`kind`·`from` 필드) — 픽셀 동일이 「비목표 위반 없음」의 증명이 됐다.
- 생성기의 진행 출력 절 표기가 float(`17.40` → `17:4`)로 잘려 있었다 — 데이터화가 부수적으로 고쳤다. 식별자를 숫자로 들고 있지 말 것.
- 2/7에 넘기는 것: 인물 정본 읽기 인터페이스는 지금 `{costume:<cast>}` 자리표시자 하나(→ `derive_prompts.SAMPLE_COSTUME`)다.
  CONTEXT 「인물 정본」이 말하는 `scripts/canon/cast/<id>.json`으로 옮길 때 파생기의 `_fill`이 그 파일을 읽게 바꾸면 된다.
- 3/7에 넘기는 것: `scenes/`에 명세가 둘 이상이면 `judge_scene.py`도 `--scene` 필수가 된다(하나면 생략 가능). 판 부정어는 80~82/77로
  `_fit_neg`가 공용 뒤쪽을 빼는 상태 — 단계 부정어가 길어지는 장면은 여기서 먼저 막힌다.
