# 2026-07-11 — 인물 성품 분류 규칙 제정 + 47인 전면 재구성

## Plan vs actual

- 계획대로 된 것: 규칙 정본화 → 전면 재구성(처분 맵) → 기계검증 → 프리베이크·주입 → 스팟 검증·배포, 슬라이스 4/4. 단일 파일 순차 저작(관계 시리즈 선례)이 이번에도 유효.
- 이탈: ① 개수 규칙 3~5 → 2~5 완화(기록이 극히 적은 셋·아벨·에녹 — 규칙이 억지 항목을 만들게 두지 않음), ② 처분 맵 1건 누락(삼손 '헌신된 출생')을 전수 대조 assert가 즉시 차단, ③ 결함 신규 부여는 성경에 분명한 인물(야곱 기만·아담 불순종)만 보수 적용.

## Learnings

- Do differently next time:
  - **자유 라벨 저작은 발산한다(180개에 104종) — 분류형 큐레이션 데이터는 처음부터 통제 어휘 + 기계검증(validate_*.py)이 정본.** 관계 시리즈의 "대량 제안 = 기계검증" 교훈이 분류 축에도 그대로 적용됨. 새 큐레이션 축을 열 때 AUTHORING.md(정의·배제·어휘)와 검증 스크립트를 세트로 먼저 만들 것.
  - **대량 데이터 변환은 "원본 전수 대조 assert" 패턴** — 처분 맵이 원본 라벨 집합과 정확히 일치해야 통과하게 하면 저작 누락·오타가 실행 즉시 드러난다(삼손 건으로 실증).
  - keep/relabel 시 기존 서술·프리베이크 본문을 보존하면 재베이크가 신규분(27챕터)으로 최소화 — 전면 재생성보다 처분(diff) 방식이 싸고 안전.
  - 규칙의 하한(3개)이 얇은 인물에 억지 데이터를 강요하면 하한을 완화하는 것이 옳다 — 규칙은 데이터 품질에 복무.
