## Plan vs actual

- What went as planned: 계획 4슬라이스 그대로. App.jsx **670 → 396줄**(51,736 → 19,564 B = 기준선의 38%), explore 블록은 `<ExploreStage … />` 한 호출. Context 미도입(CONVENTIONS §5.4 관례 유지), `Promise.resolve().then(...)` 관용구(§5.3)·로깅 prefix 규약(§1.2, `[App]`→`[ExploreJourney]`) 보존. 시각 차이 0(1부 대비 22컷 중 20컷 픽셀 완전 동일, 2컷은 이미 측정된 지도 노이즈), 번들 +0.37%(계획 ±5% 이내).
- **계획이 그릴링에서 예측한 함정이 실재했고, 그 예측대로 설계해 막았다** — 여정 상태를 ExploreStage로 옮기면 족보 탭 진입 시 언마운트와 함께 소실된다는 예측. 검증 결과 `journey` 재요청 0건 + 정차지 유지(데스크톱·모바일). **계획 단계의 그릴링이 회귀 하나를 사전 차단한 사례.**
- Divergences:
  - `useMemo` import가 미사용이 되어 제거(파생값 2개가 ExploreStage로 이동). lint가 잡아줬다.
  - **시나리오 ④(모바일 시트 pull-down)의 검증 경로를 바꿨다.** 처음엔 연표 사건 제목 클릭으로 시트를 열려 했으나 열리지 않았다 → **HEAD(1·2부 이전) 빌드로 되돌려 같은 조작을 재현했더니 동일하게 안 열렸다** = 기존 동작. **⚠️ 정정(2026-08-02, task#262): 이 관찰은 오조준이었다 — 연표 사건 제목 클릭은 HEAD에서 정상 동작한다(122건 전수 클릭 죽은 0건). 클릭된 것은 사건 제목이 아니라 언약 레이어 항목(`TimelineView.jsx:243`)이었을 것으로 보인다. 상세는 [[260802-154803-bug-hunt-2-1of2]]. 이 문장을 후속 계획의 전제로 쓰지 말 것.** 시트를 확실히 여는 경로(책 상세 "책의 무대" 장소 칩 → `onSelectNode`)로 바꿔 ADR-0010 계약(pull-down = `history.back()` 위임)을 검증했다.
  - **시나리오 ⑥의 초기 실패는 테스트 오류였다** — `location.hash` 직접 대입으로 화면을 전진시키려 했는데 안 먹었다.
  - 검증 목적으로 작업본을 임시로 되돌렸다(4파일 백업 → `git checkout` + 신규 3파일 삭제 → 빌드 → 재현 → 복원 → 재빌드). 복원 검증까지 완료.

## Learnings

- Do differently next time:
  - **앱은 `popstate`만 듣고 `hashchange`는 듣지 않는다**(ADR-0009: 마운트 시 1회 복원 + 이후 `replaceState` 반영). 그래서 **테스트에서 `location.hash` 직접 대입으로는 스테이지가 바뀌지 않는다** — URL만 바뀌고 화면은 그대로다. 딥링크는 **새 브라우저 컨텍스트 진입**으로, 화면 전진은 **UI 클릭**으로 해야 한다. 이 둘을 섞으면 "기능이 깨졌다"는 거짓 경보가 난다.
  - **`history.back()` 위임 뒤로버튼(가계도·단어분포·통계·주제성구)은 딥링크 직행 컨텍스트에서 누르면 페이지를 이탈한다**(히스토리 엔트리가 없어서 — `localStorage access denied` 에러로 나타난다). 이 계열 검증은 **처음부터 다단 클릭**(진입 지점을 만든 뒤 뒤로)으로 짠다.
  - **"회귀인가 기존 동작인가"는 추측하지 말고 HEAD 빌드로 되돌려 재현해라.** 소스 4파일 백업 → `git checkout` → 빌드 → 같은 조작 → 복원. 2~3분이면 끝나고, 이번엔 이 대조로 "연표 클릭이 시트를 안 연다"를 범위 밖 기존 현상으로 확정해 불필요한 fix-forward를 막았다. **⚠️ 정정(2026-08-02, task#262): 기법 자체(HEAD 되돌림 대조)는 유효하지만 이 사례의 결론은 틀렸다 — 되돌림 대조는 "회귀인가"만 답하고 "조준이 맞는가"는 답하지 않는다. 잘못된 요소를 클릭하면 양쪽 빌드에서 똑같이 아무 일도 안 일어나므로 "기존 동작"으로 확정돼 버린다. 조준은 핸들러 보유(`__reactProps$*.onClick`)로 별도 확인할 것. [[260802-154803-bug-hunt-2-1of2]]**
  - **분해(추출) 리팩토링의 시각 검증은 "0이어야 한다"가 기대값이라 판정이 오히려 쉽다.** 2부는 순수 구조 이동이라 20/22컷이 0.0000%로 나왔고, 남은 2컷이 곧 노이즈 목록이었다. 1부처럼 의도된 변화가 섞인 경우와 달리 임계값 논쟁이 없다 — **의도된 시각 변화와 구조 이동은 별 태스크로 쪼개는 편이 검증을 싸게 만든다**(계획의 1부/2부 분할이 결과적으로 이 이득을 냈다).
  - 분리 컴포넌트의 prop이 20개가 됐다. 관례(props 하달, Context 미사용)를 지킨 대가이고 지금은 감당 가능하지만, **다음 분해(`SidePanel.jsx` 928줄)에서 prop 수가 더 늘면 그때는 관례 재검토가 안건**이다.
