# 2026-08-24 — 콘티 최소 밀도 측정. 실질 학습은 이미 승격돼 있었고, 남은 것은 격자 설계 교훈 둘이다

fg-loop 자동 드라이브가 봉인하며 미룬 회고를 batch promotion으로 늦게 승격한 것이다(task#308).

## 계획 대비 실제

**계획대로 간 것** — 정지조건 6/6 통과(검사 exit 0 · 콘티 5장 text_nodes=0 · 생성 45장 고유해시 45 ·
몽타주 3장 규격 · 판정표). 측정은 완주했고 결과가 **음성**(통과 칸 0/45)이었는데, 계획이 그것을
정당한 결론으로 미리 인정해 둔 분기였다.

**이탈 9건.** 대부분은 측정 설계를 실측에 맞춰 고친 것이고(계단 4단→5단 · 격자를 도달 가능값으로
정정 · 프롬프트를 콘티와 같은 순간으로 다시 씀 · IP-Adapter 미적용), 둘은 계획 밖 결함을 잡은
것이다(확대 버튼 아이콘이 조건 입력에 구워짐 · 분모 드리프트 291↔293).

## 학습

**이 회고에서 새로 승격할 것은 없다.** 이 태스크의 실질 학습은 **이미 CONTEXT.md에 광범하게** 있다 —
`[[조건 입력 적합성]]`이 41/45 대 45/45, 두 갈래 실패 양상(저강도=흡수 / 고강도=막대 골격 트레이싱),
「지배 변수는 인물별 선 수와 자세」, 그리고 그 뒤의 **⚠ 측정 입력 결함 정정**(`--at 1000000`이
교체 페이드 뒤 30선 단순화 자세를 찍고 있었다 → `--at 9000`에서 cn 0.6·0.8 전문항 통과)까지 담고
있고, 분모 드리프트도 366~367줄에 「291은 22선 미만 · 293은 D_model 미달 — 같은 표에서 섞어 인용하지
말 것」으로 못박혀 있다. **중복 승격은 문서 신뢰를 떨어뜨린다.**

**다음에 다르게 할 것 — 다른 데 없는 것 둘**

- **손잡이가 계단 함수면 명목 격자를 만들 수 없다. 격자를 짜기 전에 도달 가능 값 집합을 실측한다.**
  계획의 계단(210·91·50·30)은 물리적으로 만들 수 없는 값이었다 — `--min-stroke-width`는 **저작된
  굵기값에 걸리는 계단 함수**라 임의 선 수를 못 만든다. 탐침 2회(22장)로 실제 도달 집합
  (218·149·110·76·59·57·45·34·32·20·12·1)을 얻고 격자를 정정했다. 총선도 계획의 210(소스 계수)이
  아니라 **218**(DOM 계수)이었다 — **무엇을 세는 계수기인지가 축의 값을 바꾼다.**
  ADR `260823-012040`(「계단은 예상 임계를 괄호에 넣는다」)의 **선행 조건**에 해당한다: 괄호를
  넣으려면 그 눈금이 실재해야 한다.
- **쓰이지 않은 보험도 격자가 준 정보다.** 하한 계단(20선)을 「저강도 전부 통과」 대비로 추가했고
  결과적으로 쓰이지 않았다(전부 실패). 그러나 **20선에서도 실패했다는 사실이 결론을 강화한다** —
  「감선 축에서는 도달 불가」를 상한·하한 양쪽에서 받친다. 격자에 계단을 더할 때 「전부 통과/전부
  실패면 무엇을 알게 되나」를 묻는 습관(task#305 회고)이 음성 결과에서 값을 냈다.

**기록만** — `element.screenshot()`은 요소 바운딩 박스에 **겹쳐 그려진 것까지** 담는다(확대 버튼
아이콘이 조건 입력에 구워졌다). **글자가 아니라 아이콘이라 `text_nodes: 0` 단정에 안 걸렸고 육안에서만
잡혔다.** 이 부류(측정한 층과 결함이 난 층이 다르다)는 ADR `260821-000937`·`260824-191250`과
CONTEXT `[[조건 입력 적합성]]`의 「게이트가 전부 초록인 채로 소실」이 이미 담는다.
