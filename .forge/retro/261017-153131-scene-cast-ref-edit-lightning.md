# 2026-10-17 — 2511 + Lightning 4스텝 정본 참조 편집, 판정 채택(사울 6/8·다윗 8/8, 대조 2/6)

## 계획과 실제
- 계획대로 된 것:
  - 장당 약 8.4분(「안 돔」 하한 10분 안), q8 그대로.
  - 32/32 정상, targeted 평균 15.19로 게시 관문 통과.
  - 판정 규칙을 정해 둔 그대로 적용해 채택. 358 판정 페이지 바이트 동일 유지.
- 어긋난 것:
  - **계획 결정 2(외형 = `cast_describe` 기계 삽입)가 S0에서 깨졌다.** 다윗은 바탕이 이미 같은 문구로 그려져 무처치(−1.49)였다. 라마 다윗은 정본의 붉은 튜닉을 문구대로 짙게 바꿔 정본에서 멀어졌다(8.27). fork 벽에서 사람 결정(「권장진행」)으로 정본 그림 쪽 손글씨 서술로 바꿨다.
  - S0 관문은 「첫 장 = 길갈 사울」만 봤기 때문에 통과로 읽힐 수 있었다. 다윗 문제는 엔게디 확인 장과 일부러 더 돌린 라마 1장에서야 드러났다.
  - targeted가 엔게디 다윗에서 평균 2.7(음수 3장)로 나왔지만 눈으로는 8장 모두 편집됐다. 어두운 동굴 배경에 몸 상자가 크고(386×548), 상자 밖 재렌더 잡음이 14~17이라 생긴 과소 측정이다.
  - 판정 지시 「옷 색은 빼고」는 게시 뒤 사용자 질문(「얼굴 및 몸집만 보나? 색깔도 보나?」)을 받고 넣었다(Version 2). 답하기 전이라 결과는 오염되지 않았다.
  - 완료 대기용 백그라운드 셸이 메모리 부족으로 Claude Code에 의해 정리됐다. 생성은 `nohup`이라 무사했고, 사용자 「확인해줘」로 재개했다.

## 배운 점
- 다음엔 이렇게:
  - **참조 편집 지시문의 외형은 참조 그림에서 읽어 쓴다**(PROMPTING 17로 승급). 바탕 생성 문구를 재사용하면 이미 맞는 인물은 편집되지 않는다.
  - **S0 첫 장은 처치 인물마다 한 장씩 본다.** 한 인물·한 장면만으로 관문을 통과시키지 않는다. 4.5시간 배치 전에 인물×장면 조합을 최소 한 장씩 보는 비용(장당 8분)이 훨씬 싸다.
  - **조작 확인 수치가 미달인 장은 눈으로 본다.** targeted(상자 안−밖)는 큰 상자·어두운 배경에서 묽어진다. 다음 편집 과제는 인물 분할 마스크 안에서 재는 것을 검토한다. 그전까지는 미달 장 크롭을 반드시 본다.
  - **판정 단서는 게시 전에 정한다.** 처치가 옷 색·소품처럼 정체성과 무관한 속성을 통일하면, 「같은 사람」 질문에 「무엇을 보고 무엇을 뺄지」를 고정 절에 미리 적는다.
  - **긴 생성은 `nohup`, 긴 대기는 백그라운드 셸에 맡기지 않는다.** 메모리 압박(적재 피크 58.5GB) 때 대기 셸이 정리된다. 사용자 신호로 재개하거나 10분 미만 전경 대기로 나눈다.
  - 같은 프롬프트·시드면 결과가 재현된다(S0 길갈 s11 = S1 s11, targeted 32.65 동일). S0 산출을 본 편집에 재사용하면 장당 8분을 아낄 수 있다.
