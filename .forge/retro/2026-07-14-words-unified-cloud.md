# 2026-07-14 — 단어 분포 UI 개선 (진입 버튼·통합 클라우드+범례·양피지 레이어·스태거 애니메이션, task#177)

## 계획 vs 실제
- 계획대로 된 것: 4슬라이스 전부 완료 기준 충족(진입 버튼 상단 이동·3영역→단일 클라우드+범례·구절 시트→양피지 포털 레이어·스태거 등장 애니메이션). 세션 직접 순차 실행(공유 파일 직렬 프론트 패턴), Playwright 4매트릭스 33/33.
- Divergences (낮음, 현장 결정 2건):
  - **CSS `animation: both`가 inline opacity를 덮는 gotcha** — 단어별 빈도 농도를 keyframe 종료값 `var(--w-op)`로 받고 버튼 inline에 CSS 변수로 전달해 우회.
  - **책 전환 시 스태거 재생** — 동일 key 단어 버튼이 재사용돼 애니메이션이 재생 안 되는 문제를 클라우드 래퍼 `key={bookId}`로 해결.
- **실행 직후 같은 날 quick 레인 후속 5건**이 이어짐(플랜 밖, 별도 커밋): 워드 클라우드 나선 배치(1cf41e6 — 플랜의 flex 혼합 배치를 당일 대체), 진입 UI 3차 정정(허브 pill 12f4213 → 둘러보기 하위 메뉴 탭 7076842 → 책 상세 내비 탭 c2b6808), 책 정보 바로가기 탭(e53ec23).

## 배움
- 다음에 다르게 할 것:
  - **"메뉴를 ~로 옮겨/추가해" 요구는 상단 내비 바의 하위 메뉴 탭으로 먼저 해석하라.** 이 사용자(및 이 앱)의 멘탈 모델은 탐험 내비의 뷰 토글 탭(아이콘+라벨, 활성 금색 밑줄)이 "메뉴"의 기준형이다 — 패널 내 pill 버튼·허브 랜딩 버튼으로 두 번 잘못 해석해 3차 정정을 겪었다. 배치류 요구는 그릴링 때 "내비 탭 vs 본문 버튼" 한 줄 확인이 재작업보다 싸다.
  - **워드 클라우드는 라이브러리 없이 DOM 나선 배치로 충분**(단어 ≤120): canvas measureText + AABB 충돌 + 아르키메데스 나선(y 0.55 압축), 버튼 DOM 유지라 클릭·테마 var·스태거 애니메이션이 공짜로 보존된다.
  - Playwright에서 같은 문서 내 해시 이동(goto로 해시만 변경)은 SPA 스테이지를 리마운트하지 않는다 — 딥링크 검증은 반드시 신선 로드/새 컨텍스트로(기존 "URL마다 새 컨텍스트" 교훈의 재확인).
- 후속 후보: 없음 (진입 동선 3곳 내비 통일로 수렴).
