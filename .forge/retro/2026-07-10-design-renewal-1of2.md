## Learnings

- Do differently next time:
  - **시각·디자인 가정은 그릴링 단계에서 실화면 스크린샷 1장이라도 찍고 세워라.** 코드(CSS 변수·클래스)는 선언일 뿐 렌더가 진실 — 이번 "라이트 단일" 오추정은 5분짜리 허브 스크린샷이면 막혔다. 디자인 태스크의 fg-ask는 캡처 후 그릴링이 기본 순서.
  - **실행 전 프로젝트 메모리의 도구 함정 목록을 먼저 읽어라.** "해시만 다른 goto는 SPA 리로드 안 함"(task 148)·".rel-chip 직접 클릭"이 메모리에 이미 있었는데 미참조로 1차 캡처 전체(허브 복제 12장)를 버리고 재작업했다. Playwright 작업 시작 = `feedback_playwright_testing` 메모리 선독.
  - 신규 캡처 함정 3건(메모리에도 승급): ① CSS 토글로 숨긴 뷰가 DOM에 잔존 → 텍스트 셀렉터에 `>> visible=true` 필수(타임라인 화면에 여정 리스트 텍스트가 숨은 채 매치됨). ② lucide 아이콘(📖 모양)은 이모지 텍스트 매칭 불가 → 인접 텍스트로 클릭. ③ 리로드 대안으로 `?v=<name>` 캐시버스터 쿼리가 화면당 독립 문서 내비게이션을 보장(reload보다 상태 오염 없음).
  - 사건→장소 시트 진입은 사건마다 Place 이웃 유무가 다르다(골리앗 사건은 없음) — UI 동선 검증 대상은 API(`/node/{id}`)로 이웃 먼저 확인하고 고른다.
