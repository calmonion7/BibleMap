# 2026-08-19 — 장소 페이지: "이곳에서 일어난 일"을 모으는 전용 화면 (task#270)

## 계획 대비 실제
- 계획대로 된 것: 슬라이스 3개(`/place/{id}` → `place` 스테이지 → 진입로 3곳) 전부 완료 기준 충족. 베들레헴 인물 5·사건 9, 좌표 전용 장소(오브라)도 200으로 열림.
- 이탈:
  - `overlays.place_context()` 로더를 새로 뒀다 — `place_context/places.json`은 지금까지 **Neo4j 주입 전용**이라 백엔드에서 파일로 읽는 경로가 없었다. `places.py`가 "Neo4j 없이 파일만으로 결정적"이라는 기존 성질을 유지하려는 선택.
  - 404 조건을 **넷(배경·좌표·인물·사건)이 모두 빌 때만**으로 좁혔다. 오타 id가 빈 화면으로 열리는 것보다 404가 낫다.
  - 시트 진입로와 정차지 진입로가 같은 `data-open-place` 속성을 공유해 검증기가 둘을 구분하지 못했다 → 시트 버튼에만 붙는 `data-open-place-sheet`를 추가.

## 배움
- 다음에 다르게 할 것:
  - **판정 기준(`occursAt[0]`)을 "맞췄다"고 쓰지 말고 두 응답을 실제로 대조하라.** 계획의 핵심 제약이 "화면 간 숫자가 어긋나지 않을 것"이었으므로, 새 `/place/{id}`의 인물 집합과 기존 `/place/{id}/curated-persons`의 인물 집합을 **집합 비교로 단언**했다. 같은 기준을 썼다는 코드 주석은 증거가 아니다 — 집합이 같다는 실측이 증거다.
  - **캔버스 위 요소는 클릭 검증이 결정적이지 않다 — 한계를 숨기지 말고 명시하라.** 지도 마커 팝업 진입로는 마커가 canvas라 좌표 클릭이 불안정해, 배포 번들에 팝업의 "이 장소 보기" 마크업이 실렸는지 + 캔버스가 뜨는지로 단언했다. 나머지 두 진입로는 클릭→해시 이동까지 실측. **end-to-end가 아닌 항목은 체커 주석과 보고 양쪽에 그 사실을 남긴다** — "10/10 통과"가 모든 항목이 같은 강도라는 뜻이 되지 않도록.
  - **DOM 훅은 진입로별로 구분되게 심어라.** 같은 속성을 여러 진입로가 공유하면 개수만 세는 검증이 통과해도 "어느 경로가 동작하는지"는 모른다.
