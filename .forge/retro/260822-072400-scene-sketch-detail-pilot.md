# 2026-08-21 — 장면 세밀화 파일럿 3장면 (task#286) — 자(尺)가 눈먼 것을 브라우저가 잡았다

## Plan vs actual

- **What went as planned**: 시간 예산 상향(296정차지 step 8,360~10,000ms) · 규약 B1~B6을 `lib.jsx`
  정본에 명문화 · 파일럿 3장면 재작도 · 검증기 신설과 `check.sh` 배선(22종) · 실물 UAT와 필름스트립.
- **Divergences**:
  1. **실행 순서를 바꿨다** — 계획은 재작도(S3) → 검증기(S4)였으나 검증기를 **먼저** 세워
     `line-artist` 3명에게 자기 판정 도구로 쥐여 줬다. 셋 다 1회 왕복으로 수렴했다.
  2. **검증기 파서가 눈멀어 있었다.** `style={d(reduce ? 0 : 5000, reduce)}`(삼항)와
     `<circle style={d(3500,false)}>`(stroke 요소 자체의 지연)를 못 읽어 GoliathScene을 드로인
     2,700ms로 판정했다 — 브라우저 실측은 6,000ms. 이 형태는 9모듈 **110곳**에 퍼져 있었다.
  3. **UAT와 정적 검사의 "SMIL" 정의가 달랐다** — 브라우저는 `<Label>` 이름표의 페이드인도 SMIL로
     센다. B5가 말하는 것은 *절정*이므로 `<text>` 하위라는 구조적 기준으로 갈랐다.

## Learnings

- **Do differently next time**:
  - **저작 규약을 만드는 태스크는 검증기를 저작보다 먼저 세운다.** 저작자가 자기 결과를 스스로
    판정하면 왕복이 1회로 준다. 계획 순서(저작 → 검증)를 기계적으로 따르지 말 것.
  - **정적 검사 하나로는 자기가 눈멀었는지 알 수 없다.** 독립적인 실측(브라우저)이 자의 자 역할을
    한다. 소스 불변식과 실물 UAT를 **둘 다** 두라는 관례가 여기서 값을 냈다.
  - **게이트의 위험은 "빨강이어야 할 때 초록"만이 아니라 "애초에 재지 않았는데 초록"이다.**
    후자는 실패 메시지가 없어 눈에 띄지 않는다. 대조군은 "위반을 잡는가"뿐 아니라
    **"대상이 빠짐없이 열거되는가"**도 물어야 한다(이 태스크에서 모듈 통째 열거가 다른 파일로
    옮겨간 장면을 조용히 건너뛰는 구멍이 뒤이어 드러났다).
- **Confirmed (유지)**: 파일 소유권 단위 병렬(모듈 1개당 에이전트 1명)은 충돌 0건.
