## 배운 것
- **그릴링 때의 사전 측정이 실행을 「확인」으로 바꿨다.** 열세 판의 예측값을 계획에 표로 박아 두자 fg-loop의 C2 검사가
  `diff`로 끝났고, 실행은 3줄 편집 + 문서였다. 결정론적 판정자가 있는 작업은 **그릴링 단계에서 결과를 먼저 재고 계획에
  표를 남기는 것**이 가장 싼 검증이다(같은 영역 회고 `260902-194000`의 「크기만 바꿔 한 판 재는 것이 가장 싼 판별」의 계획판).
- **문자열 grep DoD는 「그 코드를 설명하는 주석」에 걸린다.** 「옛 코드가 사라졌다」를 `grep -c "<옛 코드>" → 0`으로
  재면, 왜 바꿨는지 적는 주석이 옛 코드를 인용하는 순간 실패한다. 다음엔 ① 계획에 「주석에서 옛 값을 인용할 땐 이렇게
  표기한다」(이번엔 `n<20`)를 같이 적거나, ② 검사를 코드 형태에 묶는다(`grep -c "if n < 20"`). 이번엔 계획이 우연히
  `n<20` 표기를 쓰고 있어 ①로 풀렸다.
- **판정자 변경은 DoD에 「임계 불변」 회귀 가드를 넣어야 한다.** fg-loop 정지조건에 `c3_paste_seam_max: 0.40` grep을
  추가했다(계획 DoD에는 없었다). 「자를 고쳐 통과」와 「임계를 옮겨 통과」는 grep 결과가 같은 exit 0이라 이 가드 없이는
  구분되지 않는다 — 판정자·게이트를 건드리는 다음 계획은 DoD에 이 줄을 기본으로 둔다.
- **워크플로 없이 직접 실행이 맞았다.** 코드 3줄 + 문서 정합에 서브에이전트 팬아웃은 낭비 — fg-run의 「단일 에이전트로
  충분하면 직접」 분기를 fg-loop 안에서도 그대로 적용해 된다.
- **다음에 다르게 할 것**: 게이트 산식·가드 변경 계획은 (a) 그릴링 때 교정 집합 전체를 사전 측정해 예측표를 박고,
  (b) DoD에 임계 불변 가드와 주석 인용 표기 규칙을 함께 적는다.
