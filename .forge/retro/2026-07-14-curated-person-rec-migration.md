# 2026-07-14 — 큐레이션 저작 인물 11명 실레코드 이관 (가계도 빈 트리 해소)

## Plan vs actual

- What went as planned:
  - 이관 매핑 11건이 계획의 사전 신원 검증 그대로 적중(재탐색 0회), 다니엘·엘리야 제외 판정도 유지. 검색 회귀 방지(큐레이션 rec wip 무마킹)가 계획이 짚은 대로 핵심이었고 구현도 그대로.
  - 여정·카드·성품 무회귀(slug 축이라 API 무변경), 실동선(허브→소개→가계도) UAT까지 계획 순서대로.
- Divergences (전반적으로 낮음):
  - 활성 슬롯을 #174(검증 완료·회고 대기)가 점유 → `.forge/executed/`로 **주차**해 슬롯을 비우고 진행 — Run-all의 상태 계약(executed/=회고 대기)을 단일 실행 경로에서 재사용.
  - names_ko "이전" 슬라이스가 no-op — authored 키가 names_ko에 원래 없었음(저작 인물 nameKo는 load_authored_persons가 직접 SET). 계획의 파일 내용 전제가 틀렸으나 결과는 동일(섬 25명 신규 추가로 흡수).
  - 검색 '룻' 2건은 중복이 아니라 동명이인(Lud, 창 10:22의 개역 표기 '룻') — 기존 정확 데이터, 조치 없음.
  - api 재빌드 불필요 판명(data/ 볼륨 마운트) — persons.py lru_cache 클리어용 재시작만.

## Learnings

- Do differently next time:
  - **검증 완료·회고 대기 작업이 활성 슬롯을 막을 땐 executed/ 주차가 정석** — 상태 계약(위치=상태)에 부합하고 fg-learn이 자연히 집어간다. 회고를 미룬 채 다음 실행을 시작하는 안전한 수순.
  - **계획의 사전 조사에 "파일에 그 키가 실제로 있는가"까지 확인하라** — names_ko에 authored 키가 있다고 가정한 이전 슬라이스가 no-op였다. 대세 지장은 없었지만, 전제가 반대 방향(있어야 할 게 없음)이었으면 실행이 막혔다.
  - **데이터 파일 변경 후 API 반영은 마운트 여부부터 확인** — 이 스택은 data/가 볼륨 마운트라 재빌드 불요, lru_cache만 재시작으로 클리어. (프론트 dist 빌드 필요와 대비되는 지점 — 메모리의 빌드 규칙과 혼동 주의.)
- 범위 밖 관찰(후속 후보):
  - 동명이인 한글 표기 충돌(룻=Ruth/Lud)이 검색에서 구분 정보 없이 나란히 노출 — 검색 결과에 구분자(영문명 병기 등) 표시 여지.
