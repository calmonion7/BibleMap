# 2026-06-13 — MapView 장소 클릭 시 과도 줌 제거 (링 프레이밍 통합) (task 16)

> task 15의 미뤄둔 "사람 눈 줌 UAT"의 후속 — 모세 검색 후 장소 클릭 시 줌이 너무 당겨져 사건 링이 화면 밖으로 날아가던 문제.

## 계획 vs 실제
- 계획대로 간 것: 질문 2의 (A) 거동 달성 — 마커 클릭 시 과도 줌 제거, 링이 표시 줌에서 잘림 없이 보임. 인물/집단·토글·접힘 시맨틱 무변경, 백엔드 무변경. lint 0 / build green.
- 발산:
  1. **플랜(S1)이 가정한 수정 범위가 실제 근본 원인보다 넓었다.** 플랜은 `selectedNodeRef` 추가 + 마커 클릭 핸들러 수정 + selection effect 가시성 판정 분기를 제안했으나, 코드 정독 결과 실제 원인은 **effect 끝의 무조건 `map.fitBounds(..., maxZoom 10)`** 가 *마커 클릭으로 이미 현재 줌에서 펼쳐진 장소*에도 실행돼 카메라를 스냅하던 것 하나. effect의 fitBounds를 `primary && 아직-안-펼침`(maxZoom 7)·`primary 없음`(maxZoom 10) 분기에만 남기고 이미 펼친 primary는 카메라 미이동 → 한 블록(~30줄) 교체로 끝. ref·핸들러 수정 불필요.
  2. maxZoom 8→7로 한 단계 더 낮춤(검색 단일 장소 과도 확대 방지).
  3. 가시성 판정은 명시 코드 없이 구조적으로 충족(마커 클릭은 framing 분기 비진입 → 자동 "현재 줌 유지").

## 학습
- 다음에 다르게 할 것:
  - **버그 수정 플랜을 짜기 전에 관련 코드 경로를 끝까지 추적해 근본 원인을 좁힐 것.** 여기선 두 진입점(마커 클릭/자동 펼침)이 한 effect의 무조건 fitBounds에서 만나는 게 원인이라, 새 ref·핸들러 분기 없이 그 fitBounds 하나만 조건화하면 됐다. "넓게 잡고 들어가는" 플랜은 불필요한 복잡도를 부를 뻔했다(CLAUDE.md §2/§3).
  - **알려진 소한계 — 마커 클릭은 카메라를 재중심하지 않으므로 화면 가장자리 마커는 링이 그 변에서 일부 잘릴 수 있다**(시트 위 가시 띠가 좁은 모바일에서 더 두드러짐). 신고 대상(과도 줌)과 별개라 이번 범위 외 — 거슬리면 "가장자리일 때만 가벼운 팬" 별도 태스크로.
  - 헤드리스 모바일에서 베이스맵 타일 미렌더 재확인(task 15 학습과 동일) → 모바일 프레이밍 심미는 실기기/실서버 사용자 눈으로.
