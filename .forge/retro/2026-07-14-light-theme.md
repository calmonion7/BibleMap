# 2026-07-14 — 라이트 테마 "Day Atlas" 추가 (task#173, 다크 기본 + 허브 토글 옵트인)

## Plan vs actual
- 계획대로 된 것: 4슬라이스 전부 완료 기준 충족 — Day Atlas 토큰 블록·부트 반영·허브 토글(S1), 잔재 스윕·지도 불변(S2), 타입/valence 라이트 보정(S3), 두 테마×데스크톱/모바일 Playwright 검수+빌드+배포 확인(S4). UAT `yes`, 다크 기본 무회귀.
- Divergences:
  - **실행 방식: 워크플로우 대신 세션 직접 순차** — 직전 두 회고(book-detail·genealogy)의 "직렬 의존+공유 파일 프론트는 직접 순차가 유리"를 세 번째로 적용해 확정 패턴이 됨. 충돌·재탐색 0.
  - **S3이 더 외과적으로 뒤집힘**: 계획 "UI 사용처 ~50곳을 변수 참조로 전환" → 실제 **theme.js 상수 값 자체를 `var(--…)` 문자열로 교체**(호출부 0곳 수정). 전제 조건 2개를 실행 중 전수 확인하고 채택: ① 전 사용처가 CSS 컨텍스트(인라인 style), ② 지도(mapLayers)가 이 팔레트를 안 씀 — theme.js의 옛 주석("MapView가 공유")은 사실과 달랐다.
  - **NIGHT JS 상수 삭제**(계획은 "테마 대응"까지): Spinner의 `${color}22` 알파 이어붙임을 `color-mix(in srgb, C 13%, transparent)`로 고치자 var()를 받게 돼 hex 리터럴 상수의 존재 이유가 소멸. `${GOLD}12` 류 알파 결합 13곳도 color-mix %로 전환(hex 알파→% 환산: 12→7·22→13·33→20·50→31·90→56).
  - **`--danger` 시맨틱 토큰 신설** — 에러색 하드코딩 5곳(#f87171/#dc3545)이 라이트에서 저대비. "토큰이 없어 하드코딩 유지"라던 주석 3곳이 있는 곳 = 토큰을 만들라는 신호였다.
  - **양피지 경계는 1곳만**: 모달 3곳은 다크 스크림이 이미 분리 → SidePanel 인라인 카드에만 `--line-strong` 테두리(다크에선 흰 알파라 비가시 = 무회귀 트릭).

## Learnings
- Do differently next time:
  - **팔레트를 테마 대응시킬 땐 호출부를 고치지 말고 상수의 값을 CSS var 참조로 바꿔라** — 단, "전 사용처가 CSS 컨텍스트인가"를 먼저 전수 확인(문자열 알파 결합·캔버스/지도 paint 속성이 결격 사유). 결합 지점은 color-mix로 먼저 해체하면 var 수용 범위가 넓어진다.
  - **"토큰이 없어 하드코딩" 주석이 2곳 이상 반복되면 그 시맨틱 토큰을 만들 때다**(이번 --danger). 주석은 부채의 위치 표식.
  - **테마·전역 스타일 검증은 이번 매트릭스가 최소 단위로 유효**: 두 테마 × 두 뷰포트 × 실제 진입 동선(착지 뷰에서 토글 가시성 포함) + 기본 테마 회귀 + 새로고침 유지. 기능 체크(evaluate)와 스크린샷 육안을 병행.
  - **공유 파일 직렬 프론트 작업 = 세션 직접 순차**는 3회 연속 유효 — 이제 fg-run에서 이 형태면 기본값으로 바로 선택해도 된다.
- 범위 밖 관찰(후속 후보): 없음 특기할 것. (theme.js 옛 주석의 "MapView 공유" 오기는 이번 커밋에서 함께 정정됨.)
