# 2026-10-30 — 정본 참조 편집(2511 + Lightning) 재검: 편집기를 한 번 거치는 것만으로 원래 화소 화풍이 바뀌어 미채택

## 계획 대비 실제
- 계획대로 된 것: 고정 절(판정 규칙·정지 조건)을 첫 편집보다 먼저 커밋했다(65e9d26). 편집 5번은 모두 q8로 600초 안에 끝났다. 9문항 사람 화면을 게시했고, 답을 받아 고정 규칙 첫 줄(T에 「다른 화풍」)로 `판정: 미채택 — 편집기 통과만으로 화풍이 바뀜`을 기록했다. DoD 1~8 모두 통과.
- 어긋남:
  - T 다윗 편집이 Claude Code 메모리 부족 정리로 한 번 끊겨, 사람 지시로 다시 돌렸다(장당 피크 58.5GB 스왑 경로 — 449 걸리는 점 ③ 그대로).
  - 다윗 머리 상자가 87화소로 하한 100에 못 미쳐 Gram 세 칸이 모두 `측정 불가`였다. 편집 전에 이미 보였지만 고정 절을 고치지 않았다.
  - 사울 Gram 낌새(E가 T보다 C에 가까움)는 사람 답과 갈렸다. 머리 둘레 6문항은 모두 「다른 화풍」이었다.

## 배운 것
- 다음엔 다르게:
  - **편집·변환 수단을 잴 때는 T(자기 자신 편집 = 소음 바닥) 갈래를 꼭 넣는다.** 이번 결론을 가른 것은 E·W가 아니라 T였다. T가 없었다면 「되붙임 방식이 문제」로 잘못 짚고 E·W 변형만 더 돌렸을 것이다. 수단 자체의 바닥 변화를 먼저 재면, 갈래 비교 전에 수단 전체를 접을 수 있다.
  - **머리 둘레 측정 하한(100화소)은 장면 구도에 따라 한 인물을 통째로 빠뜨린다.** 기브아 창 시드 11 다윗은 87화소였다. 다음 Gram 낌새를 계획할 때는 그릴링 단계에서 대상 인물의 머리 상자 크기를 먼저 재고, 하한에 걸리면 다른 시드를 고르거나 처음부터 「사울만 잰다」고 고정 절에 적는다.
  - **Gram 낌새는 이번에도 사람 답과 갈렸다(448에 이어 두 번째).** 화풍 판정은 계속 사람 화면이 관문이고, 측정자 고치기(바탕 비율 고정)가 끝나기 전에는 낌새 기록에 시간을 덜 쓴다.
  - 장당 8~9분 편집은 이 세션 메모리와 겹치면 끊긴다. 긴 GPU 편집은 백그라운드 단독 실행 + 산출 파일 존재로 재개 판정하게 짠다.
- 확인된 것: 「결과 보기 전에 판정 규칙 고정 + 결과 보고 고치지 않음」 덕에, 사울 Gram 낌새가 유리하게 나왔어도 판정이 흔들리지 않았다.
- 관찰: E·W 편집이 얼굴을 바꾸는 대신 장면 표정(사울 광기·다윗 놀람)을 지웠다 — ADR 되돌리기 판단의 근거로 후속 fu-b4a3d042928a에 넣었다.
