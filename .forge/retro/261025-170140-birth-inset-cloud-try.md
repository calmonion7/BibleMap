# 2026-10-25 — 솔로몬 출생 12:25 나단 + 12:24 뭉게구름 곁 장면 합성 · 규칙 정리(task 417)

## 계획 대비 실제
- 계획대로: 큰 장면 명세 → 곁 장면 분리 → 시드 42 한 장씩 생성·합성 → 사람 판정 → 규칙 원장. 사람 판정 1로 채택.
- 벗어남:
  - **사람 판정이 그림을 두 번 바꿈**: 판 2 메모 「구름을 가운데」(한 사람 머리 곁이면 그 사람의 생각) → 인물을 양 끝으로 · 판 3 메모 「손짓이 있어야」 → 뼈대 가이드. 둘 다 계획의 「구름 꼴부터 고침」 범위였으나 구름 자리·몸짓이 핵심이었음.
  - **곁 장면에 선 여인**: 넓은 화면에 앉은 한 사람 → 빈자리를 사람으로 채움. 문구 부정을 의심했다 기각(같은 시드로 다시 그려 가설을 가름) → 틀 비율로 풀림.
  - **판정 화면 그림 깨짐**: 문자열 자리표를 그림 base64를 넣은 뒤에 바꿔 데이터 속 같은 글자(「Q24」)까지 바뀜.

## 배움
- 다음엔 다르게:
  - 문구로 준 손 자리·몸짓은 실측상 안 나온다(이번 0/4) — 몸짓이 장면의 뜻을 나르면(대화·애원) 첫 그림부터 뼈대로. 원장 pose-hold가 이제 「손을 내밂·폄·모음」을 잡는다.
  - 두 때를 한 그림에 넣을 땐 구름을 인물 사이 위에 — 구석·한 사람 머리 곁은 「그 사람의 생각」(사람 판정 4).
  - 곁 장면·작은 판은 쓸 틀의 비율로 생성한다 — 크게 그려 자르면 빈자리에 엉뚱한 사람이 들어온다.
  - 결함 원인을 가설로 세웠으면 같은 시드로 그 하나만 바꿔 가른다(부정 문구 가설 1장으로 기각 — 엉뚱한 규칙을 안 만듦).
  - 고유 이름 간판처럼 한 장 관찰이 다른 장면 승인 그림과 엇갈리면 규칙으로 올리지 않는다(올리면 승인 그림이 낡음).
  - HTML에 base64를 넣을 땐 문자열 자리표를 먼저 바꾸고 그림은 마지막에, 자리표는 base64에 없는 꼴(`@@…@@`)로. 올린 뒤 그림 디코드 검사.
