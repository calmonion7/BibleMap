# 2026-08-01 — App.jsx 분해 1부: 9개 스테이지 내비를 합성형 StageNav로 통합 + 활성 탭 금색 밑줄 미렌더 5건 수정 (task#257) [fg-loop 자동 스킵 → 일괄 승급]

## Plan vs actual

- What went as planned: 계획 4슬라이스 그대로(기준선 22컷 → StageNav 신설·9개 치환 → 밑줄 계산 스타일 검증 → 시각 동치 대조). 합성형(slot) 설계 근거도 계획대로 유효했다 — 껍데기·뒤로버튼·탭 3덩어리만 컴포넌트화하고 조립은 호출부 JSX에 남겼다. 규모가 단일 파일 직렬 작업이라 Dynamic Workflow 없이 직접 실행.
- Divergences:
  - 줄수가 계획 예상(~735줄)보다 더 줄었다 — **1081 → 670줄**. 껍데기·뒤로버튼 복붙이 예상보다 많았다. 번들도 덤으로 250,811 → 242,034 B(-3.5%).
  - **밑줄 복원에 1px 부수효과가 딸려온다(계획 미인지).** 전역 `box-sizing` 리셋이 없어 기본이 content-box다. 탭 버튼은 `height:'100%'`(=48px content)이므로 실제 2px 밑줄을 살리면 총 50px가 되어 48px 내비를 넘친다. `boxSizing:'border-box'`로 안쪽에 넣으면 content가 48→46px로 줄고 가운데 정렬된 아이콘+라벨이 **1px 위로 올라간다**. 즉 계획 S4의 "차이는 밑줄 하나"는 엄밀히 **"밑줄 + 내비 밴드 내부 1px 상승"**이다. 밴드 밖 변화는 0(정량 확인).
  - 비활성 탭도 `2px solid transparent`로 통일했다 — 통일하지 않으면 활성 탭만 content 46px가 되어 탭 전환 시 높이 지터가 생긴다(탐험 내비 작성자의 원래 의도를 5곳 전부에 적용).
  - **CONVENTIONS §2.2 문구와 실제 eslint 설정이 어긋난다.** §2.2는 "컴포넌트 파일에서 비-컴포넌트 상수 export 금지"라 하고 계획도 `constants.js` 이관을 우선하라 했지만, 실제 설정은 `reactRefresh.configs.vite`(= `allowConstantExport: true`)이고 `SpineHeader.jsx`가 이미 `HEADER_H`·`RIBBON_OVERHANG`를 export한다. 그래서 `StageNav.jsx`에서 `export const NAV_H = 48`로 두고 lint 0 확인.
  - 계획에 없던 **재배선 스모크**를 추가했다(클릭→해시 25건). 이 리팩토링의 실질 위험은 스타일이 아니라 9개 내비의 `onClick` 전사 오류였고, 계산 스타일·픽셀 대조로는 안 잡힌다.

## Learnings

- Do differently next time:
  - **인라인 스타일에서 단축 `border`는 항상 개별 `borderBottom`보다 앞에 둔다.** 뒤에 오면 앞의 `borderBottom`을 조용히 되돌리고, 코드만 읽으면 밑줄이 있는 것처럼 보인다(9개 복붙본 중 5곳이 그 상태였고 아무도 몰랐다). 같은 함정은 `background`/`backgroundColor`, `font`/`fontSize`에도 적용 — **키 순서 의존 버그는 계산 스타일 실측(`getComputedStyle`)으로만 잡힌다.**
  - **"코드가 그렇게 쓰여 있다"를 렌더 증거로 쓰지 말 것.** 밑줄 유무는 `grep`으로 확인하면 통과하고 화면에선 없었다. 시각 속성 검증은 Playwright 계산 스타일로.
  - **테마 토큰은 값이 테마별로 다르다** — `--gold`는 다크 `rgb(201,168,76)` / 라이트 `rgb(138,109,31)`. 계획서엔 다크값만 적혀 있어 라이트에서 오탐할 검증이었다. 색 검증은 테마별 기대값을 따로 잡는다.
  - **비결정 캡처는 "동일 코드 2회 자기대조"로 분류하고 나서 픽셀 게이트를 걸어라.** 책 상세 페이지에 임베드된 maplibre 지도 라벨 AA가 런투런으로 흔들려(동일 코드 5런 쌍별 밴드 밖 0~243px), 자기대조 없이 before/after만 보면 무관한 노이즈를 회귀로 오판한다. 반대로 노이즈를 통째로 무시하면 진짜 변화가 숨는다 — **차이를 관심 영역(내비 바 y-밴드) 안/밖으로 쪼개고, 밖의 값은 실측 노이즈와 대조**하는 게 실제로 작동한 방법이다(20/22컷이 밴드 밖 정확히 0px으로 나와 판정이 선명해졌다).
  - **Playwright에서 내비 바를 찾을 땐 렌더 높이가 `NAV_H`가 아니다** — `height:48` + `borderBottom:1px`이 content-box라 실제 49px. `=== 48`로 잡으면 전 케이스 미검출(첫 캡처 22컷을 그렇게 날렸다).
  - **허브(`#/`) 캡처는 `localStorage['biblemap-intro']='off'`를 먼저 심어야 한다** — 아니면 인트로 필름으로 빠진다.
  - **fg-loop 정지조건 체크는 "게임 가능성"만 보지 말고 "무관한 기존 코드를 벌하지 않는가"도 봐야 한다.** "App.jsx 최장 줄 ≤ 200자"를 줄수 게임 방지용으로 넣었는데, 기준선에 이미 200자 초과 줄이 3개 있고 2개는 리팩토링 후에도 남아 통과 불가능한 체크였다. 바이트 총량(≤ 기준선 55%) + "200자 초과 줄이 기준선 개수를 넘지 않음"으로 교체해 의도(줄 합치기 방지)를 직접 재게 했다.
