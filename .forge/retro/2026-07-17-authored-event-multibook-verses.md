# 2026-07-17 — 저작 사건 다권 근거 구절 저작 보강 (task#203, 일괄 승급 회고)

## Plan vs actual

- 계획대로 된 것: 21사건×누락 37권 병렬 저작, 기계 검증 4항목(verseID 존재·정경 순번·자기일치·rangeLabel) 탈락 0으로 32권 반영, api 재시작만으로 반영(볼륨 마운트+lru_cache), 전수 재스캔·UI 3사건 확인 통과.
- 이탈:
  - **저작 스킵 5권** — 계획이 예정한 원칙 발동(이탈이라기보다 원칙의 실증): 물위걸음의 마가·요한(베드로 서술 부재), 겟세마네의 요한(이동만 언급), 공의회의 야고보서(평행 기사·자기 언급 모두 없음), 고린도의 살후(정황 자기증언 절 없음).
  - Workflow `args`가 JSON 배열로 넘겨도 문자열로 도착해 초기 기동 즉사 → `typeof args === 'string' ? JSON.parse(args) : args` 가드 패치 후 캐시 재개.
  - UI 확인 에이전트: "외 2권" 텍스트만으로 칩을 특정하면 같은 권수의 다른 사건이 먼저 매치 → 사건명으로 행 특정 후 행 내부 칩 클릭으로 교정.

## Learnings

- Do differently next time:
  - **저작 사건은 "책 연결"과 "근거 구절"이 이원화돼 있다** — 그래프의 사건–책 연결(칩 집계)과 `event_verses` 오버레이(레이어 서빙)를 함께 채우지 않으면 칩·레이어 불일치가 난다. 새 저작 사건을 만들 땐 두 층을 한 세트로 저작할 것.
  - **근거 인정 2패턴(평행 기사 / 집필 정황 자기 언급) 어휘가 저작 품질을 지켰다** — 이 경계 덕에 sonnet 저작 에이전트들이 야고보서 인사말 일치(외부 저자추정 논거) 같은 그럴듯한 억지 인용을 스스로 거부했다. 구절 저작 프롬프트에 이 2패턴+스킵 허용을 항상 명시할 것.
  - **후속 과제**: 스킵 5권은 구절 근거를 가질 수 없는 사건–책 연결 — 칩 불일치가 4개 사건에 잔존한다. 그 연결 자체의 정당성 재검토(제거 또는 근거 재정의)를 별도 태스크로.
  - **Workflow `args`는 문자열 도착 가능성을 항상 가드할 것**(`JSON.parse` 폴백) — 도구 문서가 JSON 값 전달을 지시해도 런타임에서 문자열화될 수 있다.
  - 대량 저작의 신뢰는 "저작(창의) ↔ 검증(기계)" 분리에서 나왔다 — 저작 에이전트는 파일을 안 만지고 JSON만 반환, 병합자가 verseID 계산·정본 대조·형식 반영을 전담. 재사용할 구도.
