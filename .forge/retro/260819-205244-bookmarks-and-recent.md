# 2026-08-19 — 북마크와 이어보기: 이 기기에 저장되는 개인화 계층 (task#268)

## 계획 대비 실제
- 계획대로 된 것: 슬라이스 3개(훅·저장 스키마 → 세 화면 토글 + 최근 자동 기록 → 허브 섹션) 전부 완료 기준 충족. 파손값 폴백·상한·중복 승격까지 화면에서 실측.
- 이탈:
  - **훅 인스턴스는 App에 하나만** 뒀다. `useBookmarks()`를 각 컴포넌트가 따로 호출하면 각자 `useState`를 가져 토글이 서로에게 즉시 반영되지 않는다(계획의 "토글이 즉시 반영" 위반). 이 코드베이스는 컨텍스트 없이 prop drilling을 쓰므로 App에서 1회 인스턴스화해 내려보냈다.
  - `useStageNavigation`에 **`goToHash`를 추가하고 딥링크 복원 매핑을 `applyParsedHash`로 승급**했다. 저장 카드 클릭 복원은 `location.hash` 대입으로는 안 되기 때문(아래 배움) — 복제 대신 승급해 딥링크 복원과 카드 복원이 같은 매핑을 공유한다.
  - 저장 항목 해시를 **뷰 없는 스테이지 기본 해시**로 고정했다. 탐험은 뷰 토글마다 해시가 바뀌어, 현재 해시를 그대로 쓰면 한 인물이 최근 목록에 5번 쌓인다.

## 배움
- 다음에 다르게 할 것:
  - **Playwright에서 localStorage를 누적시키며 화면을 옮길 때는 "새 컨텍스트"가 아니라 "같은 컨텍스트 + 새 페이지"다.** 기존 교훈("딥링크 검증은 URL마다 새 컨텍스트")을 그대로 적용하면 저장값이 매번 초기화돼 이 기능은 검증 자체가 불가능하다. 반대로 같은 페이지에서 `goto`로 해시만 바꾸면 문서가 재로드되지 않아 스테이지 복원이 일어나지 않는다(C3 1차 실패의 실제 원인 — 제품은 정상이었다). **정답은 컨텍스트 유지 + 화면 전환마다 `ctx.new_page()`**: 문서는 완전 로드되고 localStorage는 오리진 단위로 공유된다.
  - **검증기가 실패하면 제품을 고치기 전에 직접 디버깅으로 실물을 먼저 확인하라.** C3가 "토글 0개·최근 0건"이라고 했지만 실제 화면에는 토글 1개와 최근 라벨 "다윗"이 정상적으로 있었다. 30초짜리 수동 확인이 없었다면 멀쩡한 제품 코드를 고치기 시작했을 것이다.
  - **문서 안에서 해시만 바꾸는 이동은 SPA 스테이지를 리마운트하지 않는다** — 앱 내부 복원은 반드시 상태 머신을 태워야 한다(`goToHash`). 이건 검증 기법이 아니라 **제품 설계 제약**이기도 하다.
- 후속 후보: 없음.
