# 2026-07-16 — 의존 `물음-응답` 표시 어휘를 petition→"나아감"으로 정정

## Plan vs actual
- What went as planned: `RelianceView.jsx` 표시 상수 9개(계기 라벨·헤더·kind 뱃지)를 계획대로 "나아감" 기준으로 정정. mode key(`물음-응답`)·데이터·검증기·의존도 % 전부 불변. 규모가 작아 워크플로우 없이 직접 실행. 빌드+Playwright 모바일 검증 통과.
- Divergences: 계획의 9개 열거 목록에 **도넛 밑 방법론 캡션**(line 274 `"물음(기도·의탁·예배)"…`)이 빠져 있었다. mode 표시를 "나아감"으로 바꾼 뒤 이 캡션만 "물음"으로 남아 같은 피처 내 어휘 불일치를 만들었고, 참조-인접 동반 수정 원칙에 따라 `"나아감(기도·의탁·예배·헌신)"…`으로 함께 정정.

## Learnings
- Do differently next time: **표시 어휘 재정의는 열거한 상수만 고치면 놓친다.** 라벨·헤더·뱃지 상수 외에 같은 단어를 쓰는 **설명 캡션·툴팁·방법론 주석**이 별도 문자열로 흩어져 있다. 계획 단계에서 대상 파일 전체를 그 어휘(여기선 `물음`/`요청`)로 **전수 grep**해 목록을 만들 것 — enumerated list는 이런 산발 문자열을 빠뜨린다. 이번엔 Playwright **시각 검증**(도넛 캡션이 스크린샷에 잡힘)이 잡았다 → 표시 문구 변경은 grep 단언 + 렌더 스크린샷 둘 다 필요.
- 내부 주석·mode key의 `물음`은 그대로 두는 게 맞다(지표 정의는 ADR-0023대로 `물음`이 정본 어휘) — 표시(나아감)와 key/정의(물음)의 분기는 의도된 것이라 CONTEXT.md에 근거를 남겨 둠(미래에 "불일치 버그"로 오인해 되돌리지 않게).
