# 2026-10-19 — 밤샘 5장면 × 8시드 + 아침 한 번 요소 문항·고르기 (task 368, 판정 부분)

## 계획 대비 실제
- 계획대로 된 것: 무인 배치 7.75시간 restarts 0(어림 7.5), 바탕 평균 61초·편집 551초, 아침 한 번 앉아 61화면 판정 → 3/5 고름, 결론 규칙대로 「부분」. 판정 요소를 명세 칸으로 쪼갠 덕에 8/8 틀린 칸이 곧 「고칠 칸」으로 바로 읽혔다(아말렉 moment·사울 pose·사무엘 pose·facing, 라마 moment·다윗 facing, 기브아 다윗 prop).
- 어긋난 것:
  - **계획의 전제가 틀렸다.** 고른 다섯 장면에는 한 장 모드 칸(`whole_background`·`relation`·`screen_facing`·`gaze`…)이 없어 `whole_prompt`가 KeyError — 실행 첫 단계에서 갈림길. 사용자 결정으로 판 단계 문구 이어 붙이기(`plate_whole_prompt`). 그 경로에 빠진 관계·방향 문장이 바로 8/8 틀림의 공통 원인으로 보인다.
  - **편집본은 한 장도 안 골렸다(바탕 3/3).** 편집 targeted가 낮은 시드도 많았다(아말렉 사울 −2.2~9.2). 정체성 편집 단계가 이 장면들에서 값을 못 했다.
  - DoD 3의 `unattended is True`는 합의 절(끊기면 다시 띄움)과 모순 — 루프 시작 때 「재시작 수와 일치」로 다듬었다.
  - night-pick 완료가 단계 사다리 밖이라 `scene_state`가 늘 재검토로 띄우는 것을 실행 중 발견해 건너뛰게 했다(계획 밖 수정).
  - 배치 종료를 기다리던 백그라운드 셸이 메모리 회수로 죽어(편집 최고 58.5GB) 자동으로 이어 가지 못했다 — 사람이 「진행확인」으로 깨워야 했다.
  - 사람 시간 113분 중 93분이 라마 한 장면 — 자리 비움이 섞여 소요 시간 측정이 오염됐다.

## 배운 것
- 다음엔 이렇게:
  - **장면을 고를 때 생성 경로가 요구하는 명세 칸이 있는지 계획 작성 때 확인한다** — `python3 -c "import derive_scene as D; D.whole_prompt(D.load('<id>'))"` 한 줄이면 된다. 지금 한 장 모드 칸이 있는 장면은 길갈 즉위·엔게디·골리앗·라마(사무엘) 넷뿐.
  - **판 문구 이어 붙이기는 인물이 하나거나 서로 닿지 않는 장면에서만 쓸 만하다.** 두 인물 접촉·등 돌림·떠남은 `relation`·`screen_facing` 같은 장면 단위 문장이 없으면 8/8 실패한다(배경·화풍·가드는 0으로 쓸 만했다). 다음 아말렉·라마는 한 장 모드 칸을 저작한 뒤 같은 8시드로.
  - **편집 단계를 기본으로 거는 것을 다시 본다.** 사람이 바탕을 고를 거라면 밤 시간 7시간 중 6시간이 버려진다. 다음 배치는 바탕 시드를 늘리고 편집은 고른 장에만 거는 순서(바탕 고르기 → 고른 장 편집 → 편집본 확인)도 후보 — 단 판정이 두 번이 되는 비용과 맞바꿈.
  - **긴 배치의 깨움은 백그라운드 셸 하나에 기대지 않는다.** 메모리 압박에서 회수될 수 있으니, 시작 보고에 「끝나면 '이어서'로 깨워 달라」를 처음부터 함께 적는다.
  - **판정 페이지 시간은 화면이 숨겨지면 멈춘다**(`visibilitychange`) — 자리 비움을 빼야 소요 분이 참고값이 된다.
  - 루프 계약의 검사는 합의 절과 맞물리는지 그릴링 때 맞대 본다(DoD 3 모순은 거기서 잡혔다).
