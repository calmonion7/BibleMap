# 2026-07-07 — 남은 era 테마 투어 8종 큐레이션 (task 126)

## Plan vs actual
- What went as planned:
  - 9슬라이스(정렬 1 + 투어 JSON 8) 전부 완료. **다윗 투어가 세운 오버레이 메커니즘(ADR-0011)이 재사용만으로 성립** — 신규 Neo4j 노드·사건·주입 0, 코드 변경은 `_list_tours()` era순 정렬 1줄뿐. 남은 작업이 "사건 저작"이 아니라 "기존 eventId 큐레이션"임을 그릴링 전 데이터 집계(era별 사건/좌표/authored 수)로 확정한 게 범위를 정확히 잡아줬다.
  - **eventId 무결성 100%** — 8종 투어 stops 전부 실제 person_events 인덱스(316)에 존재. 다윗 회고의 "hallucinated id는 백엔드가 조용히 버려 정차지가 사라진다"를 알고 있어, 큐레이션 서브에이전트에 "파일에 실제 존재하는 id만" 지시 + eventIds 반환 → main 세션이 인덱스 대조하는 검증을 설계에 넣었다. 결과적으로 무효 id 0.
  - eco 병렬 위임이 적중 — 코드 변경이 1줄이라 리스크가 낮고 큐레이션 8건은 독립적이라, sonnet 9에이전트 병렬로 156초에 완료. 편집 문체(subtitle·description)도 다윗 투어를 예시로 주니 일관되게 나왔다.

- Divergences:
  - **정차지 수가 목표(~N)를 일부 상회**: 포로 21(~15, +6)·예수의 생애 23(~18, +5)·족장 19(~16, +3). 나머지는 범위 내. 전부 유효·응집된 사건이라 트리밍 없이 사용자 판단에 남김(무해, 오히려 풍부).
  - **creation-to-flood는 12정차지 중 5개만 지도 표시**(7 목록 전용). 원시사가 비지리적(창조·타락·에덴)이라 계획에서 이미 허용한 결과.
  - **검증 하네스 함정**: Playwright `goto`로 해시만 바꾸면 same-document 이동이라 앱이 마운트 시에만 해시를 파싱 → 첫 goto(#/tours)만 성공, 이후 `#/tour/<slug>`가 전부 허브로 폴백. 앱 버그로 오인할 뻔했으나 대조군(기존 다윗 투어)도 동일 → 하네스 문제로 판명, 매 URL 새 페이지 풀로드로 재검증해 전부 정상 확인.

## Learnings
- Do differently next time:
  - **eco 서브에이전트에 수량 목표를 줄 땐 "~N"이 느슨하게 읽힌다.** 상한이 UX상 중요하면(투어 정차지처럼) "최대 N개, 초과 금지" 식 hard cap을 명시하라. 이번엔 무해했지만 다윗 투어(18)와 밀도를 맞추려면 캡이 필요했다.
  - **SPA 딥링크를 Playwright로 검증할 땐 매 URL을 새 페이지(또는 reload)로 풀로드하라.** 같은 페이지에서 해시만 바꾸는 연속 `goto`는 same-document라 hashchange만 발생 → 마운트 시 라우팅하는 앱에선 첫 URL 외엔 라우팅이 안 걸린다. 이 프로젝트는 딥링크 기능이 많아(shareable-url-deeplinks·browser-back-history) 재발 확률이 높다. **대조군(기존 정상 케이스)을 함께 돌려 앱 버그와 하네스 문제를 가르는 습관이 오진을 막았다.**
  - **참조 구현의 "숨은 부수효과 목록화"가 이번엔 검증 설계로 선제 반영됐다** — 다윗 회고에서 배운 "hallucinated id 무음 소실"·"map 프레이밍은 personId=null 게이트"를 큐레이션 지시·무결성 검증에 미리 넣어 재발 0. 회고가 다음 작업에 실제로 먹힌 사례.
