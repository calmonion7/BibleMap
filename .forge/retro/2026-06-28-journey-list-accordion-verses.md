# 2026-06-28 — 여정 리스트를 사건별 아코디언 트리로 (여정 > 사건 > 구절)

## Plan vs actual
- What went as planned:
  - `JourneyList`를 사건별 독립 펼침 아코디언으로 전환(`expandedIds` 집합, 여러 사건 동시 펼침). 직전 task90의 동일좌표 그룹 단일펼침 로직을 사건별 집합으로 흡수. 기존 `/event/{id}/verses`·`EventVerses` 재사용, 백엔드 무변경.
- Divergences (실행 중 6차례 fix-forward·확장):
  1. 토글 가시화: 흐릿한 끝단 화살표 → 보라 `📖 ▸/▾` 칩 + 구절 들여쓰기(사용자 "안 바뀐 것 같다").
  2. 모바일 첫 로딩 여정 미표시: 앱 루트 `100vh` → `100dvh`(모바일 브라우저 UI 뒤로 칩 스트립이 잘림).
  3. 모바일 칩 선택 시 가운데 스크롤(이후 5에서 폐기).
  4. 개념 명확화: 사용자가 "여정이 사건 묶음 아닌가? 사건 단계가 안 보임" → 구조는 이미 여정>사건>구절로 맞고 **표현(라벨링) 문제**였음.
  5. 헤더 reframe(`{인물}의 여정 · 사건 N개`) + **모바일을 가로 칩 → 데스크톱과 동일 세로 아코디언(JourneyList) 재사용**으로 통일(3의 칩 센터링·strip 폐기, 코드 76줄 감소).
  - 처음 `verified: yes`가 조급했다(데스크톱·단일좌표만 봄). 사용자 실기기 UAT가 모바일·개념 문제를 잇따라 드러냄.

## Learnings
- Do differently next time:
  - **"X 단계가 안 보인다"는 구조 결함이 아니라 라벨링 결함일 때가 많다** — 계층형 UI는 각 단계의 명칭·소속을 헤더/라벨로 명시해야(예 "여정 · 사건 N개", 행=사건) 사용자가 데이터 모델을 올바로 읽는다. 구조부터 바꾸려 들기 전에 "현재 구조가 이미 맞는데 표현이 안 되는 것 아닌가"를 먼저 점검.
  - **헤드리스 Playwright는 모바일 브라우저 크롬이 없어 `100vh` 잘림을 못 잡는다**(task90 모바일 검증이 통과했던 근본 이유). 모바일 레이아웃·하단 고정 요소는 실기기/도메인(biblemap.taebro.com)으로 확인, `100vh`는 기본 의심 → `100dvh`. [[feedback_playwright_testing]]에 반영.
  - **UAT는 사용자 실제 진입 경로(무클릭 첫 화면·실기기·다중-동일좌표 그룹)를 그대로** — 데스크톱·단일 케이스만 보면 조급한 verified가 된다.
  - **모바일/데스크톱을 한 컴포넌트(JourneyList)로 통일**하니 일관성↑·코드↓(가로 칩 특화 전부 제거). 분기 UI는 가능하면 단일 컴포넌트로.
- Divergences 요약: 계획(아코디언)은 맞았으나 표현·모바일·개념에서 반복 보정 — 핵심은 "구조 OK, 표현 부족".
