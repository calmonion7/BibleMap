# 테마 이원화: 다크 기본 "Night Atlas" + 라이트 선택 "Day Atlas" (ADR-0013 부분 개정)

ADR-0013은 화면마다 갈라진 라이트/다크를 **다크 단일**로 통일했다. 이번에 사용자 요청으로 **라이트 테마를 선택지로 추가**하며, 0013의 "단일" 조항만 해제하고 나머지 정체성은 계승한다:

- **기본은 여전히 다크(Night Atlas).** OS `prefers-color-scheme`를 자동 추종하지 않는다 — 자동 추종하면 라이트 OS 사용자 전원이 예고 없이 브랜드 무드(심야 네이비+금)를 잃는다. 라이트는 사용자가 토글로 명시적으로 켜는 옵트인이고, 선택은 localStorage에 유지된다.
- **라이트 = "Day Atlas"**: 웜 아이보리(양피지 계열) 표면 + 다크 웜 잉크 + 진한 금 액센트. 별개 디자인이 아니라 Night Atlas의 명도 반전 대응 — 같은 토큰 계약(`--bg-*`/`--ink*`/`--gold*`/`--line*`)에 값만 다르게 채운다. 구현은 `:root[data-theme="light"]` 오버라이드 한 겹이며, 인라인 스타일이 이미 `var(--…)`를 참조하므로(0013 적용의 부산물) 전면 재작업 없이 성립한다.
- **0013의 예외 원칙은 라이트에서 재해석**: 다크에서 "밝은 표면은 말씀·지도 둘뿐"이던 위계는, 라이트에서는 양피지 구절 카드가 배경과 명도가 가까워지므로 경계·색조로 구분을 유지한다. 지도(NatGeo 현대 타일)와 그 위 오버레이(금색 여정선·마커)는 **테마 불변** — 지도는 원래 밝은 표면이라 라이트에서도 그대로 성립한다.
- **노드 타입·valence 색은 테마별 보정값을 갖는다**: 기존 팔레트는 "다크 대비 보정값"(theme.js 주석)이라 라이트 배경에서 대비가 무너진다. UI 사용처는 CSS 변수(`--type-*`, `--valence-*`)로 전환해 테마별 값을 정의하고, 지도 오버레이는 리터럴 유지.

되돌리기 비싼 이유: 토큰 계약이 "테마 두 벌"을 전제하게 되면 이후 모든 화면·컴포넌트가 두 테마에서 검증돼야 한다(유지비 증가). 그 비용을 알고도 사용자 선택권을 우선했다.
