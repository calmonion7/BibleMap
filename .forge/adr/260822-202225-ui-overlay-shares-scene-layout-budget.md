# UI 오버레이는 장면 좌표계의 배치 예산을 함께 쓴다 — 어떤 게이트도 이 겹침을 못 잡는다

장면 스케치의 배치 레시피는 viewBox 120×64를 세 띠로 나눠 쓴다 — 상단 띠(y ≤ 8) 이름표, 그림 y 10~55,
**하단 띠(y ≥ 57) 서술형 이름표**. 경계 B10이 이 계약을 강제한다: 이름표 상자를 어떤 stroke도 관통하지 않고,
상자가 프레임 안에 있고, 이름표끼리 겹치지 않는다. 판정은 선분 대 상자 교차다.

task#303 S2가 삽화 확대 어포던스(`Maximize2` 아이콘)를 추가하면서 그것을 SVG 위 `position: absolute`의
**우하단**(`right: 2, bottom: 2`)에 놓았다. 그 자리가 하단 띠다. 실측: 9투어 682개 이름표 중 **78건**이 이
버튼과 겹친다. 사무엘 장면에서 "이름표에 획이 겹쳐 보인다"로 처음 관측됐고, 저작 에이전트는 그것을
SVG 선으로 오진해 이름표를 왼쪽으로 옮기는 회피를 택했다(그마저 버튼 영역을 벗어나지 못했다).

**B10은 이 겹침을 원리적으로 잡을 수 없다.** SVG 소스의 선분만 재기 때문이다. 버튼은 React가 같은 좌표계
위에 얹는 DOM 요소이고 SVG 소스에 존재하지 않는다. 그래서 검증기는 초록인데 사람 눈에는 겹쳐 보인다 —
게이트를 통과했다는 사실이 이 결함에 대해 아무 정보도 주지 않는다.

## 결정

**장면 SVG 위에 얹는 UI 요소는 배치 띠 계약의 적용을 받는다.** 어포던스·버튼·배지를 절대배치할 때는
이름표가 쓰는 띠를 피한다. 확대 어포던스는 **좌하**로 옮겼다 — 네 모서리를 682개 이름표에 대해 실측한
결과다(우하 78건 · 우상 7건 · 좌상 0건 · **좌하 0건**).

한 장면의 이름표를 옮기는 것은 해법이 아니다. 296장면이 같은 계약에 맞춰 저작돼 있으므로 **오버레이를
옮기는 것이 근본 수정**이고, 그래야 296장면이 함께 해소된다.

## 무엇을 맞바꿨는가

우하단은 어포던스의 관습적 자리이고(확대·전체화면 아이콘은 대개 오른쪽 아래에 있다) 발견성이 가장 좋다.
그 관습을 버리고 좌하로 갔다. 대안은 ① 어포던스를 없애고 그림 전체의 클릭 가능성에만 의존(`role="button"` ·
`aria-label` · `cursor: zoom-in`은 이미 있다) — 터치에서 발견성이 떨어진다 ② 하단 띠 이름표를 296장면에서
전부 좁힌다 — 배치 예산을 UI 편의로 깎는 것이고 원가가 크다 ③ B10을 확장해 UI 요소를 알게 한다 —
검증기가 React 레이아웃을 알아야 하므로 결합이 과하다. 좌하 이동이 가장 싸고 되돌리기 쉽다.

## 따름 정리

**SVG 좌표계는 그림만의 것이 아니다.** 장면 규약이 "배치 예산"이라 부르는 것은 실제로는 SVG와 그 위 DOM이
공유하는 화면 예산이며, 규약 쪽에만 게이트가 걸려 있다. 그래서 이 축의 결함은 **육안 검수로만 발견된다** —
이번에도 발견 경로는 UAT 중 오케스트레이터의 눈이었고, 저작 에이전트는 오진했다.
[[판독성]]이 기계로 못 재는 축이라는 것과 같은 성질의 공백이다(ADR `260822-072153`).

새 UI를 장면 패널에 얹을 때 확인 절차: 그 요소의 화면 좌표를 viewBox 단위로 환산하고, `<Label>`의
x·y·size·anchor로 상자를 계산해 겹치는 이름표 수를 세라. 0이 아니면 자리를 옮긴다.
