# 투어 정차지 해설(note)은 투어 JSON 안에 둔다 (stops를 객체 배열로 확장)

테마 투어의 깊이 보강으로 정차지마다 **투어 관점 서술**(이 사건이 이 테마에서 왜 중요한가, 2~3문장)을 저작하기로 했다. 이 서술의 보관처가 필요했다.

**결정:** `data/tours/{slug}.json`의 `stops`를 `["eventId", ...]`에서 `[{"id": "eventId", "note": "..."}]` 객체 배열로 확장하고, 정차지 해설은 **투어 파일 안에** 둔다. 9개 투어 전부를 한 번에 객체 형식으로 이관하고(미저작 note는 `null`), 백엔드는 객체 형식만 파싱한다(이중 파서 없음).

## Considered Options
- **person_events 사건 본문에 병합**: 같은 사건이 여러 투어에 속할 수 있고 해설은 *그 투어의 틀* 안에서만 유효(다윗 투어의 "사울의 창"과 사울 몰락 투어의 "사울의 창"은 다른 서술) — 사건 단일 본문에 넣으면 테마별 관점이 뭉개진다. 기각.
- **별도 오버레이 파일**(`tour_notes/{slug}.json`): 투어 정의와 해설이 두 파일로 갈라져 stops 순서 변경 시 드리프트. 해설은 투어의 "틀"의 일부(ADR-0011: 투어는 순서·틀 부여)이므로 분리할 이유 없음. 기각.

## Consequences
- ADR-0011의 계약 유지 — 사건 *본문*의 단일 출처는 여전히 person_events, 투어 파일은 순서 + **틀(해설 포함)**. 해설은 투어 밖에서 재사용되지 않으므로 이중 출처 아님.
- `stops` 형식 변경으로 `backend/app/routes/tours.py`의 stops 파싱·stopCount 산출이 1회 수정된다. 이후 투어 추가·해설 저작은 JSON 커밋만으로 반영(시드 불필요, ADR-0011과 동일).
- note는 nullable — 해설 없는 정차지도 재생·목록에서 성립(프론트는 note 부재 시 사건 제목·본문만 표시).
