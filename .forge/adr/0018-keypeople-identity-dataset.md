# keyPeople 정식 식별 데이터셋 — (책,이름)→인물id/무id, 카드 표시의 단일 결정 계층

책 상세 「주요 인물」은 두 소스의 합집합이다 — 이벤트 참여 그래프 Person 노드(`topPersons`, top-10, by-id) + 책에 저작된 `keyPeople` 문자열(by-name). 이 섹션은 기능을 붙일 때마다(163 비큐레이션 삭제 → keyPeople 병합 → 165 여정 링크 → ADR-0017/#170 구절 카드) keyPeople **문자열이 모호한 자유 텍스트**라는 근본 문제 때문에 반복 땜질돼 왔다. 실측으로 확인된 모호성: ① 같은 이름의 다른 인물이 그래프에 복수 존재(야고보 3인·유다 3인 등 nameKo가 전부 동일) ② 큐레이터의 문자열이 정본 이름과 불일치("요한"은 무명 인물을 가리키고 사도 요한의 nameKo는 "사도 요한") ③ 책 참여 사건으로 자동 판별 시도 시 7/7 케이스가 "없음"(서신서는 저자가 사건 미참여). 즉 **런타임 이름 해석으로는 결정 불가능한 데이터**다. ADR-0017 Consequences(2026-07-12)가 by-name 렌더 경로의 사각지대를 기록했고, task#171에서 이를 **워크어라운드(런타임 해석+예외표)가 아니라 데이터 자체를 "판단 가능"하게 완성**하는 방식으로 정면 해소한다.

- 데이터: `data/keypeople/identity.json` — 각 (책, keyPeople 문자열) → `{kind, id?}`. `kind=person`(그래프 노드 있는 인물)은 person id를 실어 `person_context`(by-id) 카드로, `kind=noid`(그래프 노드 없는 실제 인물 + 개념/집단/비인격)는 `keypeople_verses`(by-name) 카드로 해석. 전 keyPeople(196개) 완결 저작 — 예외표가 아니라 **전량 정식 식별 데이터**.
- 판정: 이름이 유일하면 자동 매칭. 모호한 소수(야고보·유다·가이오·알렉산더·요한 등)는 **각 후보 id의 사건·관계(SIBLING_OF/MEMBER_OF/HAS_PARTICIPANT) + 책 맥락**을 근거로 저작 시점에 1회 판정해 데이터에 고정(예: 마가복음 "야고보"=세베대의 아들, 야고보서 "야고보"=예수 동생, 요한복음 "요한"=사도 요한). 판정이 데이터에 박히므로 런타임 추측·별칭 machinery가 영구 불필요.
- 소비: 백엔드가 identity + `person_context`(by-id) + 큐레이션(여정) + `keypeople_verses`(by-name)를 조인해 (책,이름)별 완성 카드를 반환 → 프론트는 완성 카드만 표시(여정 > 구절 > 평문 우선순위 유지). person 카드는 top-10 여부와 무관하게 그 인물이 keyPeople로 등장하는 모든 책에서 노출된다(ADR-0017 사각지대 해소).

## Considered Options

- **(채택) 별도 정식 식별 데이터셋(`data/keypeople/identity.json`)** — 전 keyPeople를 완결 저작. books.json·Neo4j 무변경. 정체가 (책,이름)에 종속되는 야고보류를 자연스럽게 담는다(책별 다른 인물). "표시 문자열(books.json)"과 "정체(identity)"의 관심사 분리. 대가: keyPeople 목록이 두 곳에 존재 → 짝 검증 스크립트로 드리프트 관리.
- **(반려) books.json keyPeople를 문자열→`{이름,정체}`로 승급** — 단일 소스지만 Neo4j Book.keyPeople가 책당 납작한 문자열 배열이라 구조배열을 속성에 담으려면 JSON 문자열화(#170 verses처럼 지저분)해야 하고, inject·그래프·엔드포인트·프론트까지 파급. (책,이름) 종속 모호성과도 형식이 안 맞음.
- **(반려) 런타임 이름 해석 + 예외표** — 워크어라운드. 퍼지 매칭은 오탐 위험, 예외표는 ADR-0017이 미룬 별칭 machinery의 축소판. 무엇보다 **데이터에 자동 판별 단서가 없어 런타임으론 결정 불가**(실측 7/7 실패). 정체를 데이터에 먼저 고정하는 것이 유일하게 견고.

## Consequences

- keyPeople 식별이 **단일 결정 계층**이 된다. 별칭·동명이인 문제가 데이터 레벨에서 영구 해소되고, 이후 keyPeople 관련 기능은 이 계층 위에서 결정적으로 동작한다.
- #170이 "names_ko 미해석=노드 없음"으로 대충 나눈 by-name 분류를 정식 `person`(id 보유)/`noid`로 **정정·통일**한다. #170에서 임시로 by-name 맵에 넣은 도마는 정식 person id 경로로 뜨므로 그 임시 항목을 제거한다.
- 별칭 불일치로 여정을 놓쳤던 큐레이션 인물(예: "요한"→사도 요한)의 **여정 칩도 회복**된다.
- person 카드의 정본 창고는 `person_context`(by-id), 무id 카드는 `keypeople_verses`(by-name)로 역할이 명확해진다(ADR-0017 모델의 완성형).
- books.json 표시 문자열과 identity가 (책,이름)으로 짝지어져야 한다 — 검증 스크립트로 정합성 유지(신규 keyPeople 추가 시 identity 누락 감지).
- Neo4j 스키마 무변경.
- **(보강 2026-07-12, task#171 실행) noid의 범위 확장 — "노드는 있으나 무가치한 인물"도 포함.** 당초 noid는 "그래프 노드 없는 실제 인물 + 개념"이었으나, 실행 중 **노드는 존재하되 그 책 맥락에서 무가치(무사건·오지시)한 인물**(출애굽 바로=Exodus 노드 부재, 유다서 유다=무사건 노드, 딤전 알렉산더·요한3서 가이오=후보 불일치)도 by-name 카드(noid)로 라우팅했다. id 연결이 대표 구절/여정 어느 가치도 못 주면 by-name이 동등하고 단순. 즉 noid = "by-id로 연결할 가치가 없는 keyPeople 문자열"로 이해한다.
- **(보강 2026-07-12) 이름→id 해석에 names_ko alias는 쓰지 않는다(exact nameKo + 접미 endsWith만).** alias는 일반 단어·개념과 충돌해 오resolution을 낳는다(실측: `전도서 전도자→빌립`(빌립 alias="전도자"), `오바댜 에돔→에서`(에돔=에서 alias) — alias 정답 0·오답 2, 정답은 전부 exact/endsWith). 동명이인 판정은 alias가 아니라 후보 인물의 그래프 사건·관계(SIBLING_OF/대표 사건)로 근거화한다.
