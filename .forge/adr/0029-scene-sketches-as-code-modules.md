# 투어 장면 스케치는 투어별 JSX 코드 모듈로 저작한다

투어 재생의 정차지마다 저작 삽화 시퀀스 애니메이션(장면 스케치)이 붙게 되면서(9투어 165장면), 이 저작물의 보관·표현 형식이 필요했다. 데이터(JSON·SVG 파일)로 둘지, 코드로 둘지의 갈림.

**결정:** 장면 스케치는 **`frontend/src/sketches/` 아래 투어당 1개 JSX 모듈**로 저작한다. 각 모듈은 eventId 키의 레지스트리(`{ Scene, mood, desc, caption }`)를 export하고, 공용 표준(선 굵기 위계·전역 배율 W·단계 딜레이·이름표 컴포넌트)은 `sketches/lib.jsx`가 정본이다. `tourSketches.jsx`는 레지스트리 집계와 렌더(양피지 패널)만 담당한다. 스케치가 없는 정차지는 아무것도 렌더하지 않는다(그레이스풀 — 부분 저작 허용).

## Considered Options
- **SVG/JSON 데이터 파일 + 로더**: 저작물을 data/에 두면 백엔드 파이프라인과 일관되지만, 이 저작물의 본질이 정적 도형이 아니라 **연출**(단계 draw 딜레이, SMIL 안무, reduce 분기, 이름표 페이드인 타이밍)이라 데이터 스키마가 사실상 미니 애니메이션 DSL이 된다. pathLength 정규화·CSS 변수·SMIL을 JSX로 직접 쓰는 쪽이 표현력과 검증(빌드 타임 문법 오류 검출) 모두 우수. 기각.
- **단일 파일(tourSketches.jsx)에 전량**: 165장면 ≈ 10k줄 — 편집·리뷰 불능. 투어당 분리로 기각.

## Consequences
- 장면 추가·수정은 코드 커밋으로 반영(시드·재시작 불필요, 프론트 빌드만). 저작 표준의 정본은 lib.jsx 헤더 주석 + ADR-0025(선화 규약)이며, 무드·이름표·상황설명 등 카드 레이어 규약은 tourSketches.jsx의 패널이 소유한다.
- 데이터(투어 stops)와 코드(장면 레지스트리)가 eventId로 페어링되므로, **집합 대조 스크립트**(stops의 id ⊆ 레지스트리 키)가 커버리지 검증 게이트다 — 정차지 추가 시 스케치 누락은 이 대조로 잡는다.
- 사건 본문·해설(person_events·tours JSON)과 달리 장면 스케치는 번역·외부 재사용 대상이 아니라는 전제가 깔려 있다(코드 자산). 그 전제가 깨지면(예: 다국어 이름표) 이 결정을 재검토한다.
