# 장면 생성은 무인 드라이브가 아니라 **단계마다 사람이 승인하는 도구**로 간다 — 도구는 레포 안, 핵심 자료 구조는 도메인 중립, 승인은 명세 안

다윗 투어 36장면을 fg-loop로 몰던 방식(ADR `260904-055321`, task 331~336)은 사람 관문을 **파트 끝의 UAT**에만 두었다.
그 자리는 구조가 정한 것이었다 — `notes/PROCESS.md` §4가 「워크플로우는 런타임에 사람 입력을 못 받아 콘티 승인을 UAT로
옮겼다」고 이미 적어 두었다. 결과가 4/7에서 드러났다: 9장면을 50분 무인 생성하고 기계 판정이 둘을 통과시켰는데, 사람 눈에는
**세 장면이 같은 그림**이고 군중은 없고 C4 잉크 축은 인물이 아니라 배경을 재고 있었다(`notes/SCENES-DAVID-TOUR.md`
「규칙 실측」 1·3·4). task 337이 다른 경로를 시험했지만 역시 사람 판정 8칸이 빈 채 끝났다. 2026-09-05 사용자가 결정했다 —
**「사람이 확인해야 한다. 오래 걸리지만.」**

## 결정

1. **사다리 다섯 걸음을 사람이 하나씩 승인한다** — 본문 → 장면 서술 → [[단계 분할]] → [[단계 시도]] → [[장면 완료]].
   승인은 사람만 한다. 기계 판정 수치는 시도 옆의 참고값이고 게이트가 아니다. 한 단계는 사람이 고를 때까지 시드·문구·구역을
   바꿔 다시 시도할 수 있고, 앞 걸음이 바뀌면 뒤는 [[재검토]]다(배경 사슬 순차 의존 · 판 독립 · 명세 수정은 아래 전부).
2. **도구는 이 레포 안 `scripts/canon/`에 둔다**(앱과 다른 런타임, ADR `260825-065028`). 핵심 자료 구조
   (이야기 → 장면 → 단계 → 시도 → 승인)는 성경 낱말 없이 짜고 절 인용·인물 정본 같은 성경 전용 부분만 어댑터로 뗀다.
   **별도 프로젝트(범용 웹툰 제작 도구)로의 분리는 다윗 투어를 이 도구로 완주한 뒤 결정한다** — 이야기 원천이 하나뿐이라
   「범용」의 요구가 실측되지 않았고, 엔진이 이 머신(MPS · 47GB 캐시)에 묶여 있으며, 먼저 쪼개면 엔진 코드가 두 곳에 걸린다.
3. **승인은 명세 JSON 안에 적는다** — `stages[i].approved`(시도 id · 시드 · 승인자 · 날짜)와
   `approved.{verses,description,split,final}`. 인물 정본의 `plate.approved` 규약과 같고, 생성기가 도구 없이 명세만 읽어
   승인 시드로 재현할 수 있다. **시도 이력은 곁파일** `scripts/canon/attempts/<id>.json`(추적) — 36/36 검토를 마친
   명세가 실패 기록으로 부풀지 않게 하되 「몇 번 걸렸나」는 남긴다. **그림은 `.forge/reports/`**(무시) — 재현 명령이 산출물을
   대신한다는 규약 그대로. **재검토는 저장하지 않고 계산한다** — 승인된 시도가 기록한 입력과 지금 명세·앞 단계 승인을 비교한다.
   플래그를 저장하면 명세를 손으로 고쳤을 때 어긋나고, 계산하면 어긋날 수 없다.
4. **폰·바깥 접근은 이 머신의 기존 Cloudflare Tunnel에 주소 하나를 더하고 Cloudflare Access(이메일 허용 목록)를 앞에 건다.**
   도구 서버는 `127.0.0.1`에만 붙고, Access가 붙여 주는 인증 이메일 헤더가 없으면 거절한다(Access 설정이 빠졌을 때 GPU
   버튼이 인터넷에 열리는 사고의 안전핀 · 「누가 승인했나」 기록). 터널 설정 파일은 여러 프로젝트가 함께 쓰는 자원이라
   (프로세스 `tunnel run portfolion`) **터널 한 줄 · DNS · Access 정책은 사람 손으로** 한다 — 에이전트는 문구만 준비한다.
5. **36장면 무인 드라이브(fg-loop)와 4/7~7/7 계획은 폐기한다.** task 337의 장면 안 인페인팅 경로는 코드를 남기되
   채택하지 않는다(기본값 불변이 픽셀 동일로 증명됐고 실측 9~13번이 값어치다).

## 고려한 대안

- **별도 범용 프로젝트를 지금 시작** — 위 2의 이유로 기각. 핵심을 중립으로 짜 두면 분리는 뒤에 디렉터리 하나 옮기는 일이다.
- **CLI + Claude 아티팩트 검토 페이지**(지금까지의 방식) — 재시도마다 대화 한 왕복이 들어가 「계속 시도」가 느리다.
- **앱 프론트에 저작 화면** — 앱은 저작 파이프라인을 import하지 않는다는 경계(ADR `260825-065028`)와 설정화 비노출
  (ADR `260823-190821`)을 깬다.
- **Tailscale** — 공개 주소가 없어 Access가 불필요하지만 폰에 앱이 늘고 기존 터널을 안 쓴다.
- **곁파일 하나에 승인까지** — 명세만 보고는 어느 시드가 정본인지 모르게 된다.

## 결과

- 병목은 GPU가 아니라 사람 시간이다 — 배경 39초 · 판 90~150초라 단계 재시도는 1~2분 단위이고, 36장면 × 서너 단계 × 몇 번의
  시도는 수백 번의 사람 결정이다. 그것이 이 결정이 **의식적으로 사는 값**이다.
- 판의 재현은 같은 시드로 **다시 그린다**(판은 결정적 — v41=v42=v44). 크롭 전 판 PNG를 재사용하는 지름길(`_plate`가 이미
  저장한다)은 실측 뒤 별건이다.
- 도구의 상주 서비스화(launchd)와 완료 그림의 앱 배선(`frontend/public/scene-color`)은 이 결정 밖이며 뒤에 따른다.
- `notes/PROCESS.md` §4의 「사람 확인 지점 둘」은 이 사다리 다섯 걸음으로 대체된다.
