# 가계도 = theographic 그래프 혈통 파생 + 단절 저작 보충 (큐레이션 재저작 아님)

[[가계도-family-tree]] 페이지는 인물의 다세대 혈통을 세대별 트리로 보여준다. 이 데이터를 어디서 얻을지가 근본 결정이었다. 프로젝트엔 이미 인물-인물 관계 데이터가 **둘** 존재한다 — SidePanel "이웃"이 쓰는 그래프 직계 간선(`SIBLING_OF` 256·`PARTNER_OF` 9)과, [[인물-관계-person-relations]]의 손큐레이션 서사 오버레이(`person_relations`, "가족" 유형 44건, 방향 role 라벨 포함). 세 번째로 가계도용 혈통 데이터를 어떻게 확보하느냐가 문제다.

조사 중 **잠복 버그**를 발견했다: `load_theographic.py`의 `load_parent_child_rels`가 theographic `father`/`mother`를 **스칼라로 취급**하는데 원본은 배열(`['recPXtu...']`)이라 `MATCH (parent {theographic_id: [배열]})`이 아무 노드에도 안 걸려 **PARENT_OF/CHILD_OF가 0개** 적재됐다(형제·배우자 로더는 배열을 순회해 정상 적재). 즉 혈통의 뼈대인 부모-자식 간선이 코드 결함으로 통째 누락돼 있었다. 원본엔 데이터가 있다 — father 1584·mother 200건. 게시된 299명 기준으로 양끝이 모두 게시된 부모-자식 간선은 **137개**, 부모를 1명 이상 갖는 인물은 **127명**이다.

## Considered Options

- **(채택) 로더 버그 수정 → theographic 그래프 혈통 파생 + 단절 지점만 저작 보충.** 형제 로더처럼 배열을 순회하도록 고치면 137간선이 살아나고, 형제 256·배우자 9와 합쳐 충실한 혈통 그래프가 된다. 데이터가 이미 원본에 있으므로 **재저작이 아니라 결함 복구**이며, 프로젝트의 "정본 데이터·구절 근거" 기조와 맞고 결정적(deterministic)이다. 혈통이 끊기는 곳(부모가 미게시라 노드 없음 = 실측 48건, 또는 원본에 링크 부재)만 [[저작-인물-authored-person]] 패턴(`authored-*` 노드 + 혈통 간선)으로 국소 보충한다. 대가: 로더 재실행 때마다 저작 보충도 재적재해야 하고, 그래프 상태가 바뀌어 기존 이웃 뷰에 부모·자식이 새로 나타난다(회귀 확인 필요).
- **(반려) 큐레이션 가계도 데이터셋을 손으로 전량 저작.** theographic이 이미 가진 137간선을 사람이 다시 쓰는 대규모 수작업. 편집 통제는 얻지만 원본 신뢰 데이터를 버리고 재입력하는 비용·드리프트가 크다(에코 YAGNI 위배).
- **(반려) 기존 `person_relations`의 "가족"(44) 오버레이에서 파생.** 이미 방향 role 라벨이 있어 매력적이나, 44건뿐이라 희소하고 valence·국면과 뒤섞인 **서사 축**이라 다세대 구조 트리의 원천으로 부적합. 서사와 혈통이라는 관심사를 섞게 된다.

## Consequences

- **혈통의 단일 원천이 "버그 수정된 그래프 간선"이 된다.** 부모-자식·형제·배우자 모두 그래프에서 결정적으로 파생하며, 가계도는 그 위의 순수 렌더 계층이다(valence·국면 없음).
- **그래프 상태가 바뀐다.** `PARENT_OF`/`CHILD_OF`가 새로 생겨 이를 읽던 기존 경로(`/node/{id}/neighbors/grouped` 등 SidePanel 이웃)에 부모·자식이 노출된다 — 의도된 개선이나 회귀가 없는지 확인해야 한다.
- **재실행 규칙**: `load_theographic.py` 재적재 시 저작 혈통 보충(authored 노드·간선)도 반드시 재적재한다(ADR-0014 date_corrections 재실행 규칙과 동류).
- **단절 보충은 게으르게(lazy)** 한다 — 48개 미게시 부모를 전량 저작하지 않고, 눈에 보이거나 대표 계보에 필요한 곳만 메운다. 이번 태스크는 대표 계보 1건(예수의 족보 마1)만 뿌리까지 무단절로 보증한다.
- 저작 보충 노드는 `authored=true` 마커를 유지해 원본과 구분된다(ADR-0008 provenance 모델 계승).
