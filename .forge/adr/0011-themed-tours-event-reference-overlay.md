# 테마 투어는 기존 사건을 참조하는 런타임 오버레이로 둔다 (신규 노드·주입 없음)

[[테마 투어]]는 여러 인물의 여정 사건을 주제로 엮은 큐레이션 시퀀스인데, 이 시퀀스를 어떻게 저장·제공할지 결정이 필요했다. 큐레이션 여정 사건(`data/person_events/*.json`)은 각 인물 파일에 본문이 embed돼 있고 사건 ID는 파일 간 공유되지 않는다(다윗 테마 4인 = 중복 0 확인).

**결정:** 테마 투어는 `data/tours/{slug}.json`에 **순서 있는 기존 사건 ID 목록 + 투어 메타(제목·부제·시대·설명)** 로만 정의하고, Neo4j에 새 노드를 만들거나 주입하지 않는다. 백엔드 `/tours`·`/tour/{id}`가 런타임에 person_events에서 `사건ID→본문` 인덱스(lru_cache)를 만들어 해석하고, 좌표는 기존 `journey.py`의 배치 조회를 재사용해 여정과 동일한 stops 형태로 반환한다. 사건 본문의 단일 출처는 person_events로 유지된다(투어는 순서·틀만 부여).

## Considered Options
- **투어를 self-contained JSON으로**(사건 본문 복제): 파일이 자족적이나 person_events와 이중 출처가 돼 사건 수정 시 드리프트. 기각.
- **투어를 Neo4j 노드/관계로 적재**(예: `(Tour)-[:INCLUDES]->(Event)`): 권위 그래프에 조회 전용 큐레이션 데이터를 넣게 되고 시드 파이프라인·재현성 부담 증가(CONCERNS의 시드-deploy 단절 리스크 확대). 투어는 그래프 순회 이점이 없어 불필요. 기각.

## Consequences
- ADR-0004(추정·큐레이션 데이터는 권위그래프 밖 오버레이)·book_events 선례와 일관. 배포 시드 단계 추가 불필요 — JSON 커밋만으로 반영.
- 투어가 참조하는 사건 ID는 person_events에 존재해야 한다(계약). 인물 파일에서 사건 ID가 바뀌면 투어가 깨지므로 사건 ID는 안정 키로 취급한다.
- 우선순위화된 9개 투어(P1~P9)가 모두 이 형식을 따른다 — 투어 추가는 JSON 하나 + 데이터뿐, 백엔드/프론트 코드 변경 없음.
